# 图像模拟强度计算的近轴相位开销修复

当前蓝色陷波示例的第一窗口是源位图，第二窗口是启用偏振、相对照度、无像差、1×1 PSF 网格的仿真图。用户已明确本轮核对计算方式，不要求另一台电脑上的严格原生逐像素对照。[官方方法与本例路径核对](method-review.md)。

## 原因与修正

原照度积分对每条功率采样光线额外执行近轴面光程相位积分，并反复进行光束瞄准。调用栈采样中绝大部分时间处于这条相位路径。独立光线功率不依赖这一公共相位。

新增内部 `DiagnoseAperturesForPower`，沿用共享物理表面引擎、真实孔径、介质吸收、镀膜和 Jones 链功率，仅省去近轴面相位积分。照度及图像模拟的主光线功率使用它；默认诊断、完整光线记录、波前和衍射仍保留完整相位。功率路径的样本不用于 OPD。无像差报告也不再声称执行了 EigenPSF 卷积。

## 本机实际执行

| 内容 | 时间 |
| --- | ---: |
| 原源图预览 | 0.120 s |
| 修正前仿真，未启用调用栈采样 | 25.514 s |
| 修正后 77×77 预览，未启用调用栈采样 | 1.564 s |
| 修正后 306×306 完整图，未启用调用栈采样 | 1.447 s |
| 同样启用调用栈采样：修正前／后 | 30.568 / 1.619 s |

单次计时不是固定性能保证，完整图与预览的少量时间差受预热和并行工作影响。两者采用相同的 32×32 光瞳设置、偏振、照度和膜系，实际记录均为 86,272 次物理追迹请求；分辨率变化不减少照度采样。修正前后的预览浮点 RGB 序列 SHA-256 完全相同。完整图保留原输入图分辨率及蓝通道消光；原图预览仍包含蓝色。各阶段原始 JSON 与输入摘要保留在本目录。

**36/36 定向检查通过，0 失败、0 跳过**，最终回执为 `accepted.trx.gz`。覆盖有限／无限物距、轴上／离轴、标量／偏振、逐光线位置方向功率一致、独立物理孔径、取消、默认完整相位再次请求、两种图像分辨率、非零 RGB 透射比例和波前相位。首次新增孔径用例错误地只改了显示半径，未改独立圆孔；已改为设置实际 `CircularAperture` 并复核，首次失败回执保留。未改变产品孔径判断。

正常 Release 主程序及项目依赖构建成功，0 警告、0 错误。曾与另一任务正在编辑的 GPU 文件重叠，临时构建失败；后续完整构建及正常引用的 36 项检查全部完成。没有修改该任务的 GPU 文件，也没有用隔离检查替代最终正常引用验证。

没有运行全量光学精度矩阵、重采原生数值或控制／重启用户程序。计算方式核对和内部结果保持分别记录，不据此宣称原生逐像素认证。

## 复现

工具仅为 C# 诊断，读取原示例窗口设置并调用实际 Application／Core；不会修改产品设置或启动 GUI。

```powershell
dotnet build tools/diagnostics/ImageSimulationTiming20261126/ImageSimulationTiming20261126.csproj -c Release
# 下面传入本地仓库的绝对路径；--full 使用完整原图，--profile 启用低频调用栈采样。
dotnet tools/diagnostics/ImageSimulationTiming20261126/bin/Release/net10.0/ImageSimulationTiming20261126.dll 'D:\optical system design\opticalsystem'
```

结果 JSON 写入诊断工具输出目录。`summary.json` 记录测试、计时、实际设置、原图结果指纹及本轮源码身份；`inputs.json` 记录处方、位图和膜系的原始身份。大型输入和依赖不重复归档。
