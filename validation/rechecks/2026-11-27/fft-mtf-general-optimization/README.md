# FFT MTF 共享链路的通用性能修复

本轮解决共享准备、精确瞄准复用和重复求值的性能问题。运行时没有按镜头名称、示例编号、路径或材料名称分支；算例仅用于复现和验证。适用性、输入身份、容量/失效及验收规则已写入主规范 [RAY_TRACING_PERFORMANCE.md](../../../../docs/RAY_TRACING_PERFORMANCE.md)，并由根 AGENTS.md 引用。

## 实现与物理边界

- 支持路径的能力检查不再逐面构造 LINQ/材料集合，每次仍读取当前几何和材料；错误报告沿用原顺序和内容。
- 不可变坐标的旋转/逆矩阵按弱引用对象身份复用，零转角使用单位矩阵；不改变坐标值相等、序列化、修改副本或运算坐标系。
- 均匀传播、折射/反射与无膜层的值状态运输使用原共享公式，省去 public ray/state 的中间对象。复杂材料、交互和膜层继续使用原适配接口，没有增加第二套光学公式。
- 精确光阑瞄准的光瞳发射光束按完整物理身份和实际节点/权重复用；自定义 stopTargets、无可靠身份和不适用请求沿用原路径。容器复制不再次归一化，调用方不能修改缓存内容。修订与 Clear 同时清空两类缓存；原物理追迹缓存和发射缓存分别受原配置的条目/节点额度约束，默认各 256 条/500,000 节点。
- 近轴面只在共享规则证明输入为均匀平面界面链保持的平面波时复用恒定入射方向。原 Simpson 积分、完整相位、正反向符号及收敛条件保留；有限共轭和有像差输入继续逐点反向瞄准。
- 普通 FFT MTF 的按需加密复用已完成的原档；已解析则原样返回，欠采样则保留原物理域上的两档收敛验证、相位保护和工作预算。没有用固定低档替代精度恢复。
- Windows 普通运行脚本的清理、构建、启动统一使用 Release；`--check` 仍只检查 SDK，不启动桌面软件。

## 同输入性能复测

实际调用 `WorkbenchApplication.Analyses.RunAsync`，包含文档冻结、共享缓存和结果映射，不包含 UI 绘制或结果文件写入。每组独立进程，先计一次首次请求，再计三次同进程重复请求的中位数；CPU、Release、24 逻辑处理器、.NET 10.0.8。默认全部定义视场/波长、像面、调制、偏振关闭、按需加密，上限 2048。各轮完整设置和实际 DLL 哈希见 [timings.json](timings.json) 与 [sources.json](sources.json)。

| 菜单示例／采样 | 首次修复前 s | 首次修复后 s | 重复请求修复前 s | 重复请求修复后 s |
| --- | ---: | ---: | ---: | ---: |
| Cooke 40°／256 | 2.037 | 2.191 | 0.747 | 0.811 |
| Double Gauss 28°／256 | 2.287 | 2.117 | 0.739 | 0.807 |
| 100° 广角／64 | 7.644 | 2.617 | 6.689 | 0.262 |
| 蓝色陷波／64 | 3.247 | 0.391 | 0.091 | 0.117 |
| Hubble／64 | 0.691 | 0.208 | 0.075 | 0.032 |
| 绕点倾斜透镜／64，波长 2、视场 1、最大频率 50 cycles/mm | 1.235 | 1.267 | 0.757 | 0.533 |

本机广角重复请求约快 25.5 倍，近轴面示例首次请求约快 8.3 倍。广角首次累计托管分配约 58.487→4.279 GB，重复请求约 58.469→0.111 GB，实际追迹提交约 223 万→2.83 万；近轴面首次分配约 17.106→0.171 GB，追迹提交约 438 万→3.03 万。**累计分配不是驻留内存**，计数包含瞄准/诊断请求，不是最终瞳孔节点数。

普通折射镜头的重复请求主要仍花在波前/PSF 构造与变换，本轮约 0.7–0.8 s，没有稳定提速；部分小请求增加约几十毫秒。全部六组计时均保留，不能把热点收益宣传为每个镜头的统一倍率。运行时负载、JIT/GC 会波动；本轮不设硬性 CI 毫秒阈值。基线与最终构建之间有其他聊天的工作区更新，各组使用固定二进制和原始输入身份，未把其他功能变化归入本轮验收。

**195/195 定向检查通过，0 失败、0 跳过。** 包含 13 项本轮新增检查及原有独立相位/介质/有限共轭/尺度参考、标量/批量运输、坐标间断、材料错误、MTF 投影、两档收敛/预算/取消与缓存失效检查。另包含真实 CUDA 的 FFT 与 PSF/MTF 入口三项对照，已显式启用硬件检查开关，不能把默认跳过回执当作硬件通过。

正常 Release 主程序构建 **0 警告、0 错误**；最终数值复测和 195 项回归使用该次主程序输出的 Core/Application DLL。Core SHA-256：`E8F72EE6E6B566D6E0355EDD9E91FA93143FFE21C453DD4334DEAAD7FA0F697A`。实际源码、二进制及证据哈希见 [sources.json](sources.json) 和 [archive.json](archive.json)。

共享工作区之后又被其他聊天构建，实时输出已前进到另一哈希。本回执绑定上面捕获并实际验证的二进制，不扩展为对其他任务后续输出的验收，也未用旧文件覆盖其新构建。

第一次受限测试主机未连接而中止，未执行用例；后续一次输出放在仓库之外，7 个旧测试找不到仓库根。使用仓库内独立输出并允许运行测试进程通信后，195 项完整通过。早期 GPU 测试默认跳过，随后显式启用并通过；这些中间回执不计入通过数。诊断工具初次还原曾有 NU1900，未关闭审计；最终正常主程序构建没有该警告。

## 保留的限制

发射缓存不能消除首次精确瞄准，较大总采样可能超过缓存额度并发生正常逐出。波前、复光瞳、PSF/OTF 还没有完整的跨分析结果缓存；视场/波长外层仍逐组执行，本轮没有引入无界并行。

蓝色陷波 256 的早期修复后补充运行约 3.65 s 首次、2.02 s 再次，已成功完成；修复前有采样观察的该请求在取消预算后约 39.38 s 退出，没有完整修复前结果，不能将两者称为严格同档完整提速倍率。

Twyman Green 的普通默认全频域请求在早期修复后补充运行仍约 14.54 s 并返回预算内未建立收敛。没有降低相位或结果收敛门槛强行出图；它与历史指定频率域的已验收请求不同。本轮不是全量 95 镜头新精度验收，也未声称所有高采样/多档请求都能即时完成。补充运行的具体二进制身份单独保存，不冒充最终主程序的计时。

[evidence.zip](evidence.zip) 保留逐轮设置/回执、原始曲线、构建和测试回执；相同内容按 SHA-256 去重，逻辑文件名映射在压缩包的 `index.json` 中。既有原始处方与正式外部参考只引用身份，不另行复制。构建和验证均为后台/无界面，未启动、关闭或操控用户窗口。
