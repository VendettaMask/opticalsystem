## 确认并修复的通用问题

共用 `WavefrontSurfaceControl` 每次绘制都重新筛选、排序并构建完整网格；灰度／伪彩色为每个单元创建可变画刷；等高线即使没有任何边穿过指定值，也为每个单元创建交点列表及数组。这些开销发生在 UI 绘图路径，适用于使用该控件的干涉图及其他标量图，不按镜头名称分支。

现在每个控件仅保留一份网格和输入快照，每次检查所有影响网格的 X／Y／Value，兼容同一只读接口后面的可变列表。绘图按精确 RGBA 复用不可变画刷，最多保留 4096 项；不量化原数值或修改颜色映射。等高线仅跳过四角全部位于同一侧、原本不会产生交点的单元，保留边界等值规则、鞍点连接及原插值。

另补结果控件构造、首次绘图开始／结束和慢绘图日志。绘图计时仅覆盖托管绘图调用，不代表操作系统合成或显卡呈现已经完成；计算成功也不等于界面显示完成。

## 同输入实测

使用内置 Beam Expander 示例和真实分析服务，独立配置目录，Release／.NET 10.0.8／Avalonia 12.1.0＋Skia 离屏软件绘图。原无响应安装包自带 .NET 10.0.11，且桌面图形设置为自动；两者环境边界分别保留，没有把离屏结果当作原生 GPU 无响应复现。

每个设置独立进程，先完成计算、控件构造、布局和首次绘制，再重复绘制三次，表中为这三次中位数。分配为过程累计分配差值，**不是驻留内存**；没有进行多进程多轮统计。

| 灰度 64 | 22.23 → 6.46 ms | 2.74 → 0.70 MB |
| 灰度 512 | 255.85 → 105.02 ms | 138.31 → 0.70 MB |

五组 1200×900 输出逐像素一致；灰度画面已实际检查。18 次宽窄窗口变化、绘图／数据切换及结果控件重建均完成，修改前后都未重现原始无响应。因此，本轮证明绘图分配缺陷与修复效果，**尚未证明原始卡死已彻底解决**。

## 回执与重放

[verification.json](verification.json)记录设置、分阶段计时、程序集身份、失败对照和边界；[evidence.zip](evidence.zip)保留原始计时、TRX、唯一图像载荷及重放程序源码。相同图像只保存一次，通过 `image-roles.json` 映射前后角色，归档逐项摘要已复核；不保存安装包或第三方运行库副本。

把归档中的 `probe` 提取到仓库根目录的 `.tmp/interferogram-ui-probe`，在仓库根目录执行以下命令可重放当前源码的后台绘图；配置写入指定输出目录，不启动产品原生窗口：

```powershell
dotnet restore .tmp/interferogram-ui-probe/InterferogramUiProbe.csproj --locked-mode
dotnet run --project .tmp/interferogram-ui-probe/InterferogramUiProbe.csproj -c Release --no-restore -- .tmp/interferogram-replay 512 gray
```

第三个参数可选 `gray`／`color`／`contour`；第四个参数为绘图／数据页索引，第五个可传等高线间隔。源码与检查入口见[共用绘图控件](../../../../src/OpticalSystemDesign.App/Controls/WavefrontSurfaceControl.cs)和[新增回归](../../../../tests/OpticalSystemDesign.Tests/WavefrontRenderingAllocationTests.cs)。
