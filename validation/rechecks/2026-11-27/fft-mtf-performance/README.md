# FFT MTF 通用性能诊断

本文保留诊断阶段的原始范围；后续通用修复、完整曲线复测和适用边界见[共享链路修复记录](../fft-mtf-general-optimization/README.md)。

本次按未限定镜头的通用性能问题排查，独立选择普通折射镜头、广角镜头、反射系统和带近轴面的示例。只新增可重放诊断与记录，未修改产品光学计算、采样、相位保护、收敛目标或启动脚本。未运行全量精度矩阵，也未控制用户的运行窗口。

## 实测方法与范围

诊断调用真实 `WorkbenchApplication.Analyses.RunAsync`，包含冻结文档、共享光线缓存、运行时参数归一化和结果 DTO 构造，不包含界面绘制。每个进程连续运行相同请求两次，第一次为该进程的首次请求，第二次允许使用同一服务的光线缓存。它们不是两次独立冷启动，亦不是多轮统计中位数。

除表中注明外，使用 Release、全部定义视场、全部定义波长、调制、像面、默认按需加密、最大频率自动、偏振关闭。设备为 24 逻辑处理器、.NET 10.0.8；GPU 对照实际记录 CUDA RTX 5060 Laptop GPU。文件和二进制身份见 [sources.json](sources.json)，每次设置、回执、计时与检查点栈保存在 [evidence.zip](evidence.zip)，汇总见 [timings.json](timings.json)。

| 实际入口与设置 | 首次请求 s | 同进程再次请求 s | 首次实际追迹请求数 | 首次累计托管分配 GB |
| --- | ---: | ---: | ---: | ---: |
| 菜单 Cooke 40°，256，CPU | 1.844 | 1.155 | 455,697 | 0.801 |
| 同镜头、同采样，自动 GPU | 1.953 | 0.887 | 455,697 | 0.842 |
| 同镜头、同采样，Debug CPU，最后复测 | 2.670 | 1.493 | 455,697 | 0.801 |
| 100° 广角，64，CPU | 10.867 | 11.553 | 2,257,966 | 58.334 |
| 蓝色陷波示例，64，CPU | 2.687 | 0.100 | 4,375,710 | 17.106 |
| Twyman Green，64，CPU，含检查点采样 | 19.553 | 21.284 | 4,381,564 | 107.830 |

GB 为 `GC.GetTotalAllocatedBytes` 的累计分配量，**不是同时驻留内存**；射线数包含瞄准及诊断的重复提交，不是最终光瞳节点数。Twyman Green 的本次普通默认请求两轮均返回 `Unavailable`，原因是声明预算内未建立结果收敛，不将耗时当作成功出图。该默认请求与历史指定频率域的参考请求不同，不改写历史验收。

早期 Debug 对照为 3.895/2.380 s，体现运行时负载和 JIT 波动；不能把某一轮倍率称为固定提速。普通 64 采样探索中，菜单 Cooke、Double Gauss 28°、Hubble 以及内置性能输入均能亚秒返回。选例证实共享热点，不据此声称所有镜头同样缓慢。

## 已定位的开销

1. **光阑瞄准先于物理光线缓存命中。** `WavefrontEngine.GenerateChiefRay` 每次先调用 `RayGenerator.GenerateNormalizedPupilSamples`。需要真实光阑瞄准的节点进入 `StopAimingSolver.Solve`，反复调用 `SequentialRayTracer.TraceToSurface`；生成光束后才查物理追迹缓存。100° 广角再次请求仍执行 2,230,948 次追迹、累计分配约 58.470 GB。检查点采样的主要栈位于上述求解链路。当前窄范围的 `TryGenerateCachedFftPupil` 是另一种物理采样约定，不能直接作为通用瞄准缓存启用。

2. **近轴面需要的相位积分代价高。** `ParaxialPhaseTrace.Evaluate` 对实际受光节点执行 Simpson 加密，每个积分位置可能再次 `Beam.Aim`，后者用多次入射几何追迹求解。蓝色陷波 64 采样首次请求约 437.6 万次追迹、17.1 GB 累计分配，采样栈以该积分/瞄准链路为主。256 采样的有采样诊断在 35 s 取消预算后约 39.379 s 退出，已执行 44,568,634 次追迹并累计分配约 174.091 GB；未完成，不报告为完整计算时间。FFT MTF 依赖相位，不能照搬图像强度仿真的省略相位路径。

3. **默认欠采样恢复会变成多档完整计算。** 普通 `MTF` 默认按需加密，局部相位不满足条件时转入 `FourierResultValidationAnalysis`。当前外层先试请求档，验证器又从请求档开始，逐级求值和比较结果；MTF 默认预算上限为 2048。即使最终无法给出收敛结果，也已经付出多档光瞳、波前和变换开销。此处优化应复用相同物理输入下的已求值数据、改善工作规划，保留原相位保护和两档收敛条件。

4. **逐组处理与中间结果仍有开销。** `MtfAnalysis.GenerateData` 串行遍历视场和波长，常规路径先构造二维 PSF 再求两个方向 OTF；共享服务缓存的是光线，而不是完整波前/复光瞳/PSF/OTF。菜单 Cooke 256 在第二次请求中仅有 135 次实际追迹，仍需约 1.155 s、累计分配约 658 MB。前一轮已将第二次二维 OTF 变换改为完整 PSF 投影加两个一维变换；该项修复不能消除本次发现的前置瞄准与相位热点。

5. **普通启动器运行 Debug。** `Run-OpticalSystemDesign.cmd` 的 clean/build/run 都没有指定配置，因此使用 Debug。最后同设置复测中 Debug 约 2.670/1.493 s，Release 约 1.844/1.155 s；早期轮次差距更大。诊断没有修改该脚本，也没有关闭调试或改变运行中的软件。

## 单独 FFT 对照

通过反射调用同一共享 Core 的二维 Fourier 入口，使用双精度复数组，每个尺寸预热一次，再计时三次。只计变换调用，不计创建输入；GPU 的每次调用包含该实现的设备分配、传入与读回。单位为三轮中位数毫秒。

| 二维边长 | CPU ms | GPU ms |
| --- | ---: | ---: |
| 128 | 2.651 | 0.644 |
| 512 | 10.232 | 2.673 |
| 1024 | 40.826 | 8.340 |

此对照说明 FFT 核心能在毫秒级完成这些尺寸；完整请求还含多个视场/波长及前处理。GPU 已实际执行变换，但不自动加速本次采样到的 CPU 光阑瞄准和近轴相位积分，不能只用 FFT 加速倍率估算整条分析提速。

## 后续优化次序

先处理相同冻结处方、视场、波长、瞳孔坐标和物理选项下的瞄准/波前重复工作，减少逐节点分配与重复能力检查；再优化近轴相位的可证明精确分支及积分内复用。随后复用自动加密的已完成档位，限定跨分析缓存容量，最后评估视场/波长的有界并行和剩余数组/FFT 开销。缓存键需覆盖完整光学身份，保留失效、取消与资源预算。

本记录为性能诊断，不是精度改动或新数值认证。没有新增通过测试数。诊断 Release/Debug 构建成功，构建出现 NuGet 审计端点不可达的 NU1900 警告；未关闭审计。检查点观察以 10 ms 限频抓取当前调用栈，存在并行工作栈缺少外层帧及观察扰动，不能把栈计数换算成严格耗时占比。关键广角/近轴面结论另有关闭观察器的实测。
