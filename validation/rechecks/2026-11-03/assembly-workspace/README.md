## 过程与范围

最初一次构建缺少标题栏命名空间导入，已修复。随后正常App构建通过，但共用主测试DLL被另一项后台检查占用，出现复制重试失败；没有关闭该进程。临时`.tmp/assembly-ui-runtime`用于独立编译和首轮离屏检查，不作为正常默认输出通过的依据。独立构建曾出现重复using警告，已清理。

首轮6项中1项通过、5项失败：宽屏初次布局向已有父节点重复添加结果面板，引发Avalonia父节点异常。已改为两个面板始终保留同一父节点，窄窗口仅切换可见性和列宽，记忆原分栏比例。旧记录保留在`first/workspace-first.trx`和`test-first.log`，不计为最终通过。

共用测试目录释放后，正常默认Release App、内置模块依赖和主测试项目重新构建，见[构建日志](build-default.log)。当前检查包含明暗主题、三语布局设置、13/18/22字号、760–1440窗口、全部参数滚动访问、真实离屏鼠标分栏拖动、表格排序、数字键盘编辑、宽窄切换、模式参数适用性和文档修订失效。实际Double Gauss镜头的UI叉丝像素、返回计数和倍率与同物理请求的共享Application结果直接逐项比较。

正常输出的`checked/workspace-checked.trx`为7通过/2失败，两个失败都在真实镜头测试的初始化记录中：通用JSON序列化器拒绝原处方合法的无穷物距，尚未进入装调窗口。仅修订测试的数值记录选项后两项通过，又在相同两项中补查实际大字号图像，使用产品的`ApplyRecursively`全界面字号入口，而非仅改变窗口根字号。前后App/Core/Application字节身份保持；已通过的7项布局检查不重复运行或重复累计。先前`real`和`final`两项批次保留其阶段范围，以`final-typography`为最终真实镜头结果。

探测面无结果时不绘制假图；已有结果仍使用原固定320×320像素和物理毫米范围。新绘图仅测量刻度文字边距并居中，保留原灰度映射和光线数据。所有事件发送给测试内的headless窗口，不控制用户桌面或系统剪贴板，不启动/关闭用户应用；没有安装、发布、实物仪器或原生多屏验收。

只保留必要的真实预览、日志、TRX及身份元数据，不冻结另一份源代码或运行时。临时构建留在忽略的`.tmp`目录，不加入验证证据或交付。
