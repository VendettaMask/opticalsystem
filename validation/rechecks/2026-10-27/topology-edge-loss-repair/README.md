# 21°边缘失光：原因、修复与同预算4→3复验

日期：2026-10-27。结论：确认真实口径遮挡，修复训练遗漏边界光线及可选阶段检查耗尽补偿额度的问题；同预算短程仍未得到合格三片，最少合格片数保持4。全部计算在后台串行执行，BelowNormal、两个CPU处理器、无GPU或桌面操作；原完整长训练保持停止，未提交/推送/发布。

## 具体原因

使用[上一轮](../representative-reduction/README.md)同一合格四片和失败三片，全部物理计算走共享Core，不更改口径或取消裁光：

- 遮挡面是第二片SF15玻璃的后表面 `element-002:back`（三片中的顺序面索引6），有效半口径3mm。21°正Y视场的瞳孔上沿67.5°、78.75°、90°、101.25°、112.5°五个方向在每个波长被挡，共15/99条检查光线。
- 原失败三片在486.1327/587.5618/656.2725nm的最差口径缺口分别为58.136/65.606/68.846µm，红光最大截距半径约3.068846mm。并非数值边界误差；所有被挡光线在Core不裁口径的诊断续迹中都到达像面，无瞄准、交点或全反射失败。
- 密集10×32积分也分别损失3/4/6条，合计13/960；有效比例98.6458%虽超过98%，独立边界零失光门槛仍失败。训练1×8只取内部Gaussian点，三色全部通过且最小余量超过0.4mm，原残差完全看不到这些边缘光线。
- 被删除的是光阑后的一片N-BK7弱透镜：前顶点z=3.795600mm、厚1mm、前后曲率±0.003/mm。只删除它、保留其他曲率/材料/绝对坐标，已经在同一SF15后表面损失9条。弱光焦度不代表对斜光束的路径没有作用。随后近轴恢复匹配一阶量，却未约束这个真实边缘包络，失光增至15条。

以下只重放已保存的阶段处方，不新增优化。口径缺口来自Core可诊断但不算作物理有效光线的续迹。

## 已修复的问题

`TopologyTrainingSampling.IncludeBoundaryClearance=true` 在原训练视场另加33条中心/边界的可微最小口径余量残差，独立于原Gaussian光斑统计，沿用几何约束0.01mm尺度；固定布局、全部光谱、实际额外追迹及GPU计数合并保留。缺光线不能被丢弃或当作零梯度，部分请求不能产出可用目标。没有改变Core追迹、材料、口径、光阑、像面或验收定义。

首轮8次隔离对照显示，增加边界残差确实改变了处方，但局部后可选密集检查只得到不足的追迹额度，耗尽训练余额后Full首次评估即失败。因此新增 `Options.ProtectCompensationRayBudget=true`：仅对Local之后、Full之前的可选检查，当剩余非终验额度不足以预约其完整既定额度时，记零工作量 `StageValidationDeferred` 并继续Full。恢复后的可行阶段检查、独立终验和80万终验预留仍保留。此策略不声称保证所有配置下的训练额度，只解决此处部分检查耗尽余额的情形。

两个新增字段均可空且null不写入身份，旧计划/检查点仍按旧行为执行。新自主示例显式开启两项；不同残差或策略不得解释成同一Adam续跑。原AutoLens UpstreamE58入口、默认MOBILE_CONFIG和停止的训练均不变。

## 冻结协议与实际结果

源为上一轮已合格四片的固定物理评测副本，不冒充原库文件未经修改的导入。原来源物理化/准备成本在上一轮单独留痕。使用42/101、C直接恢复/D渐进后备；源几何不扰动，两个种子仅控制搜索，结果重复不能算两份独立处方。

每次仍为6决策、600函数、100梯度、200万实际追迹、60秒上限；局部4/全目标8次短程提议、恢复150函数、训练每方向3点/1×8/轮廓8、最大单训练阶段40万、总额内终验预留80万。曲率变量、尺度/边界、材料和结构权限与上一轮相同，未增加轴向/面型自由度。

最终验收完全不变：每方向21点合并后35视场、每视场RGB共960积分与99中心/边界光线、轮廓64；焦距/F数±2%，RMS≤50µm、最大半径≤150µm、畸变≤3%、有效积分比例≥98%，独立边界零失光及原结构/制造门槛。
