# Initial-structure direction, checkpoint identity and background acceptance

The user changed the product goal to our own initial-structure retrieval/design workflow. Upstream AutoLens one-to-one reproduction is no longer a completion gate. Pure C#/.NET, shared Core and the original physical/manufacturing gates remain mandatory. Existing algorithm identities and historical evidence remain unchanged.

## Checkpoint protocol repair

The retained [Linux failures](../two-element-primary-first/green-tests/green.trx) occurred while loading the Windows checkpoint, before optimization. The same two tests passed on Windows before this repair ([baseline log](historical-windows-first.log), [TRX](historical-windows-first.trx)). These are not newly reproduced Windows failures.

The old v1 fingerprint serialized generated Gaussian pupil and boundary trigonometric coordinates. Equal algorithm/settings can produce different last-bit sample encodings on different platforms. Read-only auditing of the retained Windows checkpoint and [Linux native readbacks](../two-element-primary-first/native-audit/native-audits.json) verifies exact equality of targets, structural constraints and all 35 field coordinates. The recorded v1 protocol hashes differ: Windows `7fc8e060…92e964`, Linux `8aa5e4e9…6245f4`. The differing fingerprint inputs are the generated sampling values; individual Linux sample values were not retained, so the precise transcendental operation/ULP difference has not been measured. [Original Windows audit](identity-windows.json), [complete descriptor binding](identity-windows-v2.json), [read-only C# audit source](identity-audit/Program.cs).

New physical assessments use protocol v2: exact targets, constraints, field coordinates, algorithm versions, 10×32 Gaussian integration, 32 boundary directions plus center, 64 radial manufacturing checks, CPU, common polychromatic centroid and the existing distortion/transmission settings. Runtime samples and physical calculations still come from the unchanged shared Core. This is a protocol identity revision, not a numerical or optical acceptance change.

The two known historical v1 encodings are accepted only when the complete v2 descriptor equals `233c8a3914f4510f55c201c0acb91b521f2cbb02bd28cd6c3f15df95c728feee`. Native v1 verification remains available for other existing records on their original platform. Unknown hashes or different descriptor bindings fail closed. This narrow registry does not claim portability for every unknown historical v1 protocol. No rounding, checksum bypass, history rewriting, cache replacement or optical tolerance change is used. Existing file checksum, plan/task/optic fingerprints, bounded collections, optimizer identity and append-only accounting checks still apply.

The new regression checks both retained encodings, unchanged source identity, zero rays during load/validation, and rejection after a one-ULP target/constraint change, a field change or a forged protocol. It also saves and reloads checksummed copies with each retained encoding in a temporary directory (the source fixture is never written). The two original historical optimizer tests and the retained sampling-precision regression passed in the first [focused run](portability-ui-focused.trx) (6 tests, 16 seconds); the strengthened [file roundtrip tests](identity-file-roundtrip.trx) passed 2/2 in 2 seconds.

## Background UI acceptance

The native attempt reached the normal main workbench → Laboratory → Initial Structure → Autonomous Topology window and its native open-file dialog. It was interrupted by the user's physical Escape key. It did not complete plan loading, a search or native acceptance. The user then explicitly required background testing without desktop occupation. No further computer-use tools or native launches are used. The isolated process was already closed when checked in the follow-up; installed application processes were not stopped. The temporary foreground verification-profile feature was removed from final product code.

An actual accessibility defect observed in that attempt is repaired: action buttons, numeric inputs and checkboxes expose their localized labels instead of internal IDs. Existing stable control IDs remain unchanged. Chinese, English and Japanese are checked in the headless UI regression.

The follow-up uses `SafeHeadlessUnitTestSession` / Avalonia.Headless with off-screen Skia rendering, temporary run directories, two processors and BelowNormal priority. It checks plan loading/checking/saving without tracing, unsupported/invalid input errors, stop/save/reopen/resume, append-only work/history, exact Core STAROPT export, close-during-work cancellation, failed-save window preservation and the existing module entry/preset controls. The smoke fixture intentionally sets an unattainable 1e-9 mm RMS limit to verify that an unqualified export is labelled truthfully; it is not the original design acceptance task. Native file dialogs are not replaced by claims of native acceptance: headless picker seams cover only application behavior around selection. Follow-up results: **10/10 passed, zero skipped/failed, 48 seconds**, recorded in [background log](background-acceptance.log) and [TRX](background-acceptance.trx); five off-screen renders are under `headless/`, including [480-DIP Japanese layout](headless/narrow-ja-JP.png) and [unqualified endpoint/export](headless/endpoint-failed.png). These test groups overlap and must not be added together.
