# First-order seed preparation and diverse autonomous pools

This implements the first two priorities agreed for our own initial-structure workflow: bounded first-order seed preparation and diversity-aware candidate retention. It draws on the workflow ideas documented by [HappyLens](https://happylens.readthedocs.io/en/latest/gallery/prime_generation.html); no HappyLens source or Python/PyTorch runtime is included, and this is not a Delano implementation or upstream reproduction.

## Product behavior

Inside Laboratory → AI Initial Structure → Autonomous Topology, **Prepare First-Order Seeds / 生成一阶起点** explicitly runs a separate CPU preparation job. It uses the loaded/example physical templates, deterministic bounded multi-start curvature/optional axial coordinates, and the existing numerical least-squares solver. Thick-lens transfer matrix A, whole-system optical power, fixed-stop inverse F-number, all derivatives, surface sag, separation and slope come from shared Core. No module-local optical engine or thin-lens acceptance surrogate is introduced.

The preparation panel sets starts, retained seeds, function cap and time limit. Its stored configuration is `Options.SeedPreparation` (version 1); opening/saving a plan or starting an autonomous run does not automatically execute preparation. Defaults: 12 starts, at most 4 retained seeds, 300 total function requests, 40 per start including final first-order checks, 15 seconds and 10,000 traced-ray hard allowance. The usual centered paraxial path consumes zero traced rays; a trace budget still guards accidental/internal physical tracing. Only explicitly permitted curvature and axial coordinates move. Materials, profile families/high-order coefficients, mechanical reference, stop, image and apertures remain fixed in preparation. Protected elements and original axial windows are retained. Historical read-only optimizer plans and deletion transition templates cannot use this command.

Search uses 16 radial geometry samples; every retained endpoint also passes the original manufacturing limits on the 64-sample Core grid, the original focal-length/F-number tolerances, and the declared matrix-A focus tolerance. This is **first-order feasibility only**: no spot, distortion, field transmission, global optimum or full physical acceptance is inferred. Complete optical checks still run through the existing autonomous search. Preparing seeds replaces the draft seeds only when feasible endpoints exist; otherwise original seeds remain. It does not optimize a running/historical checkpoint in place.

Preparation records include the complete source plan, protocol, settings, accepted endpoints/rejections and actual work. Reports (`.seed-search.json`) have a checksum and bounded atomic write; a companion `.topology-plan.json` can be reopened normally. Both are saved under the run directory's `preparations/`. Stop/cancel preserves completed preparation results and their charged work before returning; close waits for completion/save. Save failure leaves the draft unapplied and reports failure. Editing or loading another plan clears stale preparation summary text.

**Retain Diverse Structures and Glasses / 保留不同结构与玻璃组合** explicitly sets `Options.PoolDiversity` (version 1, bounded rank window). Per element count it prioritizes formally qualified designs, keeps the best-ranked representative, removes exact prescription duplicates, then selects farthest representatives from the quality-ranked window. Distances use normalized prescription coordinates and categorical material differences. This is a structural descriptor, not a computed per-element aberration or power model. It uses persisted results/metadata without additional optical calls; no cost is hidden in pool selection. All candidates and accepted archives remain in history even when not retained for further scheduling. Loaded pool membership/order must match the recorded policy before work can run.

Both optional properties are omitted when null. Existing plan fingerprints, default examples, old scoring-only pool selection, optimizer versions and checkpoints are preserved. Unknown policy versions fail closed. This change does not enable the old hybrid optimizer entry point.

No desktop windows, native input, GPU, remote job, full suite, release, commit or push was used for this batch. Native interactive acceptance and post-fix Linux/macOS execution remain open.

Default Release build completed through the test projects.

The retained small preparation used three starts and 120 total/40 per-start allowances. It spent 58 functions, 61 explicit Core matrix/pupil requests, 55 Jacobian builds and 14,458 geometry queries, with zero traced rays; one endpoint passed first-order preparation and two were rejected by dense geometry checks. Timing is a single-run measurement, not a benchmark. The fixture is the three-element example with the axis field only. The UI workflow separately uses an intentionally unattainable RMS limit to verify that subsequent physical failures remain unqualified. Neither fixture certifies the original wide-field design or successful three-to-two reduction.

## Next priorities and limits

Adaptive population/global exploration is the next independent opt-in strategy to evaluate under equal quotas. Deletion contribution ranking follows the existing strict deletion/restoration work. Catalog-material branches with recovery/compensation already exist; stronger neighborhood selection and alternating allocation remain future work. These three recommendations are not claimed implemented by this first batch. No new original-task output comparison or success-rate claim is made.
