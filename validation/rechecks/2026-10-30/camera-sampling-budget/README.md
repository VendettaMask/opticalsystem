# 三维衍射瞳面/场景连续加密与保存复算

日期：2026-10-30。针对上一轮原 32×24 冻结实验中央 `(14,10)` 起 4×4 区域的两个未完成项。原镜头处方、像面、像元尺寸、波长、QE/传感器/ISP、PSF 额外半径 4、源保护带 24、参考数据及既有精度容差不变；原完整 B 不替换成加密结果，不自动降低任何请求采样。

计算上限阻断已解除，五个相邻层级对照全部完成。场景末级变化明显缩小；瞳面 48→64 仍变化 **1.5420%**，且比 24→48 的变化略大，**尚不能确认瞳面已收敛**。没有放宽容差把它标为精度通过；完成分级验证与确认精度达标是不同结论。

## 原因与修复

原实现对每个有效瞳面点都先计算四条出瞳面积有限差分辅助光线，之后才发现该源点的完整原 PSF 窗口与检查区域没有交集。这些辅助光线消耗追迹额度，却不会用于任何输出复场采样。新调度仍追迹全部原源点、实际瞳面点、遮挡和几何落点，先用与原算法完全相同的窗口求交；仅空交集不再计算辅助映射。区域内贡献、远旁瓣、有限单元公式和累加顺序保持，没有强度阈值裁剪、几何回退或峰值/能量拟合。

瞳面 12→24 按原调度的等价计数为 9,536,640 次追迹（本次实际数加省去数），优化后实际 **5,887,656**，省去 3,648,984 条无输出辅助光线。场景 1→2 的等价计数为 10,343,024 次，优化后实际 **6,556,004**，省去 3,787,020 条。因此这两项均能在原 8,388,608 条额度内完成；基准对保存 B 的波段功率和光电子逐点最大差仍为 0。

继续到瞳面 48/64 与场景 4 包含真实新增的采样，不能靠缓存或删点假装免费。局部诊断采用明确记录的 `RegionExactSupport/2` 工作策略：单次渲染全程累计最多 **67,108,864** 条实际追迹、**400,000,000** 次表面交互、**200,000,000** 次复场单元求和；没有按源块重置额度。流式候选查询上界 **1,048,576**，实际命中表面点仍受原 **65,536** 上限约束。原 `网格 × 对象数` 预检过度估计了实际表面点；未命中的对象不再被记成采样点。完整渲染仍使用原光线/交互额度和候选预检，不提供靠局部 API 拼接整图的流程。计算工作额度与物理误差容差分别记账，未放宽后者。

## 分级、保存与兼容

- 瞳面保持场景 1、像元中心、窗口 4 和保护带 24，连续比较 12→24、24→48、48→64。
- 场景保持瞳面 12、像元中心、窗口 4 和保护带 24，比较 1→2、2→4。
- 每级保存三波段 W/像元、期望电子、无噪声 RAW、设置、全局 CFA 相位、工作计数与相邻级差异。不把后续层级差误称为对原基准的差；未完成层级后不能附带后续成功数据。
- 完整实验保留原 B 和各级报告，绑定原 B SHA-256。旧单层报告及失败状态保持可读，使用冻结旧报告夹具验证原身份没有变化。当前 V8 光学规则和 V7 历史复算身份保持。
- 界面按一次点击执行瞳面/场景的全部实现层级，展示实际工作量和限额；取消或失效任务保留规则沿用原 A/B 流程。局部比较没有新增“精度通过”阈值，不能用局部或独立轴结果证明整幅、联合高采样或商业软件认证。

实际运行由 [C# 诊断程序](../../../../tools/diagnostics/CameraSamplingBudget20261030/Program.cs)调用原服务完成；两个独立轴并行执行，每轴各计算一次基准，成本账本计入两次真实基准和五次加密渲染。保存后替换工作工程，从冻结镜头重新计算所有级别，并逐点核对功率、电子、无噪声 RAW、参数、各级差异与执行计数。

全链复算已完成，上述逐点数值和计数全部完全一致。交付计算与独立复算每轮各 7 次渲染，实际追迹总计 107,045,052 条、表面交互 493,468,152 次，省去无输出辅助追迹 62,417,348 条；单级额度在本级所有源点间累计，不能把各级累计量误当成单次上限。计入两次基准，不隐藏重复执行成本。
