# 初始结构 M2：实现与对照验证

范围为[新计划](../../../../docs/INITIAL_STRUCTURE_SEARCH_IMPLEMENTATION_PLAN_2026-10-30.md) M2.1–M2.5；入口及实现边界见[M2 使用说明](../../../../docs/INITIAL_STRUCTURE_M2_2026-10-30.md)。复用共享 Core 和原 `TopologyValidator`，不改目标、制造标准、视场、波长、逐面口径、光阑、像面或原权限。

## 冻结和实际输入

[基线清单](baseline-source-sha256.json)与[基线源码归档](baseline-source.zip)保存本轮前 Core、InitialStructure、桌面入口、M0/M1 重放程序、计划与构建属性共 489 个文件，以及原 HEAD/dirty 状态。用户其他在途修改保留，未重置、提交或推送。

[正式协议](experiment-protocol.json)、[实际运行时哈希](formal-runtime-sha256.json)、[源码哈希](formal-source-sha256.json)固定运行身份。实际运行的 119 个搜索/构造/重放文件另存[归档](executed-source.zip)，逐项 SHA-256 回读；正式结果之后只对一个引擎文件及测试作空白排版，保留执行时的原字节。每个结果的 input 文件保存完整实际处方、配置、取得起点的费用、原输入文件路径及 SHA-256。八片任务使用 M0/M1 相同种子关闭臂中实际完成原终验的处方，原 21°使用冻结原始三片输入，所有臂共享相同起点；不能把原 21°继承的合格输入称作新构造成功。

统一端到端上限为每任务/种子 600 functions、200 gradients、2,000,000 rays、110 s；八片 M0/M1 起点的冻结实耗先从上限扣除，最终再相加，原 21°用户已有处方不另收自动取得费用。M2 对每个父方案重新完整终验并计费。旧准备的墙钟数据来自当时实际运行，当前 M2 耗时另列，不冒称在本轮重新测过整段历史准备。

六臂：fixed（固定拓扑控制）、direct（结构变化后直接短补偿）、recover（先一阶恢复）、compete（再进入统一竞争）、power（仅功率分配新路线）、combined（组合）。种子 42–46，各臂三任务，共 90 次；按种子轮换臂顺序，串行运行、Core CPU double、进程 BelowNormal、抑制嵌套并行。阶段和配额在正式派发前冻结，保留所有失败和未完成者。

## 执行与回读

重放程序：[C# 实验入口](../../../../tools/diagnostics/InitialSearchM2/Program.cs)。独立的[完整校验程序](../../../../tools/diagnostics/InitialSearchM2Verify/Program.cs)回读保存哈希、Core 快照/协议、原目标和约束、全部累计费用、统一上限、工作起点门槛、不可覆盖的父方案和重算 Pareto 集。

```powershell
dotnet build tools/diagnostics/InitialSearchM2/InitialSearchM2.csproj -c Release -m:1 -p:NuGetAudit=false
dotnet tools/diagnostics/InitialSearchM2/bin/Release/net10.0/OpticalSystemDesign.InitialStructure.Benchmarks.dll . .tmp/m2-replay-42 42 combined
dotnet run --project tools/diagnostics/InitialSearchM2Verify/InitialSearchM2Verify.csproj -c Release -p:NuGetAudit=false -- validation/rechecks/2026-10-30/initial-structure-m2
pwsh -NoProfile -File tools/diagnostics/InitialSearchM2/Summarize.ps1 -EvidenceRoot validation/rechecks/2026-10-30/initial-structure-m2
```

每次重放用新目录，既有证据不覆盖。可替换 arm 和种子，最后附任务名可仅重放一项。关闭 NuGet 在线审计是由于环境无法连接漏洞数据服务，未改项目审计设置，也不代表漏洞扫描通过。

## 回归和修正记录

首轮 11 个新计算用例中 3 个数组断言使用了 backing-array 身份比较，修正为逐项比较；界面配置用例同样改为内容指纹比较。功率路线的全范围随机分配未在小夹具中闭合，改为冻结前部的有界局部功率分配；依然通过实际 Core 矩阵和独立闭合验证，未用父功率或粗分数冒充结果。位置随机化使用同片刚性移动并裁入原机械边界，避免首片被提议到物方参考面之外。失败和预试记录保留。

首次正式 v1 批次在 50 次已保存结果后主动中断并保存至 interrupted-formal-v1/，原协议及运行时/源码哈希保持。当时完整合格判定正确，但部分直接补偿候选一阶目标失败仍进入工作起点返回值。已加回与旧准备相同的原几何、焦距、F 数和无过渡片门槛，并新增四类明确回归；未修改原目标或终验。v1 不进入最终统计，v2 重新执行全部 90 个单元。

修正后的定向回归 **53/53 通过**，零失败/跳过；默认 Release App/模块构建成功。覆盖 Core 厚片功率逆解与独立参考、真实固定功率/目标闭合、全部结构操作及原权限、保护片与口径、全新绑定、预算/取消、实际有界保存、旧结果内容哈希、M0/M1 和三语离屏回读。没有全仓或原生桌面测试。

## 正式结果

正式 v2 **90/90 次完成并通过独立回读**，242 次原规格密集验收全部完成、未完成数 0。保存内容哈希、同快照 Core 指纹、原验收协议、全部原目标/约束、固定平面/口径、保护片、各候选累计及统一预算、工作起点门槛和 Pareto 重算均通过。116 个搜索/构造/重放源码文件运行期间保持哈希。详见[校验结果](formal-verification.json)、[逐次账目](formal-runs.json)、[全部原终验](formal-finalists.json)、[全部分支](formal-trials.json)、[归档](formal-qualified-archive.json)与[汇总](formal-summary.json)。

### 恢复与竞争确有作用，但尚未越过原门槛

原 21° seed44 的二片候选通过原几何、焦距/F 数和全部通光检查：先恢复/短补偿的最差 RMS 为 **94.472560 µm**、最大半径 **264.855938 µm**；加入竞争后为 **67.867662 µm**、**199.461913 µm**。相对这次恢复终点有进一步改善，仍分别超过原 50 µm 与 150 µm 上限，故明确不合格；还有 10 条原验收违例。其他种子的失败和直接补偿分支的大幅一阶偏差均保留，没有用最佳种子替代五种子结论。

两个八片目标的恢复臂/竞争臂各有 **20 次真实恢复成功**（每目标），但所有完整终选仍未满足通光和像质。受原最多八片限制，插入和拆片均被明确拒绝，未自动开放九片。原 21°的插入、拆片、并片、材料和面型分支保持原禁用权限；5 次删片中有 3 次一阶恢复成功，2 次记录秩不足。没有通过扩大口径、改变 F 数或面型权限获得改善。

### 独立功率路线

仅功率臂和组合臂分别进行每目标五次构造：八片 F/8 有 **3/5** 次通过固定前部功率及原一阶目标闭合，八片 F/4 **5/5**，原 21° **1/5**。这些是真实 Core 逆解与独立复核，不是把随机标签算作成功；仍没有通过完整像质。`TargetClosure:Completed` 表示内部有界求解已结束但没有接受的起点，不是闭合成功；只有 `AllocatedPowersAndOriginalTargetsClosed` 计为成功。原任务两个新增合格指标继续为 0。

正式结束后对组合臂父方案和实际终选作 **43 次只读失光诊断**，额外 **71,222 rays**，单列为分析成本，没有作为搜索反馈或隐含验收额度。原快照保持，见[事后定位](posthoc-loss-diagnostics.json)。seed42 代表例：F/8 父方案与终选均只有 147/225 样本到像面，其余 78 次首先被后组固定净口径遮挡；F/4 为 57/225，168 次被原口径遮挡，轴上瞳坐标 0.888073834 的真实入射截高约 5.550461462 mm，超过首片 5 mm 净半径。原 21°父方案和保留三片终点均为 375/375 到像面；二片失败需看完整原验收像质，不能统一归因于失光。
