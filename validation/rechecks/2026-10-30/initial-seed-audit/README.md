# C# 初始结构问题检查与修改方案

本轮只新增后台 C# 诊断工具和证据，没有修改生产算法、验收要求或用户处方。输入是前一轮冻结的 v3 起点，追迹与分析全部调用当前共享 Core。当前代码已存在可选真实光线筛选，本报告按其实际行为检查，不重复建议从零增加相同能力。

## 检查方法

诊断程序：`tools/diagnostics/InitialSeedAudit20261030/`。程序成功编译，0 警告、0 错误。原始输入的 SHA256 见 `input-sha256.json`；相关引擎/Core 源码 SHA256 见 `source-sha256.json`。两次运行均完成，相关生产源文件在各次运行内未变化。第二次针对 F/4 加入保留固定光阑、移除镜片孔径后的逐面追迹，见[补充传播检查](../initial-seed-f4-propagation/results.json)。未操作桌面窗口。

测试了八片 F/8 全视场 25° 的三个起点，以及八片 F/8 全视场 10°、三片 F/8 全视场 10°、八片 F/4 全视场 25° 各一个对照起点，均为 50 mm。每候选有独立 40 秒/500,000 光线额度；全部保存实际费用。正式独立验收调用原 `TopologyValidator`，其 21 视场、积分/边界光线及阈值未改变。

口径反事实检查在独立副本上执行：以 5 个视场、所有设计波长及积分/边界光线调用原 Core 光线包络求径，余量系数 1.01，固定光阑保持。仅全部请求光线完成时才应用诊断口径，再检查 64 径向制造几何与原完整物理验收。没有将放开孔径的光线认作原口径下的合格结果。

## 实测发现

### 1. 厚透镜 v3 构造阶段未针对视场改变初始形状

同一种子 42 下，三片与八片各自从半视场 5° 改为 12.5°，保留的三份起点镜片坐标、材料和面型均完全相同。视场元数据保存正确，但其未进入该构造路径的初形选优。见 `field-sensitivity.json`。

代码对应：`FixedStopDelano` 约束近轴边缘光线、目标焦距、固定光阑和像面；`ThickStructureSeedGenerator` 的布局内评价是一阶残差和制造几何。视场只能在后续真实追迹中产生区别。这个结论只针对当前厚透镜 v3 准备路径，不代表整个产品不使用视场。

### 2. 八片 F/8 全视场 25° 首先遇到净口径限制

冻结测试的各片净半口径为 5 mm。每个广视场起点检查了 147 条最大视场光线；三份起点的这 147 条均因镜片圆孔径限制不能按原口径完成，而在诊断性继续传播时可以到达像面。第一份起点的首个遮挡位置分布在多片镜片的前后表面，并非仅某一个末端表面。

原 Core 求得三份起点所需的最大净半口径分别约 9.27、9.71、9.11 mm。按诊断包络重新确定各片口径后，三份的原密集物理验收通光比例均达到 100%，64 点制造几何检查均未发现失败。这证明此批 F/8 起点确有可恢复的口径截光；不证明用户允许扩大到该尺寸。

### 3. 通光恢复后仍有真实像差超标

| 八片 F/8、全视场 25° 起点 | 原口径完整验收 | 诊断口径下最差 RMS | 原 RMS 上限 | 诊断口径完整验收 |
|---|---|---|---|---|
| 0 | 失败 | 142.86 µm | 50 µm | 失败 |
| 1 | 失败 | 120.08 µm | 50 µm | 失败 |
| 2 | 失败 | 155.74 µm | 50 µm | 失败 |

诊断口径下只剩 RMS 与最大斑点失败，未出现通光、畸变或几何失败。原口径下丢掉边缘光线后看到的较小 RMS，不能当作镜头已经接近达标。八片/三片 F/8 全视场 10° 的两个控制起点均通过原完整验收，说明失败具有规格和初形依赖，并非所有候选都无法正常追迹。

### 4. F/4 不能只靠口径调整

抽查的八片 F/4、全视场 25° 起点中，147 条最大视场光线有 117 条可通过忽略孔径的诊断传播继续到像面，另 30 条仍失败。保持固定光阑、移除镜片孔径后，这 30 条首次无有效交互的位置均在最后一片后表面 `generated-7:back`，未记录到先发生的全反射交互。当前证据支持“该处求交/传播失败”，不足以进一步断言具体几何根因。

包络求径请求 735 条光线，只有 705 条完成，因此原 Core 正确返回 `Applied=false`，没有应用不完整半径估计。

### 5. 已有真实光线筛选能拒绝坏起点，但诊断信息不完整

F/8 广视场起点的当前默认筛选返回 `UnavailablePhysicalMetrics`，不产生 `QualityScore`，没有误放行为合格。但由于先检查 RMS 是否可用，再累积通光信息，边缘视场零通光导致提前退出时，报告仍保留轴上结果：`CompletedFields=1/2`、`MinimumValidFraction=1`、`BoundaryChecksPassed=true`。这几个值描述的是已完成视场，不是全部请求视场，容易误读。

此外，多布局内部先按最大最小间隙余量压缩成一个起点，末端真实光线筛选无法看到已被丢弃的其他布局；物理预筛前的候选截断仍使用一阶分数。这是静态流程中确认的候选损失风险，本轮未量化其对完整成功率的影响。

## 建议修改顺序

### 第一阶段：先修诊断，再区分口径权限

1. `SeedImageQualityScreening` 先记录每视场、每波长的实际通光比例和边界失败，再判断 RMS 是否有定义；零通光明确记录 0，RMS 保持 null。未完成视场与传播异常分别记录，仍禁止参加合格排序。
2. 在构造结果中增加明确的口径策略：固定口径、有界自动口径、只诊断所需口径。保留原固定光阑；不得自动突破逐面净口径、机械口径或保护条件。
3. 复用 Core 包络求径，报告所需/允许口径差。自动模式只在全体请求光线完成、尺寸在界内且重新通过边厚/空气间隙/曲面定义域时应用；其余情况返回修复原因。
4. 对 F/4 这样的传播失败增加首次失败表面、交互类型和完成样本数，不能归结为“口径不足”。

第一阶段验收：当前 F/8 广视场例能明确报告口径截光；自动口径且上限足够时恢复通光，固定 5 mm 半口径模式仍明确失败；F/4 的 30 条传播失败不能被尺寸估计掩盖。所有正式验收阈值保持。

### 第二阶段：让视场参与构造，并把物理筛选前移

1. 在布局内加入主光线与边缘光束包络的共享 Core 评价。厚度、间隔、曲率更新后重新调用一阶构造，形成有限轮次的“一阶构造—通光检查—几何复核”。所有变化受原设计权限和描述边界约束。
2. 不再只保留间隙最大的单个布局；各有效镜片分配/功率形式保留有限候选，在稀疏真实追迹后排序。采样前按结构形式分层，避免先用机器精度附近的一阶残差截掉其他形式。
3. 已有末端真实光线筛选继续保留；将轴上/中间/边缘至少 3 个视场作为新的显式采样协议候选。新协议独立版本化，旧记录的采样与身份保持。
4. 临时可修复候选与完整合格归档分开；RMS 只在通光条件明确后用于合格排序。

第二阶段验收：相同随机种子下改变目标视场，应能改变布局选择、修复路径或给出明确的不适配原因，而不再仅复制相同形状并在末端拒绝。

### 第三阶段：少量候选短程竞争，验证完整成功率

1. 对有限个通光候选分配相同的小额度原生优化，再按完整物理结果选优；优先恢复通光，其次像质，最后比较制造余量。
2. 在共享函数/光线/时间总额内对旧 v3 与新策略逐种子配对比较，报告完整验收成功率、通光、RMS/最大斑点、费用和失败原因。不能仅比较“一阶保留数”。
3. 课程式视场/口径扩展和更广的玻璃/功率搜索列为后续实验；最终始终回到原始规格和原独立验收。

本轮不改生产算法。下一轮应优先落实第一阶段和第二阶段的有限候选筛选，再依据同预算结果决定是否扩展搜索。
