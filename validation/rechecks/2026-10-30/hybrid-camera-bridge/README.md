# ImSym / Speos 融合：共同光谱探测器与 NSC—相机库接口

用户在 2026-10-30 明确要开发融合 ImSym 和 Speos 能力的软件。本轮把目标写入项目协作约定、[成像产品主线](../../../../docs/CAMERA_IMAGING_LAB.md#产品目标imsym-与-speos-能力融合)与[非序列路线图](../../../../docs/NONSEQUENTIAL_ZEMAX_PARITY_ROADMAP.md#与成像传感器共享的产品主线)，同时完成所有首版应用都可复用的一段 Core 连接。首个完整应用场景尚待用户优先级选择，相机贯通用例为建议。

## 已完成的库能力

- `SpectralDetectorPower` 冻结每个波长带、每个物理像元的功率，单位为 W/像元，含实际像元尺寸与显式行序。每带功率已积分，不能当 W/nm、辐照度、曝光量或归一化显示数组。数组/列表深复制并只读公开；沿用相机尺寸边界，波长带数最多 1024、像元×带数最多 8388608，超限在复制前拒绝。
- `NonSequentialCameraSensor.Capture` 只接收匹配矩形探测器的原始 `PowerByWavelength`、定义及波长快照，检查身份/尺寸/W 编号/总功率。不发起追迹，不读取显示颜色/归一化，不将波长表权重重复乘入已追迹功率。
- `SpectralDetectorSensor` 在正局部 Y 起始的相机栅格上选择 Bayer QE，将功率按曝光与实际光子能量变为电子数，再调用既有传感器噪声、满阱、ADC、去马赛克与 ISP。NSC 原始负 Y 起始数组显式翻转。原像元面积与光学损耗已进入功率，不再追加；旧人工满白辐照度和固定三波段 QE 不参与新功率输入。
- 两个既有相机公式入口仅共用相同的光子能量常数，原表达式顺序不变。真实光学追迹、制造/比较容差及冻结参考没有修改。

这段接口不携带复场/相干相位。相干路径必须在光学层先正确形成强度；不能用功率相加模拟干涉。蒙特卡洛光线估计误差也不等同于传感器的散粒噪声。

## 验证

最终定向 **44/44**，新增 `NonSequentialCameraSensorTests` **13** 项，原传感器、连续积分与光谱材质 **31** 项，零失败/跳过。新用例覆盖：

1. 四种 Bayer、两条光谱带的独立电子数公式及真实行序转换；曝光两倍、原人工辐照度/固定 QE 不误入新通路，波长表权重不重复计数。
2. 正式 NSC SourceRay 的 550 nm、1e-13 W 光线进入 4×4、3 µm 物理像元探测器，再计算 10 ms、总 QE 0.5 的电子数、RAW 与 ISP。中心落点对应输出绿色像元，功率守恒独立检查；这只是一个共享 Core 单光线连接控制，不是完整镜头/三维漫反射场景认证。
3. 不可变输入、确定性重复运算、空探测器的纯暗电流、像元功率不重复计面积，以及像元尺寸不符、错误身份/波长/总功率、缺失 QE、负值/NaN/Inf、工作上限和取消。

首轮新测试把 double 断言精度误写为 20，xUnit 编译检查拒绝，未进入测试。改为原定功率守恒相对误差检查后通过；原编译日志保留，不更改任何旧断言或光学门槛。最终默认 Release App 带完整依赖构建零警告、零错误，测试数不代表完整仓库或跨平台通过。

原 TRX、编译/构建日志与数值控制在[证据包](evidence.zip)，源文件/二进制与逐项结果身份见[机器账目](verification.json)。只读核验工具为 `tools/diagnostics/HybridCameraBridge20261030/verify_evidence.py`。

## 未完成与后续门槛

本次不是完整产品发布。库调用者必须提供同一不可变追迹会话的探测器/波长定义；应用层未来仍须核实场景哈希、修订、坐标和探测器几何。尚未接入相机桌面入口、统一工程的运行编排、三维场景渲染、正式 Lambertian/测量 BSDF 方向采样、鬼像/主成像的混合去重，以及设备实测/独立完整成像验收。

现有旧 Lambertian/BSDF 别名只扣减主光线能量，不生成散射方向；现有 2×2 填充因子空间权重退化也仍开放。本轮不把这些旧缺口算作已关闭，不以 44 项通过或光子数公式控制代替 Speos/ImSym 等效认证。未控制用户桌面、运行旧长任务、提交、推送或打包发布。
