# 普通 PNG 导出规格差异定位

日期：2026-10-30。用户要求先检查普通图片导出的差别与原因，暂不修改导出行为。本次使用普通分析和二维/三维布局的截取/保存方法，不调用 `ReportImageRenderer`、PDF 纸面模型或 PDF 写入器。

## 实测方法与范围

- 读取原高斯 28° 标准镜头，SHA-256 `f994005d633d4af742402469c9e4e2e0c289a57aed3ae876fb3231d1d3f95460`，前后哈希一致。五项实际分析结果各计算一次，随后冻结结果并用正常工作台控件呈现。
- 使用独立 Avalonia Headless/Skia 窗口，在 1000×800 与 600×600 两种尺寸、相同浅色主题和默认字体下，调用按钮使用的 `CapturePlotImage` / `CaptureViewerImage` 与 `SavePlotImage` / `SaveViewerImage`。未打开系统文件选择器或控制用户窗口。
- 共 7 类内容、14 组普通 PNG 样例；每组重复捕获尺寸一致。全体窗口 `RenderScaling = 1`，因此本表排除了不同系统缩放设置这一变量。
- 另对共享导出框传入 1.25 倍作参数探查；这不是 Windows 原生屏幕缩放切换测试。二维/三维探查包含临时页的像素对齐/布局取整，不将其输出简单当成原 PNG 宽高乘以 1.25。
- 本诊断没有改变产品代码；8 个普通 PNG 截取/共享外框/自适应布局文件与当前 HEAD 完全一致，哈希见 `source-check.json`。与此前报告快照对照时，13 个文件中 12 个一致，通用文案注册文件另有并行相机工作新增的注册行，已单列，未回退或当成本次导出修改。没有全仓测试、额外优化、OpticStudio 对比或桌面操作。检查程序首次构建出现跨 await 的 Span 编译错误，已在独立探针中修正；最终构建 0 警告、0 错误，运行完成，日志均保留。

## 原因

1. **两个入口取图范围不同。** 分析图取 `ResponsiveAnalysisPlotHost.Child.Bounds`，分析面板本身的 12 DIP 左右边距及工具/结果页签不进入图片；本例 1000 宽窗口对应 976 宽的分析内容。布局视图按实际场景宽高另组完整图签页，浮动工具不占同样的外侧空间，本例对应 1000 宽。共享外框再给两侧各加 1 DIP，所以得到 978 和 1002 两档宽度。
2. **完整内容可以超过屏幕可见区。** `ResponsiveAnalysisPlotHost` 取视口尺寸与内容最小可读尺寸的较大值。图例的最大预留宽度 240 DIP 加上两侧 12 DIP 被计入最小宽度；六幅光线像差图各有 200 DIP 最小边长，按完整图对重排。本例光线像差在宽窗口仍需要 839 高，窄窗口最小内容宽度达到 688，因此普通导出为 978×841 / 690×841，包含屏幕外内容，而不裁成视口。
3. **图签是最小高度，不是固定高度。** 共享图签最低 132 DIP，边框后常见 134 DIP；内容、文件名和字体可以继续撑高。可用宽度小于 600 DIP 时，图签由左右分栏变为上下堆叠。本例窄点列图的图签从 134 增到 296 DIP，MTF 增到 246 DIP；点列图窗口变小后，导出反而从 722 增高至 740 像素。窄布局窗口实际宽 600，不触发同一阈值，而分析内容宽 576，已触发堆叠。
4. **文件外框与内部坐标区也不是一回事。** 宽窗口中点列、MTF、场曲的 PNG 外尺寸同为 978×722，但点列各子图画布约 257×257，MTF 单画布为 718×580，场曲为两幅约 417×582。子图数、正方形约束和图例侧栏都会改变内部实际绘图区。
5. **系统缩放影响最终像素数。** `ExportImageFrame` 对已布局内容按 `ceil((逻辑尺寸 + 两侧边框) × RenderScaling)` 创建位图。普通 `bitmap.Save` 只编码该位图，不在保存阶段重新缩放。本次差异在同为 100% 时已经出现，主要原因是前三项屏幕布局差异。

## 结论与边界

普通导出目前实现的是“保留当前完整图面”，尺寸跟随屏幕布局，尚无统一输出画布、图签高度和文字规格。重复保存不是随机变尺寸；差异来自保存前的视口、自适应布局及内容测量。上述行为支持完整图面和可读性，但不能满足所有图片固定规格的要求。

本批只完成定位，不裁剪内容、不修改字体/子图或相机、不增加导出设置，也未覆盖任何桌面报告。后续规格调整应区分文件外框、内部子图尺寸与像素密度，保留完整数据和图签，不能只把所有结果强行拉伸到同一宽高。
