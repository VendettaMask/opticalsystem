# 精确平板生成：共享计算内核与 P2 完整目标流程

日期：2026-09-07。本阶段提供单一片数、初始目录玻璃及前表面光阑的生成引擎；新界面和多家族搜索仍属于 P3/P4。

## 所有光学计算共用正式 Core

`SpotMetricEvaluator.EvaluatePupilSamples` 为正式点列计算增加显式瞳孔采样入口，内部仍调用同一个 `SpotAnalysisEngine.Generate` 和 `SpotMetricEvaluator.Summarize`。折射、求交、材料色散、参考中心、RMS、最大半径及光线失效统计没有在实验室重新实现。返回数据包含类型化坐标量与单位；成像系统为 mm，无焦系统为 mrad。全失光返回缺失指标，不能用人造数值替代像质。

`Paraxial.EstimateOpticalPower` 直接返回正式系统矩阵的 `-C`，在平板零光焦度时仍为有限值。它与正式焦距计算使用相同的矩阵实现。已有点列接口及一般分析默认值未调整；公共点列路径现在明确剔除非有限截距／权重，并将它们计入失效样本。

P1 已迁移到上述接口，算法身份升为 `strict-flat-bootstrap/v2`。轴上截距仍采用绝对坐标、既有 17/49 条光线和不含表面透射损耗的几何权重；无有效光线时 RMS 为 null。光线计数现在只统计实际真实光线，近轴矩阵计算不再伪计为一次光线追迹。因此旧 v1 的光线计数不能直接当作 v2 计数；旧证明文件保留，不覆盖历史证据。原有测试中的解析与 Snell 参考代码只作测试校核。

## 单家族生成路径

公开入口为 `FlatStartDesignService.Solve(specification, elementCount, cancellationToken)`，结果契约为 `FlatStartDesignResult`，算法身份 `strict-flat-design/v1`。

1. 按预算从全部曲率严格为零的平板启动，保存根与首次弯曲过程。
2. 依次尝试“60% 入瞳／25% 半视场／主波长”“完整入瞳／50% 半视场／主波长”“完整入瞳／完整视场／主波长”“完整入瞳／完整视场／全部正权重波长”。轴上规格只请求轴上；单色规格省去重复多波长阶段。
3. 放大阶段若失光，有限次数二分难度增量并回到当前有效候选；未完成的目标阶段必须记录，最终请求仍使用完整用户目标。
4. 曲率、中心厚度、空气隙和自动后焦共同参与带尺度的阻尼最小二乘。固定后焦不进入变量向量，导出处方也标为固定。边界差分使用可行侧，非法几何和失光样本不产生虚假的导数。
5. 光学残差来自正式返回的光焦度、共同多色参考中心下的截距和最大光斑半径；实验室只组合目标误差、权重和缩放。中心厚度、边厚、空气边缘间距、后焦与总长作为硬界限。
6. 从新快照发起完整目标的加密正式分析，随后才决定候选状态。`CandidateSnapshot.Evaluation` 中 RMS 与最大光斑记录最差视场，完整报告另存所有视场及各波长通光数据。

入瞳始终由目标焦距/F/# 和当前阶段比例确定。净半口径沿用平板根的显式尺寸（目标入瞳半径乘规格裕量，至少 1 mm），搜索不放大它来隐藏失光。根中的材料、机械／净口径和视场定义在阶段切换时保持一致。

最终采样固定为归一化视场 `0、0.25、0.5、0.7、0.85、1`，每视场每波长为中心加 6 圈 × 16 方位，共 97 条等权瞳样本，包含边缘；只含轴上的规格不人为制造非零视场。所有正权重波长共用同一多色质心，波长权重仅应用一次。逐视场及逐波长检查通光；每个视场独立检查 RMS 和最大半径，不能用总体平均代替。

预算包含启动、差分探测、失败试步、阶段入口和最终加密请求。一次评价指一个候选在指定阶段的完整请求，真实光线数另计。P2 在请求前检查取消／时间；P1 保留迭代边界的时间检查，正式点列在波长批次之间响应取消。时间或评价预算不足以完成最终验证时，不发布达标候选。P2 尚无中途检查点恢复。

## 验证与证据

正式接口的一致性检查覆盖相同采样下的既有点列指标、共同多色质心与一次谱权重、全失光无指标、非法采样、无焦坐标单位、取消和零光焦度。实验室检查包括严格平板起点、完整目标逐视场验证、边缘失败不被轴上掩盖、厚度和固定后焦约束、预算、确定性及导出回读。

50 mm 单色与 75 mm 可见光样例的候选经正式 STAROPT 存储导出、回读，再直接调用正式 Core 核对每个加密视场的 RMS、最大半径和失光数。JSON 结果可完整回读，不改变快照及报告指纹。

机器可读结果见 [P2 单家族结果摘要](../labs/InitialStructure/benchmarks/flat-start-v1/design-results.json)。完整运行过程位于本地 `artifacts/validation/initial-structure-p2-20260907`；摘要记录其 SHA-256、规格指纹、实际数值与最终处方。

本轮最终验证：实验室全量 **63/63**，0 失败、0 跳过，约 2 分 59 秒；其中原有 42 项和新增 P2 21 项。正式点列、共用接口、批量追迹及数值修复定向回归 **46/46**，包含已提交 `123456.ZMX` 和 MS-L7 的捕获设置检查。正式与实验室两套解决方案分别在默认 Debug/Release 目录构建为 **0 警告、0 错误**。两套解决方案格式验证与差异检查均通过。日志为 `lab-full.trx`、`formal-shared-core.trx`；旧十个实验基准未改。

## 本阶段边界

12 个规格的单家族调查使用冻结的目标、容差及预算，不等于 P0 协议的 12 × 5 次多种子发布验收。单一家族未达标不代表不存在可行设计；之后需要比较玻璃分配、光阑位置和其他结构家族。不能为通过当前调查修改冻结目标或口径。

桌面当前仍运行旧版 v3 工作流。新 P2 引擎已可通过独立 Engine API 运行并通过既有 `CandidateExportService` 导出，但尚未接入新的按钮、进度和图形页面。没有新增安装包内容，也没有把实验室放入优化菜单。

本次没有对新生成处方执行 Zemax/SYNOPSYS 实机对照；共享内核的一致性不等于外部精度认证。正式已提交的 Zemax 基准及容差不变，正式全量测试基线也不因定向检查而改写。
