# 图像文件读取、源类型和 BMP 导出修复

日期：2026-10-16。范围为本机排查确认的三类文件链路问题，以及普通位图查看器中的同类读取错误；不修改 Core 光学算法。用户已确认未安装 OpticStudio，原生依赖按授权跳过，独立 Cooke/Tessar 调查继续排除。

## 已实现行为

- **读取流所有权**：尺寸检查使用 `SKManagedStream(..., disposeManagedStream: false)`；元数据 codec 释放其包装流，但不关闭随后真实解码所需的同一个受限文件流。图像模拟导入及普通位图查看器同步处理。源文件在成功、无效格式或资源拒绝后均释放；不重新打开文件来绕过原读取的大小检查。
- **源类型**：内置模式及未显式选择模式时使用产品默认内置目标，忽略设置中残留的外部路径，结果元数据的实际 `SourceFile` 为空。外部模式必须有有效文件；空白路径明确报错，丢失文件保留 `FileNotFoundException`，不静默回退到内置图。设置本身不删除路径，切回外部模式仍可继续使用。
- **BMP 编码**：不再请求 Skia 不支持的 BMP 编码器，而是在已有尺寸预算内写出标准 14 字节文件头、40 字节信息头、24 位无压缩 BI_RGB、BGR 字节序、四字节行对齐和自下向上的行。PNG/JPG/JPEG 保留原编码路径；三类格式均在完整编码后使用既有原子写入，失败不替换已有输出。

`显示为` 继续控制被导出的栅格，没有改成强制导出仿真图；Core 同时显示两幅图时的第一幅选择策略也未改动。PNG 的透明像素继续按黑底合成 RGB。图像单边/总像素、输入字节上限和查看器的独立显示上限不放宽。

## 回归范围

新增文件测试覆盖 PNG/JPG/JPEG/BMP 读取、真实运行时外部输入、内置模式残留有效/丢失路径、缺失外部输入、模式往返切换、透明度、真实 BMP 头/颜色/行方向/填充、PNG/JPEG/BMP 输出再读入、失败保留已有文件及文件句柄释放。

查看器回归运行正式窗口构造、文件生命周期和输入拒绝路径。普通相关进程保持既有 headless 占位渲染，并显式检查该宿主的 1×1 占位尺寸；独立进程设置测试专用 `OPTICALSYSTEMDESIGN_IMAGE_FILE_DECODE_TESTS=1`，启用真实 Skia/Avalonia 解码，严格检查原图 3×2 像素尺寸，并复核无效格式、超大元数据和文件字节预算。这不是原生桌面人工验收。
