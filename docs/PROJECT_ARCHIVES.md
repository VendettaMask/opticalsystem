# 工程归档

`.starpack` 将当前工程、所需输入、实验资料和选定结果保存为一个文件，用于分享、备份和跨机器恢复。日常工程保存使用 `.staropt`。

## 创建归档

在“文件 → 工程归档 → 创建归档”打开清单。清单捕获当前编辑状态，包含未保存的工程修改；创建归档不改变原工程的保存路径和脏状态。

- **设计归档**包含原生工程、已关联资料、分析窗口设置，以及已打开实验室的输入。
- **完整归档**再选择光线数据库、已有实验结果和计算记录。
- **添加文件**关联补充资料；**重新定位**为缺失输入选择新的源文件，保留它在归档中的逻辑路径。
- **刷新清单**重新捕获当前工程和实验状态。

归档始终带有完整原生工程，其中的多配置、评价函数、求解、材料/镀膜快照、非序列场景、散射表和网格沿用 STAROPT。主程序公差与优化编辑器保存定义和运行选项；分析参数和工作区布局保存为项目设置。初始结构还收集已打开的自主拓扑设计窗口。

四个实验室分别保存：

| 实验室 | 输入 | 可选记录和结果 |
| --- | --- | --- |
| AI 初始结构 | 当前规格、搜索选项、自主设计计划及其中的种子 | 形式搜索记录、自主记录、准备记录和报告 |
| 光学镀膜设计 | 膜系、材料、目标与计算设置 | 原生镀膜实验结果 |
| 相机成像仿真 | 当前传感器、ISP、光谱、场景等输入；外部图片随包收集 | 原生完整 A/B 实验、RAW/ISP 和采样记录 |
| 光学装调 | 仪器参数、测量方向与模式 | 已有共轭表和叉丝图像记录 |

资料收集、打包和恢复显示进度，可取消。完整分析会话的数据库在捕获时取得只读使用句柄，即使随后切换追迹会话，归档仍能读取捕获的数据库版本。恢复后重新追迹，再次创建归档时收集当前数据库。

## 恢复归档

在“恢复归档”中选择文件，或通过“打开”选择 `.starpack`。查看工程名称与资料清单，指定一个新的工程文件夹，然后点击“恢复归档”。

全部成员完成长度和 SHA-256 校验、原生工程验证后，恢复目录才发布。应用打开其中的 `main.staropt` 并恢复工作模式；所选光线数据库成为当前分析数据源。已有目标目录保留，恢复需使用新目录。

恢复后的清单提供“打开所选资料”，调用相应实验室或数据库查看器；文本、表格和图像可直接预览，PDF 使用系统阅读器。相机外部图片按新工程目录重新绑定。四个实验室的输入与记录均按其原有格式打开。

窗口布局默认保存在包中；勾选“恢复后应用窗口布局”或手动打开工作区资料时才应用。正常启动的编辑器与布局页策略沿用现行工作区规则。

恢复目录的 `.starpack-manifest.json` 记录资源清单。再次打开该目录中的 `main.staropt` 后，创建归档可继续收集已恢复的资料。该清单与资源文件随工程文件夹一起维护。

## 格式与实现

STARPACK v1 使用 ZIP64，成员由 `manifest.json` 和 `data/<SHA-256>` 数据项组成。清单记录工程名称、应用版本、时间、捕获修订、工作模式，以及各资源的用途、逻辑路径、长度、摘要和必需属性。内容相同的资源共享一个数据项，恢复时按逻辑路径分别写出。

原生工程和已经压缩的数据库/图片直接存放；JSON、CSV、TSV 和文本按需压缩。数据以 128 KiB 缓冲区流式复制，并在目标目录内暂存、完成后原子发布。大型输出通过共享 `BoundedFile.WriteStreamingAtomicAsync` 写入，常规文件接口保留既有大小约束。

默认最多 10,000 个逻辑文件、单文件 64 GiB、总展开数据 256 GiB；清单上限 8 MiB，ZIP 目录上限 32 MiB。STAROPT 和各实验格式继续执行自身的读取约束。逻辑路径采用相对路径，同时检查路径穿越、Windows 保留名、重复名称及跨平台同名冲突。

实现入口：Core 的 `ProjectArchiveStore`；Application 的 `IProjectArchiveService`；App 的 `ProjectArchiveWindow` 和实验资料适配器。归档不改变光学计算公式。

## 本轮功能验收

按用户要求，本轮验收检查打包、恢复、资料重开和界面操作，不运行 95 镜头完整精度矩阵。定向场景涵盖未保存修改、去重、原始输入删除后的恢复、临时数据库换会话、图片重新绑定、取消与旧文件保留、数据损坏、大小预算、已有目标目录，以及 ZIP64 的超过 4 GiB 偏移读取。离屏窗口按三种主题和 100%／150%／200% 显示倍率检查。
