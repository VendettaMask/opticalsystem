# Tolerancing

## Scope

The desktop tolerancing workspace follows the public Zemax workflow shape:

1. Generate tolerance operands with a wizard.
2. Review and edit the tolerance data table.
3. Validate operands.
4. Run two-sided sensitivity and seeded Monte Carlo analysis.
5. Review statistics, save the definition, or export a report.

It is a native managed-CPU implementation. The interface and operand names are familiar to Zemax users, but numerical equivalence with every Zemax tolerancing option and proprietary `.TOL` file compatibility are not claimed.

## Opening the workspace

Open the **Tolerance** Ribbon category and choose **Sensitivity** or **Monte Carlo**. Both commands focus the same tolerancing document because its editor, run settings, and results form one workflow.

The toolbar contains:

- **Tolerance Wizard**
- **Add**
- **Delete**
- **Validate**
- **Save Tolerance**
- **Load Tolerance**
- **Export Report**
- **Run Tolerance**

## Tolerance Wizard

The wizard accepts a start/end surface range and three generic manufacturing-grade presets:

- Commercial
- Precision
- High Precision

Preset values are editable before generation. They are convenience defaults, not vendor guarantees.

The wizard can generate:

| Code | Parameter | Unit |
| --- | --- | --- |
| `TRAD` | Surface radius | mm |
| `TTHI` | Thickness or air spacing | mm |
| `TSDX` | Surface X decenter | mm |
| `TSDY` | Surface Y decenter | mm |
| `TSTX` | Surface X tilt | degrees |
| `TSTY` | Surface Y tilt | degrees |
| `TIND` | Refractive index | dimensionless |
| `TABB` | Abbe number | dimensionless |
| `COMP` | Image-distance compensator | mm |

Plane surfaces are skipped for `TRAD`. Air and mirror transitions are skipped for `TIND` and `TABB`. The image-distance compensator varies the spacing immediately before the image surface, so it moves the image plane during tracing. Radius tolerance may be a fixed millimeter value or a percentage of each nominal radius.

`TCON` conic tolerance is supported by the editor and analysis engine but is added manually rather than generated by the current wizard.

## Tolerance data editor

Each row contains:

- enabled state;
- operand code;
- surface number;
- minimum and maximum deviation from nominal;
- statistical distribution;
- optional comment.

Select a row, edit its properties in the right-side panel, and choose **Apply to Current Row**. Validation rejects:

- missing surfaces;
- non-finite limits;
- minimum greater than maximum;
- zero-width active tolerances;
- duplicate type/surface pairs;
- negative physical thickness or image spacing;
- invalid refractive-index or Abbe-number ranges;
- an image compensator assigned to the image surface instead of its preceding spacing;
- a table with no active tolerance operand.

Compensator rows are control rows rather than sampled perturbations.

## Statistical distributions

Two distributions are available:

- **Normal**: the interval midpoint is the distribution mean and the minimum-to-maximum interval spans `6σ`. Samples outside the interval are rejected, so the limits do not acquire artificial probability mass.
- **Uniform**: samples cover the complete minimum-to-maximum interval.

A fixed random seed makes Monte Carlo results repeatable for the same optical system, operand table, and run settings.

## Evaluation criteria

The analysis can minimize either:

- field- and wavelength-weighted RMS spot radius in millimeters;
- field- and wavelength-weighted RMS wavefront error in waves.

Both criteria use the same Gaussian-quadrature merit-function definitions as the optimization workflow. The optimizer still minimizes a weighted sum of squared residuals internally, but reports and acceptance limits always use the physical criterion rather than that squared merit.

## Sensitivity analysis

For every active tolerance operand, the engine separately applies the minimum and maximum deviations. If compensation is enabled, the compensator is optimized at each endpoint. The result table reports:

- negative-limit criterion;
- positive-limit criterion;
- worst criterion;
- worst criterion change from nominal.

Rows are sorted by absolute worst change so the most influential tolerance appears first. The optical model is restored after every endpoint.

## Monte Carlo analysis

Each trial:

1. starts from an immutable snapshot of the nominal optical system;
2. samples every active tolerance operand;
3. evaluates the uncompensated physical criterion;
4. optionally optimizes active compensators;
5. records the compensated criterion and its change from nominal;
6. restores the nominal snapshot.

Run settings include trial count, random seed, compensation iteration count, and an optional physical-criterion pass/fail limit. Invalid trials, including trials with no valid evaluation rays, are reported as failed and count against yield.

The statistics tab reports:

- nominal;
- mean;
- standard deviation;
- minimum and maximum;
- P50, P90, and P95;
- estimated yield when a nonzero acceptance limit is supplied.

## Saving and reporting

**Save Tolerance** writes `*.startol.json`. The file contains the ordered operand table and run settings. **Load Tolerance** validates the document against the currently open optical system before replacing the table.

Tolerance definitions and results are deliberately separate from the `.staropt` optical project. Saving a project does not silently change or embed the active tolerance study.

**Export Report** writes a tab-separated text report containing the run summary, statistics, two-sided sensitivity table, and every Monte Carlo trial.

## Current limitations

- Zemax proprietary `.TOL` import/export is not implemented.
- The wizard does not yet create surface irregularity, fringe, asphere-coefficient, multi-configuration, or user-script tolerance operands.
- Compensation currently uses continuous image-distance refocus with LM/DLS; arbitrary multi-variable compensator groups can be added in the core but do not yet have a dedicated wizard.
- Element-level `TEDX/TEDY/TETX/TETY` rigid-body tolerances require explicit element grouping and are not yet implemented; the current decenter/tilt rows are surface-level `TSDX/TSDY/TSTX/TSTY`.
- Material tolerances use an Abbe approximation around the perturbed reference index/Abbe pair.
- Tolerance analysis is CPU-based and runs on a snapshot so it cannot modify the active prescription.

## Validation

The regression suite covers:

- wizard operand generation;
- validation;
- minimum/maximum endpoint sensitivity;
- restoration of perturbed variables;
- seeded Monte Carlo repeatability;
- compensator improvement;
- application cancellation during document switching;
- statistics and yield output.
