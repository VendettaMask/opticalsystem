## 1. 项目决策

实验室第一版选择“从平板生成 + 搜索数据闭环”，不先建设大规模镜头库，不先训练生成模型，也不先接入大语言模型智能体。

选择顺序如下：

1. 用确定性的物理模型证明平板结构能够演化为可追迹、可继续优化的候选结构。
2. 保存每次搜索的输入、种子、过程、失败原因和输出，形成具有来源信息的内部实验数据。
3. 数据量和质量达到门槛后，增加相似结构检索和候选排序模型。
4. 只有在前三项稳定后，才研究直接生成结构的模型和设计智能体。

这一决策的核心理由是：平板生成既是独立可用的实验能力，也能产生后续机器学习真正需要的数据。数据库或生成模型可以提高效率，但不能替代真实光线追迹、约束检查和数值验证。

## 2. “完全独立”的定义

实验室代码与正式产品共享经过验证的 Core 光学能力，但不进入正式产品的状态链、文档链和发布承诺。

必须遵守以下隔离规则：

1. 正式项目 `OptilandWorkbench.Core`、`OptilandWorkbench.Application` 和 `OptilandWorkbench.App` 不得引用实验室程序集。
2. 实验室引擎只能消费不可变 `OpticSnapshot`、材料目录快照和明确版本的计算接口，不能持有 `WorkbenchRuntime`、`WorkspaceCoordinator` 或主窗口状态。
3. 实验搜索不能原地修改当前打开的镜头。每个候选必须拥有独立快照、修订标识、随机种子和算法版本。
4. 实验室使用独立解决方案和构建入口；默认正式解决方案、安装包、自动更新和发布说明不包含实验室二进制。
5. 实验数据写入独立用户数据目录，不写入正式 STAROPT 工程，也不混入正式镜头库。
6. 候选结构只有在用户明确执行“导出为 STAROPT”后才能进入正式工作台；导入后按普通外部文档重新校验。
7. 实验功能不得注册为正式分析、正式优化器或兼容 API，不得改变现有默认值、缓存键、撤销历史和测试基线。
8. 后续若在主程序增加入口，只允许使用受开关控制的薄启动器启动独立实验程序，不建立正式程序集到实验算法的代码依赖。

建议的仓库布局为：

```text

  OptilandWorkbench.InitialStructureLab.slnx
  src/
    OptilandWorkbench.InitialStructure.Contracts/
    OptilandWorkbench.InitialStructure.Engine/
    OptilandWorkbench.InitialStructure.Persistence/
    OptilandWorkbench.InitialStructure.App/
  tests/
    OptilandWorkbench.InitialStructure.Tests/
  benchmarks/
    specs/
    accepted-baselines/
  schemas/
```

依赖方向固定为：

```text
InitialStructure.App
  -> InitialStructure.Engine
  -> InitialStructure.Persistence
  -> InitialStructure.Contracts
  -> OptilandWorkbench.Core

正式产品项目
  -X-> 任意 InitialStructure 实验室程序集
```

实验室如需 Core 当前没有的通用能力，应先提交独立的 Core 变更并完成正式测试和文档，不允许把实验语义偷偷放进 Core 公共 API。

## 3. 第一版范围

### 3.1 纳入范围

第一版只处理下列系统：

- 顺序模式、旋转对称、折射式成像系统；
- 固定焦距，不含变焦和多配置联动；
- 球面表面；
- 可见光波段；
- 默认无限远物体，可为后续有限共轭预留规范字段；
- 3 至 8 片镜片，每个片数作为独立候选家族搜索；
- 用户给定焦距、F/#、视场、波长、像面范围、总长和基本制造约束；
- 输出多个结构有差异且通过明确验收闸门的候选，而不是只输出单个最低 Merit 值结果。

“从平板开始”在数值上定义为：每片镜片由两个平面表面组成，初始曲率 `c = 1 / R = 0`，具有合法中心厚度、空气间隔、材料和光阑平面。算法使用曲率而不是以无穷大半径作为优化变量，避免在平面附近产生数值奇点。第一次搜索扰动可以弯曲表面，但运行记录必须保留精确平板根节点。

### 3.2 第一版输入

`InitialStructureSpecification` 至少包含：

- 共轭类型；
- 有效焦距或像方放大率目标；
- F/# 或入瞳直径；
- 视场定义及采样；
- 波长、权重和参考波长；
- 允许的镜片数量范围；
- 最大总长、最大口径和后焦距范围；
- 可用玻璃目录或受限玻璃集合；
- 中心厚度、边缘厚度和空气间隔下限；
- 畸变、远心性、相对照度等可选约束；
- 搜索预算、并行度、确定性随机种子和停止条件。

所有长度、角度和光谱字段必须使用结构化数量与单位，不允许解析显示文本来决定物理含义。

### 3.3 第一版输出

每个候选至少发布：

- 完整、独立且可校验的光学快照；
- 输入规范指纹、父候选、结构变异和优化阶段谱系；
- 算法名称、算法版本、随机种子、数值后端和运行环境；
- 一阶量、有效光线比例、RMS 光斑、波前、畸变和制造约束结果；
- 未满足约束、失败光线和数值异常的结构化诊断；
- 与其他候选的结构距离和所属候选家族；
- `Exploratory`、`TraceValid`、`Refinable` 或 `LabAccepted` 状态；
- 导出时使用的 STAROPT 格式版本和验证结果。

实验室只把 `LabAccepted` 解释为“达到当前实验基准中预先定义的初始结构门槛”，不得解释为已经完成设计、达到量产条件或优于商业软件。

### 3.4 明确不纳入第一版

- 非球面、自由曲面、衍射面、梯度折射率和反射系统；
- 变焦、多配置同步、折叠光路和偏心倾斜系统；
- 自动增加或删除镜片的无约束拓扑搜索；
- 镀膜、杂散光、热分析和完整公差闭环；
- 从互联网抓取或反推商业镜头处方；
- 依赖未注明来源的大规模镜头数据库；
- 直接生成最终量产处方；
- 大语言模型直接写入曲率、厚度或玻璃并绕过物理验证；
- 宣称与 CODE V、SYNOPSYS、Zemax 或 LensMind 数值等价。

## 4. 用户工作流

实验室程序第一版采用独立桌面窗口，工作流为：

1. 新建实验并填写结构化设计指标。
2. 选择片数范围、玻璃集合、搜索预算和确定性种子。
3. 运行规范预检查，显示互相冲突或缺失的约束。
4. 创建各片数对应的精确平板根结构。
5. 启动可取消的候选队列，实时显示阶段、有效候选数、淘汰原因和资源占用。
6. 使用表格比较候选指标，并在同一无框架视图区查看结构、光线和主要像差。
7. 固定候选、恢复检查点或提高指定候选的细化预算。
8. 明确选择候选并导出 STAROPT；导出前再次执行完整结构和追迹校验。

实验室关闭、崩溃或取消时不得影响正式工作台。中断恢复只读取实验室自己的检查点。

## 5. 规范架构

### 5.1 Contracts

`OptilandWorkbench.InitialStructure.Contracts` 只保存稳定、可序列化的实验契约：

- `InitialStructureSpecification`；
- `SearchBudget`；
- `SearchRunManifest`；
- `CandidateSnapshot`；
- `CandidateLineage`；
- `EvaluationVector`；
- `ConstraintViolation`；
- `SearchCheckpoint`；
- `AlgorithmIdentity`。

契约必须有显式 schema 版本。未知字段应可保留或明确拒绝，不能静默丢失影响结果的数据。

### 5.2 Engine

`OptilandWorkbench.InitialStructure.Engine` 负责：

- 规范归一化和可行性预检查；
- 平板模板构造；
- 候选种子和结构家族生成；
- 分阶段评价函数；
- 连续变量、离散玻璃和结构操作搜索；
- 候选去重、Pareto 排序和多样性保留；
- 检查点、取消、超时和资源预算；
- 最终物理与制造约束验证。

引擎不得依赖 Avalonia、主程序服务、Dock、显示名称或本地化字符串。

### 5.3 Persistence

当前原型使用独立目录中的原子 JSON manifest 和候选文件，已经与正式工程数据隔离。L3 计划迁移为版本化数据库，推荐 SQLite 保存索引和运行状态，候选光学快照使用内容寻址的压缩文件保存。无论采用哪种存储，必须记录：

- 数据来源和许可状态；
- 输入规范和规范指纹；
- 成功与失败候选；
- 算法版本及参数；
- 父子谱系和结构操作；
- 每阶段评价结果；
- 计算时间、光线数量和数值后端；
- 导出、删除和人工标记记录。

数据库不进入 Git。基准目录只提交人工审查过、许可明确、尺寸受控的规范和结果摘要。

### 5.4 App

实验室 App 只负责编辑规范、调度运行、查看候选、比较结果和导出。计算状态通过只读事件或消息 DTO 发布；UI 不直接修改引擎内部候选。

窄窗口、键盘导航、屏幕阅读器名称、进度公告、取消操作和长表格虚拟化从第一版纳入验收，不复制正式 App 已经修正过的可访问性问题。

## 6. 平板到初始结构算法

### 6.1 阶段 0：规范预检查

在启动昂贵搜索前完成：

- 单位和范围检查；
- 焦距、F/#、视场、像面和总长的基本一致性检查；
- 给定玻璃集合的波长覆盖检查；
- 片数、厚度、口径和空气间隔是否存在明显矛盾；
- 计算预算能否覆盖最低种群和细化轮数。

预检查只能报告明确可证明的冲突。不能因为经验规则不理想就错误宣布物理上无解。

### 6.2 阶段 1：精确平板根结构

对每个允许片数建立独立根结构：

- 每个折射面曲率为零；
- 中心厚度和空气间隔满足硬下限；
- 光阑位置覆盖前部、中部和后部等离散变体；
- 材料从受限集合或玻璃类别代表中选择；
- 像面位置由规范给定的长度包络初始化。

根结构必须能够序列化、重新加载并得到相同指纹。它不需要成像，但必须是结构合法的光学模型。

### 6.3 阶段 2：一阶可行性展开

从平面附近使用曲率变量产生小扰动，并优先优化：

- 总光焦度及符号；
- 有效焦距；
- 后焦距和总长；
- 光阑与主光线基本行为；
- 表面曲率和厚度边界。

候选首先通过近轴模型快速筛选。近轴通过只代表值得进入真实光线阶段，不能直接标记为有效初始结构。

### 6.4 阶段 3：真实光线可达性

逐步增加视场、波长和光瞳采样，淘汰：

- 无法到达像面的候选；
- 非预期全反射或大量渐晕候选；
- NaN、无穷值和几何相交候选；
- 中心厚度、边厚、空气间隔或口径非法候选；
- 依靠极端曲率或长度欺骗一阶目标的候选。

采样密度采用课程式递增，低成本筛选和最终验证必须使用不同的请求标识，不能把低密度结果冒充最终结果。

### 6.5 阶段 4：像质细化

通过真实光线的候选再逐步加入：

- 多视场、多波长 RMS 光斑；
- 波前 RMS；
- 畸变；
- 横向色差和轴向色差；
- 相对照度；
- 远心性或主光线角度；
- 用户明确启用的附加评价项。

约束采用分层和字典序闸门：先满足结构与一阶硬约束，再比较像质，不允许一个很小的加权总分掩盖严重的单项失败。每版评价规则必须拥有独立版本号。

### 6.6 阶段 5：玻璃和制造性

连续变量稳定后，再在受限玻璃集合中执行离散邻域搜索：

- 以折射率、阿贝数、部分色散和可用性建立候选邻域；
- 每次换玻璃后重新执行焦距恢复和真实光线细化；
- 记录材料目录版本，不把材料显示名称作为唯一身份；
- 检查中心厚度、边厚、曲率、口径、空气间隔和基本装配包络。

第一版只提供初始制造性筛选，不把它描述为完整公差或量产验证。

### 6.7 阶段 6：多样性保留

最终结果不能只是同一局部极小值的数值抖动。候选指纹至少考虑：

- 镜片数量和光阑区间；
- 各镜片光焦度符号序列；
- 胶合与空气分隔模式；
- 归一化曲率、厚度和空气间隔；
- 玻璃类别序列；
- 一阶量和主要像差向量。

当前算法版本 2 已实现第一步可用的家族内代表排序：先按现有标量质量分数排序，再在质量前 64 个候选中按曲率、厚度和半口径的归一化光学距离贪心选取最多 8 个代表，其余候选完整保留在代表之后。真正基于多个独立目标的 Pareto 前沿、聚类半径标定和 UI 家族解释仍是计划项，不能把当前代表排序称作 Pareto 优化。

## 7. 搜索策略

第一版采用 CPU 并行，不把 GPU 作为可用性的前置条件。当前 L3 已实现确定性多种子并行、一阶焦距恢复、低密度真实光线筛选、有界差分进化，以及预算允许时基于有限差分 Jacobian 和阻尼正规方程的局部细化。最终候选使用独立的 density-4 请求重算并通过结构化硬约束，低密度搜索分数不能直接产生 `LabAccepted`。只有性能剖析证明光线计算或目标评价是主要瓶颈后才评估 GPU 后端。

当前组合与后续边界为：

1. 当前使用确定性一阶光焦度分配和有界种群扰动；Sobol 或拉丁超立方仍是候选改进。
2. 当前独立实现的有界差分进化负责跨盆地连续搜索；CMA-ES 尚未实现。
3. 当前在预算足够时执行阻尼最小二乘局部细化；更完整的多残差信赖域仍是候选改进。
4. 玻璃选择使用有限邻域搜索，不把离散材料编号当作连续变量。
5. 片数、光阑区间和胶合模式作为候选家族，不在第一版连续优化循环中任意增删表面。

现有正式优化器可以作为对照或局部工具，但实验室不能仅复用不同名称指向同一简化随机扰动实现。每个公开算法名必须对应可测试的算法行为、停止条件和确定性规则。

默认规模目标为 64 至 256 个并行或分批种子，但实际数量由搜索预算和基准测量决定，不作为固定产品承诺。

## 8. 数据闭环与 AI 路线

### 8.1 第一阶段：只积累可信数据

第一阶段不训练模型。每次运行同时保存成功和失败路径，因为失败边界对于预测候选是否值得继续计算同样重要。

数据必须满足：

- 来源明确；
- 输入和算法可重放；
- 指标由同一版本的规范计算链产生；
- 失败不是空值，而是结构化原因；
- 不包含未经许可的商业镜头处方；
- 版本升级后可以识别旧指标，不能混为同一标签。

### 8.2 第二阶段：检索与缩放

数据库积累到足以覆盖多种规格后，先实现：

- 规范特征和结构指纹检索；
- 近似结构的无量纲缩放；
- 检索候选与平板候选共同进入统一验证；
- 检索来源、距离和缩放操作可追溯。

检索结果不能绕过平板候选，也不能因来源是历史成功案例就自动获得更高状态。

### 8.3 第三阶段：候选排序模型

第一个机器学习模型只做低风险决策：

- 预测候选进入下一阶段的成功概率；
- 预测计算成本和常见失败类型；
- 推荐搜索预算、玻璃邻域和局部优化顺序；
- 对候选排序，但不直接发布处方。

必须保留随机探索比例，避免模型只重复历史结构。模型版本、训练数据清单、特征版本和验证集结果必须进入运行来源信息。

### 8.4 第四阶段：条件生成模型

只有在内部数据覆盖、许可、去重和独立验证达到门槛后，才研究由设计指标生成候选拓扑和初始处方。生成结果与平板和检索结果使用完全相同的物理验证，不为 AI 单设宽松标准。

### 8.5 最后阶段：设计智能体

智能体只能调用结构化工具，例如：

- 新建候选家族；
- 分裂或合并光焦度；
- 移动光阑；
- 扩展玻璃邻域；
- 增加某阶段预算；
- 请求正式分析；
- 比较和解释候选。

智能体不得直接改写运行中候选的内部对象，不得依据显示标题选择分析，也不得把自然语言判断当作数值验收。

## 9. 运行记录与可复现性

每次搜索必须产生不可变 `SearchRunManifest`，至少记录：

- 规范内容和指纹；
- 精确平板根结构指纹；
- 随机数算法和种子；
- 算法及评价函数版本；
- Core 提交版本和数值后端；
- 材料目录版本；
- 并行度、时间、评价次数和光线数量预算；
- 检查点链；
- 最终候选和淘汰摘要；
- 异常、取消和资源耗尽状态。

当前运行 ID 由 UTC 毫秒时间、规格指纹和随机熵组成。持久化先在运行根目录内构建隐藏暂存树，候选和清单全部刷新成功且未取消后才通过目录重命名发布；已存在的运行目录不可覆盖。读取时重新验证 manifest 状态、版本、算法身份、诊断上限、候选文件精确集合、规范化 SHA-256、光学快照、评价和谱系；仅大小写不同的候选 ID 会被拒绝。原子检查点保存已完成种子索引、种子候选、诊断和算法身份，恢复结果与不中断运行的候选指纹及排序一致；损坏 JSON 会作为明确的无效数据错误返回，App 不会把它当作可恢复运行。当前不序列化差分进化种群，细化中断从 `refinement-ready` 检查点重跑确定性细化。SQLite 检查点索引和更细粒度种群恢复仍属于后续阶段。

相同版本、相同输入、相同种子和相同确定性配置必须得到相同的候选指纹及排序。非确定性加速模式必须显式标记，不能覆盖确定性基准。

## 10. 验证体系

### 10.1 单元测试

- 精确平板模板及曲率零点；
- 规范归一化和单位；
- 随机序列重放；
- 变量边界和修复策略；
- 候选克隆与快照隔离；
- 结构指纹和去重；
- Pareto 排序与多样性选择；
- 检查点往返；
- 失败诊断和取消传播。

### 10.2 集成测试

- 从规范到候选的最小完整运行；
- 每个候选使用正式 Core 追迹器重新验证；
- 并行运行不共享可变 `Optic` 或追迹缓存绑定；
- 导出 STAROPT 后重新载入，结构和关键指标一致；
- 取消、超时和异常不会发布半写入候选；
- 实验运行不改变当前正式工作区、撤销历史或文档修订号。

### 10.3 基准集

基准规范使用自建合成规格、许可明确的公开示例和可审查数据，不直接提交商业软件私有处方。每个规范在搜索前固定：

- 输入规格；
- 资源预算；
- 必须满足的硬约束；
- 初始结构质量门槛；
- 至少需要的结构家族数量；
- 允许的数值容差；
- 失败时应发布的诊断。

当前提交了 10 个自建合成规格和 `flat-to-usable-hybrid/v1` 的最低结果摘要。2026-08-30 定向重放中，01、02、04、05、06、07、08、10 各产生 3 个不同片数/光阑验收家族，03 和 09 各产生 2 个，因此为 `8/10`，达到 L3 的 80% 门槛。摘要只冻结最低家族数，允许后续算法改善；不得静默降低最低值掩盖回归。

Zemax 2026 R1 的 `123456.ZMX` 基线继续只承担已捕获文件、设置和版本范围内的精度验证，不扩展为智能初始结构搜索基准。Optiland 0.5.8 的已有 Cooke/Tessar 数据仅在 validation/history 作为冻结辅助历史回归，不再新增对照，不能作为生成能力结论。

### 10.4 性能测试

性能报告至少分开统计：

- 根结构与种子生成；
- 近轴评价；
- 真实光线评价；
- 玻璃离散搜索；
- 持久化和 UI 映射；
- 总墙钟时间、CPU 时间、峰值内存和候选吞吐量。

不得只报告探索候选数量；无效候选比例、通过各闸门的比例和最终结构多样性同样是必要指标。

## 11. 实验室验收闸门

### L0：设计冻结

- 本文、schema 草案、依赖规则和基准来源规则完成评审。
- 明确第一批 3 个合成规范和每个规范的验收阈值。
- 尚无正式产品入口。

### L1：隔离骨架

- 状态：已完成（2026-08-25）。
- 独立解决方案、项目、测试和数据目录建立。
- 架构测试证明正式程序集不引用实验室程序集。
- 一个平板根结构可以保存、重新载入和重复追迹。

### L2：可行性原型

- 状态：已形成首个可重放原型（2026-08-25），后续仍需扩大规格覆盖。
- 至少一个 3 片系统从精确平板根节点进入真实光线可达状态。
- 运行可取消、可重放、有完整谱系和失败诊断。
- 结果不写入正式工作区。

### L3：实验室 V1 引擎

- 状态：门槛已完成（2026-08-30）。
- 覆盖 3 至 8 片的固定焦距球面系统。
- 基准集不少于 10 个预先冻结的规格。
- 在各自固定预算内，至少 80% 的基准规格产生不少于 3 个结构家族的 `LabAccepted` 候选。
- 所有接受阈值按基准逐项定义，不使用一个宽松总分替代硬约束。
- 相同确定性配置重复运行的候选指纹和排序一致。

当前实测为 `8/10` 规格达到三个 `LabAccepted` 家族，两个规格达到两个；冻结输入、固定预算和最低结果位于 `labs/InitialStructure/benchmarks`。这完成 L3 门槛，但不代表离散玻璃、完整制造性、光学距离聚类或商业软件数值等价已经实现。

80% 是实验室阶段门槛，不是对任意用户规格的成功率承诺。达不到时保留真实结果并分析失败，不得修改基准输入来制造通过。

### L4：独立实验室 UI

- 状态：核心工作流已完成（2026-08-30），跨平台人工 UI 验收待完成。
- 规范编辑、预检查、运行队列、取消、检查点、比较和导出完整可用。
- 窄窗口、键盘导航和辅助技术通过定向测试。
- 关闭或崩溃不影响正式工作台。

当前 App 已实现结构化规格、显式预检查、单运行候选队列、取消/种子检查点恢复、A/B 指标与剖面比较，以及 STAROPT 原子导出后回读快照验证。源级定向测试锁定 820 px 响应式断点和自动化名称；macOS 宽窗口截图无重叠。由于未打包 Avalonia 进程没有被本机 Computer Use 可访问性驱动发现，不能把窄窗口、键盘和读屏器实机结果写成已通过，L4 的跨平台人工验收仍保留。

### L5：可选产品启动入口

- 只有 L3 和 L4 稳定后，才评审“实验室 > 智能初始结构（实验）”入口。
- 入口默认关闭，只启动独立程序，不把实验程序集链接进正式运行时。
- 正式安装包是否包含实验程序由发布配置明确决定。

### L6：数据辅助

- 检索、排序模型或生成模型分别通过离线消融测试。
- 必须证明相对于相同预算的纯物理搜索有可重复收益。
- 任何模型关闭后，平板生成与完整验证仍可独立工作。

## 13. 主要风险与控制

| 风险 | 表现 | 控制措施 |
| --- | --- | --- |
| 平板退化 | 所有面初始无光焦度，传统半径参数在无穷点不稳定 | 使用曲率零点、分阶段小扰动和一阶光焦度展开 |
| 组合爆炸 | 片数、光阑、玻璃和曲率形成巨大空间 | 片数分家族、玻璃延后、逐级提高真实光线成本 |
| 评价函数投机 | 很低总分但厚度、光线或局部视场非法 | 硬约束闸门、分层目标、最终独立重算 |
| 重复候选 | 输出大量相同局部极小值 | 结构指纹、聚类、Pareto 排序和家族配额 |
| 并行污染 | 候选共享可变镜头、缓存或随机数 | 每候选不可变快照、精确缓存身份、分流随机序列 |
| 搜索过慢 | 高密度真实光线过早进入大种群 | 课程采样、批量评价、性能剖析后再决定 GPU |
| 玻璃离散不稳定 | 把玻璃编号连续化导致无意义搜索 | 物性邻域、换玻璃后恢复优化、目录版本化 |
| 数据质量不足 | 模型学习到旧算法偏差或重复结构 | 保存失败、版本标签、去重、时间切分验证和消融测试 |
| 来源与版权 | 商业镜头被抓取、反推或无许可训练 | 来源字段必填、白名单导入、禁止反推处方 |
| 实验污染产品 | 实验状态改变正式文档或发布承诺 | 独立进程、独立数据、显式导出、默认不打包 |
| 用户过度信任 | 把初始结构误认为量产设计 | 状态分级、失败项可见、禁止“完成设计”措辞 |

## 16. 完成定义

该功能只有同时满足以下条件，才可称为“实验室 V1 已完成”：

- 独立代码、测试、文档和运行数据契约一致；
- 从精确平板根结构开始的谱系可审计；
- 候选由正式 Core 真实光线重新验证；
- 基准集达到 L3 门槛并公开失败项；
- 确定性重放、取消、检查点和快照隔离通过测试；
- 实验运行不会修改正式工作区；
- 导出结果重新载入后仍通过同一验证；
- 文档明确区分已实现、实验结果和后续计划。

在这些条件达到前，任何原型只能称为“探索性实验”，不能称为可用的智能初始结构功能。
