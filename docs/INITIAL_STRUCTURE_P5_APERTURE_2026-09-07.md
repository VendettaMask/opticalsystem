# P5 续项：孔径恢复与多色继续优化

本记录继续 [平板生成计划](INITIAL_STRUCTURE_FROM_FLAT_PROPOSAL.md) 的 P5；[首轮 v2 结果](INITIAL_STRUCTURE_P5_2026-09-07.md)及其 60 次原始摘要保持冻结。本轮不提交或推送。

## 已复现的原因

1. 单个视场丢失一条光线后，旧搜索把该视场所有坐标残差替换为常数，并拒绝对该状态求导。它无法利用连续的光学变化恢复通光。
2. 搜索的可行性及候选保留隐含要求 100% 通光，而冻结规格明确要求逐视场、逐波长至少 98%。09 的诊断中，较低残差的步骤被保留逻辑丢弃，追加评价重复从同一个旧候选开始。修复统一使用规格原有门槛；最终验收的通光、像质、焦距及采样要求全部不变。

## 计算与依赖边界

- Core 新增显式 `SequentialRayTracer.DiagnoseCircularApertures` 和 `SampledApertureDiagnostics.Evaluate`。利用已有的光线生成、表面相交、材料和折射/反射、像方坐标、光谱权重、共同质心及光斑统计，报告每条光线的最小圆孔径余量（mm）、限制表面和未截光诊断坐标。
- 正式普通追迹、缓存、物理孔径、分析默认值均不改变。诊断既不记录表面数据，也不读取/写入普通追迹缓存，不修改传入 Optic。非圆形物理孔径显式报不支持；找不到交点等传播失败不生成替代光线。
- 实验室在真实追迹有丢光时才额外请求诊断。诊断用于连续搜索残差，不能给出通光或候选验收结论。额外诊断光线计入实际追迹成本，最终表格与门槛仍来自独立的真实截光评价。
- 依赖仍为实验室 Engine → 正式 Core。没有 src → 实验室、验证资料或外部运行时的反向依赖；没有新增实验室光学公式。
- 孔径修复阶段使用 v3；当前搜索、设计、独立精修已升级为下文的 v4。v1/v2/v3 检查点可读、可导出、可作为独立 v4 精修的来源，不能直接续跑并冒充原算法。新增诊断能力字段在默认值时省略，保留旧检查点校验和序列化兼容性。

## v4 阶段顺序验证

保留的 v4 修改仅在有多个有效波长时改变根家族的继续优化顺序：初始平板聚焦之后，以全孔径、全部有效波长在 25%、50%、100% 视场三个阶段推进。单色阶段顺序不变，已有完整候选仍直接进入完整密集目标精修。该顺序使色差优化早于大视场单色像质优化，并减少较高维问题在过多阶段之间分摊评价预算。

目标加权、候选排序和交替精修的试验未改善定向结果，已全部撤回；不在当前算法中保留这些开关或适配器。正式 Core 计算及 v3 孔径诊断未再次改变。

## v5 最大半径权重调查（已撤回）

v4 的最大半径超限残差与 RMS 坐标残差存在权衡：接近门槛时，最大半径的归一化超限平方很小，搜索可能保留 RMS 更低但边缘仍超限的候选。曾调查全阶段或仅密集阶段将这一搜索残差乘以 4，未改变最终门槛。对 v4 的 12/104 候选追加 250 次评价能够达标，但这不属于原 10,000 次预算；重新从平板开始的 12/104、12/105 调查仍失败，不能将追加预算的结果计入原协议。

2026-09-08 用户明确纠正工作方式后，已停止此调查并撤回全部 v5 源码和算法身份。当前恢复到 v4 对照，完整 v5 工程/60 次验证未执行。后续按[自动搜索策略整改](INITIAL_STRUCTURE_SEARCH_STRATEGY_2026-09-08.md)先实现通用求解器与自动调度，停止用完整验收集作为人工调权重的内循环。
