# 初始结构实验室：宽视场失败路径与搜索预算复核

2026-09-27 当前验证：正式 Core 已修复采样点斑、汇总点斑、自动口径及口径诊断遗漏光线瞄准设置的问题，并统一瞄准目标与发射坐标的渐晕比例。正式相关定向 **90/90**（71+19，无重叠）、实验室完整 Release **247/247** 通过；默认主程序及实验室 Debug/Release 构建零警告、零错误。实验室搜索策略仍为 v16，生成时仍关闭瞄准，独立物理光阑尚未闭环；30 个原候选的追加复核发现畸变、物理光阑及分支覆盖仍有缺口。正式全量 **1311/1311**、比较工具 **104/104** 仍为历史记录，本轮未重跑；没有新的 Zemax 外部对照或并行主界面功能验收。见 [文献、实测与剩余问题](INITIAL_STRUCTURE_LITERATURE_AUDIT_2026-09-27.md)。下文更早验证保留历史范围。

本文保留 v15 的实现、实验与 242 项测试基线。v16 入口修复阶段 的后续细化入口修复、同预算结果及 247 项回归见 [细化入口复核](INITIAL_STRUCTURE_JOINT_RESTART_2026-09-27.md)；这里的原始数据不改写。

v15 阶段保留连续光线域内的几何/像质联合求解与不完整像质显示修正。相同 50000 次评价的宽视场搜索，最好最差视场 RMS 从 161.145 降至 **134.444 μm**，改善约 16.6%，仍不满足 50 μm 门槛。**能完整追迹、目标函数下降和最终像质达标是三个不同结果。** 曲率退回方案因完整搜索退步而撤回；默认 QUICK 模式保留。

## 已确认的显示问题

面积策略下，自动口径要求全部指定光线完成传播后才应用包络。失败时，旧口径可能只让少量光线到达像面；这些存活光线仍可形成很小的诊断光斑。原界面直接显示该 RMS，且只按 `.rms` / `.maximum-radius` 违反项判断对应行是否“满足”，因此可能在追迹失败的方案上显示很好的像质数字。

`CandidateRow` 现在读取正式评价的 `HasContinuousSearchResiduals`：不完整面积评价在候选与目标栏显示“光线不完整”，RMS 和最大半径目标显示“无法判定”。逐视场原始值保留并标为“诊断”，详情解释其局限。完整评价和历史离散采样保留原来的含义。候选验收、Core 计算和导出数据没有因显示修正而放宽。

## 文献与实现之间的差距

Yang、Fu、Heidrich 的课程学习工作采用逐步扩大视场、口径，并结合几何正则化；其对象包含高阶非球面及可微追迹，不能把论文像质直接当作本项目球面、单波长试验的预期成绩。[Nature Communications 2024](https://www.nature.com/articles/s41467-024-50835-7)

SYNOPSYS 官方第 41 课明确讨论宽角起始系统无法通光的问题：先构造能追迹、降低出射角的前组，再继续设计；该示例还关闭 QUICK，对各候选做完整优化，并在后续检查真实光阑的填充。它的 92.4° 半视场、塑料非球面系统与本次 40° 球面任务并不等同，但提示了应分别验证前组形态、根优化预算和瞳孔处理，而不是仅改变一个优化开关。[OSD：Designing a very wide-angle lens，第 1–3 页](https://osdoptics.com/wp-content/uploads/2020/05/41_designing_a_very_wide-angle_lens.pdf)

## 被否决的曲率退回方案

冻结 v14 宽视场 QUICK 的 24 个根、每根 260 次预算。其中 11 个根最终没有连续完整光线，8 个属于六至八片结构。许多入口从 `(0.65 pupil, 0.5 field)` 跳至完整目标后，局部求解器返回 `InvalidInitialEvaluation`。此时已经缺少求导所需的光线，不能用小的残存光斑判断候选好坏。

对这 11 个入口，先做中间阶段二分，再比较曲率同比退回；每种方法都分别使用原来的几何阶段和直接联合阶段，合计各 22 项。二分中间阶段恢复完整目标为 **0/22**，曲率退回为 **22/22**。这些只是诊断对照，完全调用正式 Core；没有外推光线、补写缺失像面坐标或改变目标。

将曲率退回接入完整搜索后，10000 次宽视场评价的连续根从 13/24 增至 24/24，物理可行根从 13/24 增至 21/24，但最好 RMS 没有改善。50000 次同预算对照则出现退步：最好的最差视场 RMS 从 **161.145 μm** 增至 **230.469 μm**，两者都不达标。搜索把更多工作花在恢复及质量很差的新分支上。因此该方案已从产品路径撤回，不能以通光数量增加作为上线依据。

实验补丁保存在 [rejected-recovery.patch](../labs/InitialStructure/benchmarks/stage-recovery-20260927/rejected-recovery.patch)，只用于复现这项被否决的实验，不表示已实现的产品功能。试验检查点内的临时版本号也不构成发布版本。

## v15 保留的求解修正

v14 的 V2 残差已包含正式 Core 返回的几何约束，也允许求导探针在有限几何边界两侧取样。但局部求解入口仍只看 `GeometryFeasible`：只要越界，就改为只优化几何。部分六至七片入口在这个阶段耗掉一个差分模型窗口，后续实光线阶段连一个完整 Jacobian 都来不及构造。

v15 在 V2 且 `HasContinuousSearchResiduals` 为真时，直接使用包含几何约束的实光线联合目标。几何恢复仍用于无法提供完整光学数据的几何越界入口；历史目标保持原阶段选择。缺失光线仍不能参与光学求导，0.5 mm 边厚、最终通光和像质门槛均未改变。求解仍使用 v14 的受保护 Broyden、QR 阻尼和实际下降检查；没有引入第二套光学计算。

五个冻结入口各用 90 次局部评价比较：四个同阶段目标值优于原阶段切换，一个退步；它并不是普遍更优的局部路径。是否保留以完整搜索为准，而不是仅以几何修复次数或局部目标下降为准。

| 同一任务与预算 | v14 原路径 | v15 联合入口 | 保留达标记录 |
| --- | ---: | ---: | --- |
| F/8、20°，10000 次，QUICK | 39.208 μm | 39.208 μm | 两者均 10/10，均覆盖六个根分支 |
| F/2.8、40°，10000 次，QUICK | 285.610 μm | 285.610 μm | 两者均 0/10 |
| F/2.8、40°，50000 次，QUICK | 161.145 μm | 134.444 μm | 两者均 0/10 |

表中为保留处方中最小的“最差视场 RMS”，不是所有候选的平均值。相同种子为 101，焦距 50 mm，单波长 587.6 nm，目标 RMS 50 μm、最大半径 150 μm；40° 是本任务的最大半视场。大预算最佳 v15 处方为五片，EFL 49.8663 mm、F/# 2.79251、最大半径 301.237 μm。焦距与 F/# 已满足，本次仍因光斑大小失败。

v15 没有解决高片数根的整体失败：宽视场 QUICK 的连续根仍为 13/24，物理可行根从 13/24 变为 12/24。50000 次搜索中六片仍未分到邻域操作。不能用最佳五片候选改善掩盖这项局部退步。

## 单独增加根预算也不够

另以冻结 v14 DLL、相同 50000 次评价运行本项目 FULL 模式，每根上限从 260 增至 1200。最好结果为八片、最差视场 RMS **203.049 μm**，EFL 47.0686 mm，仍失败；连续根只有 4/24。更长的既有路径可能把结构推入不能完整追迹的区域。本次因此没有把默认模式改成 FULL。本项目的 QUICK/FULL 是已记录的根预算/筛选策略，不能等同于复现了 SYNOPSYS 的第三/五阶筛选或 PSD。

下一项优先工作是以正式 Core 验证专门的宽角前组起点与逐步扩展策略，并比较高片数根获得有效优化窗口后的完整像质。还需解决真实瞳孔、结构族覆盖和多波长验证；这些均为后续工作，不是本次已实现能力。

## 重算与工程验证

最终 v15 的 30 个保留记录均通过新建 Core 快照重算及 STAROPT 导出回读，处方指纹和已发布评价完全一致。另用 41 个视场、16×48 面积积分点及 72 个边缘点加密检查，无丢光线。10000 次宽视场中一个本就失败的记录 RMS 增加约 1.077 μm；50000 次 v15 的 RMS 最大变化约 3.2×10⁻¹⁵ mm，最大半径变化最多约 0.480 μm。达标与不达标结论未因此改变，不能把所有宽角结果称为全面收敛。

包括被否决方案及 FULL 诊断，本轮共运行七次完整搜索，并重算/导出核对 70 个保留记录；它们不是 70 个独立成功设计。未完成 v15 的 60+15 多种子验收协议。

2026-09-27 最终实验室完整 Release 回归 **242/242**，无失败或跳过；默认 Debug/Release 构建、格式和差异检查结果记录在 [verification.json](../labs/InitialStructure/benchmarks/stage-recovery-20260927/verification.json)。正式 Core 源码及默认 Debug/Release 二进制与前轮一致。本轮没有修改正式主程序，但工作区存在并行的 Ribbon/主题界面及相应正式测试改动，主程序二进制也已改变；这些不在本轮验证范围。正式 **1311/1311** 与比较工具 **104/104** 仅引用已有完整记录，不能用于认证这些并行改动，本轮未重跑，也没有把实验室测试计入正式数量。早期夹具枚举读取错误及被替代实现的检查记录保留于原始日志，最终结果单独列出。

检查点版本为 15，面积策略仍用调度策略 2。v1–v4、v6–v14 可读、可导出，并可成为独立追加细化的来源，不能静默用 v15 续跑。历史 v10 的 43/60、30 次成功及未运行留出集保持其原有范围。
