## Implementation contract

- Reference checkout: `https://github.com/WenguanZhang/HappyLens`, commit `8456f7d9e1fb3264f86b05a4ca43c29173e059ea`, Apache-2.0. The downloaded Python project and its isolated runtime remain research tools outside the product. No Python service, interchange or second tracing engine enters the application.
- New generation is an explicit versioned preparation option. Null preserves existing template preparation, plan fingerprints and historical checkpoints. The descriptor declares supported individual singlets, surface families, material choices and stop interval; unsupported cemented groups are rejected rather than represented as separated singlets.
- Delano ray-height/invariant reconstruction belongs in shared Core and provides proposals only. Physical realization, first-order polishing, manufacturing geometry and all final optical checks use existing Core. A first-order proposal never counts as a qualified prescription.
- Population exploration is an explicit versioned autonomous-search option. Differential proposals alternate with bounded local/full compensation and original independent physical validation. Candidate history, best qualified archive, random state, parameter bounds and all charged work survive cancellation/reload. Original task planes, stop aperture, fields, spectrum and old search behavior remain unchanged; newly generated lens apertures are explicit descriptor inputs.
- All generation/annealing, local optimization and physical validation have declared finite budgets. Preparation cost is reported separately from autonomous-search cost. Final comparison uses equal allowances, and reports failures without implying global infeasibility or a universal success-rate improvement.

## Implemented product behavior

`ParaxialSeedSearchOptions.Generation` is nullable. Absent means the existing template preparation path. A version-1 descriptor explicitly declares 2–16 independent singlets, spherical/even-aspheric profiles, per-element catalog-material choices, stop interval, clear semi-diameter, thickness interval and minimum back clearance. The existing task supplies the fixed reference, stop, image, fields, spectrum and environment; source lens shapes and spacings are not the initialization source. Protected or transition elements cannot be replaced by this command. Cemented doublets, Q surfaces and one-element Delano diagrams are unsupported and explicitly rejected.

`RandomPhysical` samples thicknesses, air allocation, curvature/bending and permitted discrete materials. `Delano` samples and anneals the two-ray height diagram using the optical invariant; Core reconstructs powers/distances and produces symmetric thick-singlet starting curvatures using real catalog indices. Diagram candidates are proposal models only. Their distances guide interval allocation around the fixed stop; finite thickness and the physical envelope require a subsequent thick-lens correction, not an assertion that the thin diagram is already a physical solution. The module ranks returned proposal quantities but implements no independent tracing, dispersion or optical-analysis formulas. For an axis-only task a nonzero 0.1-degree diagram scale avoids a singular invariant; this does not change the task's actual fields or final validation.

Both paths enter the original shared-Core matrix/derivative preparation and 64-radial-sample manufacturing checks. All annealing evaluations count against per-start/global preparation limits, including failed constructions; completed starts and rejections are saved. New reports use `initial-structure-descriptor-seeds-v1`, keep the source plan/options and optional diagram count, and remain first-order feasibility only. The desktop exposes descriptor/Delano choices, count, stop interval, aperture, thickness/back-clearance and per-start limits; complex per-element material/profile descriptions can be stored in the plan. Opening/saving a plan performs no optical work.

`Options.PopulationExploration` independently enables bounded current-to-pbest differential proposals with forced binomial crossover. F/CR are explicit fixed settings: this implementation does **not** claim full upstream SHADE success-history adaptation. Donors use compatible surface/parameter identities; fewer than four compatible candidates use a recorded random rebirth within the same permitted bounds. Proposals enter Local, Full and the original independent validation. Population Local uses all permitted variables unless the existing explicit active-variable strategy selects a subset. No aperture, stop, fixed image or material is silently mutated by the differential step. In structure mode, population and original discrete decisions alternate; the material branch regression verifies that enabling population search does not hide existing permissions. Fixed-topology mode performs population/compensation only. Qualified-only reduction cannot enable population exploration.

Best qualified archives and immutable candidate history remain available even when descendants fail. Proposal random state, pending stage, axial anchors, continuation and event costs use the existing checkpoint protocol. Null options preserve historical serialization/fingerprints; the retained portability tests still pass. Generation and population search remain explicit choices, not automatic upgrades to old records or default AutoLens training.

## Measured comparison

The final comparison is **three elements, 50 mm, F/12.5, maximum half-field 5 degrees**, F/d/C wavelengths (486.1/587.6/656.3 nm), seeds 42/73/101. It is not the previous F/3.34, 21-degree reduction task. Template preparation retains the authored aspheric/template prescription; the two new descriptors generate spherical singlets with 5-mm clear semi-diameters and declared 2–3-mm thicknesses. Those are different allowed starting structures, not identical prescriptions or identical mechanical apertures. Stop/reference/image and optical targets are the same. Within each population/local pair the exact prepared seed pool is shared.

Each preparation has four starts, 100 evaluations/start and 400 total. Each search has four decisions, 300 function requests, 80 gradient requests, 2,000,000 rays and 45 seconds. The final comparison permits four updates per decision in both arms: Full4 for local-only, Local2+Full2 for population. The latter has an extra stage-initial gradient evaluation, so actual work differs and is reported rather than equated. Final acceptance still uses 21 fields, 10×32 area-integration pupil samples per wavelength, separate center/boundary checks and unchanged 50/150-µm RMS/maximum and 3% distortion limits.

Best qualified worst-field RMS, in µm:

| Seed | Template + local | Random physical + local | Delano + local | Delano + population/local |
| --- | ---: | ---: | ---: | ---: |
| 42 | 20.0933 | 19.9511 | 16.6871 | 19.7349 |
| 73 | 20.0933 | 18.5749 | 16.8691 | 11.5298 |
| 101 | 19.1600 | 21.3824 | 17.8778 | 19.9197 |

The mean for template/local is 19.7822 µm; Delano/local is 17.1447 µm, **13.33% lower in this three-seed fixture**. Random/local averages 19.9694 µm and does not improve the mean. Population exploration improves only one of the nine paired mode/seed comparisons and is worse in the other eight. It remains opt-in; this evidence does not establish a general population-search benefit or a new default policy.

The best combined endpoint, seed 73, has RMS 11.5298 µm and maximum radius 34.0889 µm, with all 21 fields retaining 960/960 integration and 99/99 check rays and no original-gate violations. Its search consumes 32 functions, 24 gradients and 371,856 rays; its separate preparation consumes 60 functions, 24 Core matrix requests, 16 Jacobian builds and zero traced rays. [Openable plan](../validation/rechecks/2026-10-29/happylens/delano-population.topology-plan.json), [STAROPT endpoint](../validation/rechecks/2026-10-29/happylens/comparison-final/Delano-73-population.staropt), [all final comparisons](../validation/rechecks/2026-10-29/happylens/comparison-final/summary.json).

Two earlier 18-run batches are retained separately: `comparison` allowed twice as many population updates and is not an equal-update comparison; `comparison-equal-updates` still used the old two-variable Local selection. Only `comparison-final` supports the table. Their search ray totals are 6,318,840 / 6,224,664 / 6,224,664 respectively, not one run's budget. Each batch has nine separately recorded preparations; comparisons reuse each preparation for the two search arms. These correlated pilots are not extra independent success-rate evidence. STAROPT exports verify snapshot save/readback, not a fresh external optical certification.
