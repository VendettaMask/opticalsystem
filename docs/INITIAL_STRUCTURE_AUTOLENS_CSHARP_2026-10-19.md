# AutoLens 的 C# 集成试验与完整移植差距

AutoLens 的课程优化思路可以在 Optical System Design 内部以纯 C# 实现，沿用共享 Core、平板根谱系、预算、保存恢复和 STAROPT 导出。本轮增加可选择的 CPU 试验模式，不替换默认 v20 搜索。它是受 AutoLens 启发的适配，不是原版 AutoLens 或 DeepLens 的完整重构；是否改善结果由相同输入和预算的对照决定。

## 固定来源

源码依据为 [AI4Optics AutoLens](https://github.com/AI4Optics/AutoLens/tree/e58db32f3a0b07f25861b5839a45970f77b5c947)，固定提交 `e58db32f3a0b07f25861b5839a45970f77b5c947`，重点核对 `1_autolens.py` 与 `deeplens/geolens_pkg/optim.py`。上游论文为 Xinge Yang、Qiang Fu、Wolfgang Heidrich 的 *Curriculum learning for ab initio deep learned refractive optics*，Nature Communications，2024。

上游当前脚本将光阑半径从目标的 **0.5 倍**按余弦进程增大到 1 倍；其说明文字写作 25%，与执行代码不同。本轮按执行代码保留半径含义，不把面积比例当半径。原版使用 PyTorch 反传和 Adam，优化连续材料后再匹配目录，随后再次细化；没有可直接替代这些步骤的预训练初值网络。

## 已集成范围

在“实验室 → AI 初始结构 → 搜索 → 局部优化算法”选择“AutoLens 启发式 · C# CPU 试验”。默认仍为“原生信赖域”。试验限定现有无限远、旋转对称、球面初始结构支持范围。

| 环节 | C# 试验实现 | 与原版的差异 |
| --- | --- | --- |
| 初值 | 原有精确零曲率根与显式曲率初始化 | 不复制上游随机镜头初始化或示例处方 |
| 课程 | 5 个余弦口径里程碑，半径 0.5 到 1，全视场、全部配置波长 | 不是原版训练步数与更新间隔 |
| 局部更新 | 有界 Adam，通过 Core 残差有限差分求梯度，每次探测计费 | 不是自动微分；另要求实测下降和回退 |
| 全目标细化 | 保留现有原生信赖域求解器和候选保护 | 不是上游第二阶段 Adam |
| 光学目标 | 现有 Core 的面积积分光斑与约束残差 | 不复制上游环臂采样、损失权重或光学公式 |
| 材料 | 已有真实目录玻璃家族搜索 | 不连续优化折射率和阿贝数，不引入虚构材料 |
| 最终验收 | 原完整口径、全视场、全波长、独立 21 视场加密与边缘检查 | 原规格和容差不降低 |

`FlatStartSettings.OptimizationMethod` 显式选择 `AutoLensCpuExperimentV1`。默认零值不序列化，因此旧记录的缺省含义和指纹不变。试验运行、候选谱系和追加细化使用带 `autolens-cpu-experiment-v1` 后缀的算法身份；规格指纹防止切换算法后恢复同一运行。历史算法不能伪装成此试验。检查点保存已完成光学工作和保守计费的中断配额，不保存或伪造 Adam 动量；不同课程、家族和独立细化之间重新建立求解状态。

所有光学量来自唯一共享 Core。新增优化器仅处理数值向量和调用者提供的残差，没有移植第二套追迹器、材料色散或分析公式。无 Python、Python.NET、PyTorch、外部光学进程或服务依赖。第三方[许可证原文](../third_party/autolens/AutoLens-LICENSE.txt)和[适配声明](../third_party/autolens/AutoLens-NOTICE.txt)随主程序构建与发布复制到 `Licenses`；包检查增加这两项要求。

## 验证协议

新增测试覆盖余弦课程、缺省序列化、模式与版本拒绝、Adam 探测计费、缺失梯度、取消、边界、最终独立验收、检查点保存恢复、追加细化、正式 STAROPT 往返和实际桌面控件。三组对照取冻结规格 03、07、09，统一为面积采样、实体光阑、自动变径，各方法设置 600 次评价和两分钟时间配额，片数、玻璃、目标和初始光学根一致，仅优化方法不同。时间在评价边界检查，不强杀正在进行的 Core 调用；测试另对最终快照进行独立 Core 回放，因此整组复验时间不等于搜索时间配额。这是本产品两个路径的有限对照，不是原版 AutoLens 的速度或数值复现。

## 同预算对照结果

下表为 Release 默认输出的实际结果。RMS 为完整目标、独立加密验收的最差面积 RMS，单位 mm；评价数包含启动、差分探测和最终验收，不是迭代数。

| 规格 | 默认 RMS | 默认评价数 | C# 试验 RMS | 试验评价数 | 完整目标结论 |
| --- | --- | --- | --- | --- | --- |
| 03 单色 50 mm | 0.04674981 | 102 | 0.03748049 | 556 | 两者均达标 |
| 07 复色 24 mm | 0.04041339 | 71 | 0.03934216 | 554 | 两者均达标 |
| 09 复色 50 mm | 无有效完整光束 | 320 | 0.05746458 | 600 | 两者均未达标 |

试验三组分别记录 19、16、16 次实际接受的 Adam 更新，证明课程路径执行了光学优化，而不只是新增菜单。前两组更低的 RMS 使用了更多评价；默认算法在完整目标达标后停止，尚未与相同实际工作量的默认追加细化比较，不能据此归因于课程策略更优或宣称效率提升。

规格 09 的默认路径在时间配额结束后，独立验收仍有失光，不能把幸存光线的统计值作为有效全视场 RMS。试验路径的积分与边缘检查光线全部通过，但最差 RMS **0.05746458 > 0.05**、最大光斑半径 **0.17350361 > 0.15**，仍保留 8 项像质违规，候选仅为 TraceValid，不是 LabAccepted。原规格、通光门槛和容差没有降低。

## 工程复验范围

最终默认 Debug/Release 根解决方案各 19 项目，零警告、零错误。Debug 聚焦回归 **53/53**，包括新增专项和既有坐标映射、策略、完整目标细化与渐进恢复；Release 对照 **3/3** 通过表示结果与验收契约正确，设计达标数仍为上表的 **2/3**。实际桌面控件操作与渲染 **1/1**；主程序内置交付、依赖边界和许可证检查两配置各 **16/16**。这些集合分别计数，不把初轮 22 项专项再次相加。界面验证为实际控件的无头运行与渲染，不是人工安装验收。

15 个本轮 C# 文件的格式核对通过；主程序、初始结构测试及主测试目录的 Core 副本与各自默认 Core 一致。Core 源码未改，原工作区与 HEAD 冻结证据各 **2668/2668**，原汇总哈希保持。严格文档检查结果由[机器账本](validation/AUTOLENS_CSHARP_EXPERIMENT_2026-10-19.json)记录。

首轮对照因测试未传入显式形式初始化而失败，两种方法都停在平板启动；失败 TRX 保留，后续按同一明确形式重跑。广泛 Debug 集合和完整 Release 模块测试含历史万次搜索协议，本轮主动中止，不计作完整通过；最终仅报告上述聚焦范围。早期沙箱宿主连接失败及构建占用重试也保留在[原始归档](../validation/experiments/2026-10-19/autolens-cpu-experiment-evidence.zip)。本轮未运行 Python、补采 Zemax、重打安装包、提交、推送或声称远端 CI 通过。

## 完整移植仍需解决的问题

完整原版能力还需要在共享 Core 内建立与正式追迹一致的可微接口，处理交点迭代、光阑瞄准、遮挡与全反射边界；不能在初始结构模块复制一套可微光学公式。连续材料优化及目录映射、非球面与胶合拓扑生成、原版损失和采样、批量并行与 GPU 均需独立实现和验收。它们没有因为 CPU 课程能够运行而自动完成。

当前试验适合验证架构衔接和评估课程策略。即使单个案例达标，也不足以替换默认搜索，或声称达到上游论文的效果；扩大困难规格与多种子验收应保留独立预算和未达标记录。
