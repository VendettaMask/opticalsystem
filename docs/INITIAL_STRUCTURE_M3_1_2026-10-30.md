# 初始结构 M3.1：胶合共享界面与 SPC 过渡基础

对应[实施计划](INITIAL_STRUCTURE_SEARCH_IMPLEMENTATION_PLAN_2026-10-30.md)的 M3.1。本轮完成底层数据、编译、参数和验收边界；自动寻找鞍点、胶合结构调度、已有镜头检索、自动口径、性能实验、准备检查点和三语产品入口仍未交付。完整过程见[本轮证据](../validation/rechecks/2026-10-30/initial-structure-m3-1/README.md)。

## 胶合处方

`DesignTopology.CementedInterfaces` 是可空的显式 v1 扩展。相邻两片必须引用同一个面 ID，且共享面的顶点、面型、净口径和机械口径完全一致。编译成一个真实 Core 玻璃—玻璃界面，两片映射共用同一 Core 面索引；不生成两个人工空气界面。多片胶合链可从受支持的 Core 快照导入，材料仍逐段解析、冻结并验证目录数据来源。

共享面只绑定一次。曲率、非球面参数或轴向坐标同时作用于两侧玻璃；任一侧受保护，绑定和直接 Core 更新都拒绝修改。轴向修改保留其他外表面和固定参考、光阑、像面，重新编译并检查两侧真实厚度。原绑定不能用于换材料或变更结构后的快照。

普通制造检查分别采样每片玻璃的中心、边缘厚度和斜率；共享面不产生虚构的空气间隔。两侧玻璃可能需要不同的边缘采样半径，因此坡度残差按所属玻璃分别编号。胶合组仍用原 `TopologyValidator` 的 CPU 密集像质、失光和制造门槛验收。

这项扩展目前供显式编译、绑定、固定拓扑计算和验收使用。现有自主调度和旧增删拆并操作会明确拒绝胶合组，避免把独立单片的变量/删除规则直接用于共享面。没有增加桌面勾选项或自动启用新路径。

## 零厚度过渡与实体化

独立的 `InitialStructureSpcTransitionV1` 保存冻结父处方、结构限制、原绑定身份、新元件 ID 和成对曲率偏移。其编译结果是 `CompiledSpcTransition`，不是 `CompiledTopology`，不能传给普通优化器或合格设计归档。

过渡态保留原玻璃/空气界面，以及零空气、零厚度的同材料球面元件的前后两面。两个新增面可取相同的正、负曲率偏移。此时通过共享 Core 检查固定参考到像面的 ABCD 不变，并对两个独立曲率使用 Core 自动微分。过渡态不执行物理光斑追迹，普通拓扑导入拒绝这些零间隔/零厚度界面。

`SpcTransitionCompiler.Materialize` 要求恢复普通正中心厚度；可选择真实最小空气间隔，或在完全一致的共面面型处建立一个胶合共享面。曲率已偏移而与原背面不同的过渡态不能静默合并为胶合面。调用方可显式替换为原结构限制允许的目录玻璃；不执行自动玻璃拟合。实体化保留原片、逐面口径和固定平面，空间不足、片数超限或材料越界均拒绝，后续仍须完整原规格验收。

`SpcTransitionFiles` 提供有大小上限、原子写入、独立身份和 SHA-256 校验的实验文件。它不属于普通 `.optic.json`、`.topology-plan.json` 或自主检查点，不注册产品文件打开入口；也不是 M3.5 所需的随机状态/候选池/预算恢复检查点。

[SPC 原始论文](https://doi.org/10.1051/jeos/2026024)还要求从局部最优出发，构造分支并优化、增厚、重新优化和选择玻璃。本轮只实现上述过渡与实体化基础，没有证明父方案为驻点、Hessian 为鞍点，也没有复现论文的搜索或性能结果。
