# 功能图标语义设计规范 1.3

当前 221 款图形覆盖主程序、顺序/非序列分析及内置模块的 332 处入口和状态。196 款依据实际名称新绘，25 款沿用用户已确认的专用原稿；后者不冒称本轮新绘。交付见[可搜索图库](assets/icons/index.html)、[全部逐项设计说明](assets/icons/设计说明.html)、[HUD与魔法主题SVG包](assets/icons/scientific-outline-1.3.zip)。

## 从名称到图形

设计与评审共用[全项目设计语言与工作方法](UI_DESIGN_SPEC.md#全项目设计语言与工作方法)，将功能辨识、阅读主次和主题一致性落实到实际18/24/32尺寸。方法补充不改变1.3的网格、语义ID或当前图形包；光域后续目标与已交付材质的区别见下文。

先写对象与动作，再决定可见特征。例如“锁定膜层”需要膜层截面和闭合锁，“删除视场”需要场点扇和减号，“导出图像”需要图像框和向外箭头。不能因为旧名字叫 `scan-line` 或 `chart-line` 就沿用扫描框或通用折线。

同义的添加、删除、保存、前后导航可以共享基础图形；对象或分析含义不同则拆分。模板只共享具有相同含义的轴、文档边界、光学面等部件，每款专用图形均记录设计意图。逻辑绑定使用稳定英文图标 ID；中文标签仅供设计判断与显示，运行时不按文字选择绘制实现。

| 功能族 | 必须体现的结构 |
| --- | --- |
| MTF 频率 | 调制随频率下降的响应；与直方柱、PSF 峰区分 |
| 离焦 MTF | 随焦位置变化的峰及焦面参考线，最佳位置为最大值 |
| MTF 随视场 | 场点扇、离散场点和场边变化 |
| 傅里叶 / 惠更斯 / 几何 | 分别用频谱采样、次波圆弧、几何光线作方法标识 |
| RMS | 最小值响应，与离焦 MTF 的最大值峰区分；视场/波长/离焦各有变量标记 |
| 点列 | 像面内独立点簇；离焦用多像面，全视场与结构矩阵保留排列语义 |
| PSF / 圈入能量 | 点峰与衍射环 / 包围圈与累积上升，不能共用一个靶环 |
| 光程差 / 波前 / 干涉 / 傅科 | 路径程差 / 等程差轮廓 / 条纹 / 刀口半瞳 |
| 像差与色焦 | 对应光线扇、畸变网格、焦点轴向或像面横向分离 |
| 报告 | 文档及实际内容结构，表面表、系统透镜、分类树、摘要和基面分别设计 |
| 膜系 | 基底上的层截面；新增、反转、闭/开锁与光谱响应分别表达 |
| 视角方向 | 目标面着色，后侧与下方面以虚线辅助区分；方向动作本身保持 |

所有分析曲线在图标中均为定性示意，不以图标表达某一镜头的真实数值。

## 视觉和主题

源 `viewBox` 为 `0 0 32 32`，线宽 1.65，圆端点和圆连接。`structure` 表示边界/坐标/容器，`signal` 表示动作或核心特征，`secondary` 表示参考和次要节点；小节点可用对应 `-fill`，保留必要透明度和虚线。不要加入位图、字体、文字标签、外链或按钮背景；避免把颜色作为区别两种功能的唯一依据。

| 主题 | 结构 | 主信息 | 辅助 |
| --- | --- | --- | --- |
| Light | #8298A8 | #398FF0 | #28ADAF |
| 黑洞 Dark | #A5978B | #F0AE79 | #D5B89C |
| Lumen HUD | 钢色渐变 / #6C8D9D | #78DCFF | #C4F5FF，参考点金色 |
| Isekai 剑与魔法 | #A18B5F | #EACC8B | #A6B48B |
| Pixel | #2F5169 | #B8283A | #196937 |

颜色由 `ThemeRegistry.IconPalette` 提供，程序继续处理禁用、强调前景与背景对比度；独立导出 SVG 展示普通状态。主题身份、字体、品牌和物理光线/波长/材料/曲线/状态语义保持。

光域后续设计采用钢铁侠式纯投影HUD，以发光光学结构、通透叠层、分段仪表环和精密刻线表达功能，不再引入金属构件、实体舱板或写实材质。主响应与动作仍是第一识别特征，背景、按钮及文字继续使用主题自己的资源。上表钢色渐变及下述原生材质能力描述已交付的1.3资源；本轮方法同步没有重绘它们，新版整套效果尚未确认，不能将历史图包标成已完成新风格。

异世界的世界观固定为剑与魔法。魔导书、卷轴、法阵、符文和古典炼金器具均须服务于实际功能：指南是魔导书，报告是卷轴，编辑是账册与羽笔，光瞳和波前是法阵与符文刻线。炼金是这个世界里的器具语汇，不能把整套改成仅有旧金配色的通用科学图，也不要求每个命令都出现剑、魔杖或相同徽章。基础操作保持简洁。

仅光域允许局部钢色渐变、信号边光及中心高亮；不作用于文字或数据。独立SVG使用本地固定32网格的定义，原生绘制使用对应材质，强调/禁用单色覆盖关闭材质。两个主题各有221款资源；普通、黑洞、像素保持原图。

## 后续改图与文档同步

新增或修改实际功能图标时，先确认对象、动作、自变量和方法，再同时完成五主题适配；光域与异世界需要各自有含义的造型，不能只给基础图换色。18、24、32 尺寸均检查功能辨识度，主题材质不能盖住核心轮廓。命令 ID、功能名称、操作、布局及物理数据颜色保持。

本规范是当前语义与主题造型的维护入口。[本地图标说明](LOCAL_ICONS.md)记录资源与接入，[主题包规范](THEME_PACKAGES.md)和[UI 规范](UI_DESIGN_SPEC.md)沿用同一规则。用户最早收到的[Word 风格规范](assets/icons/图标风格规范.docx)及[网页规范](assets/icons/图标风格规范.html)同步到 1.3；完整图库附带同版规范。每次交付须同步图形来源/功能对应表、图库、SVG 包、变更记录和 `AGENTS.md` 的长期偏好；仅在末尾追加新说明而保留冲突的旧正文不算完成。

## 源码与扩展

`scripts/semantic_icon_designs.py` 保存 196 款新绘路径的定义；`Scientific/Designed/manifest.json` 保存实际名称、含义与分析命令映射。原确认稿留在 `Approved`。未使用的 1,748 款 Lucide 目录留在 `Glyphs`，保留来源且不混入当前重绘图包。

`build-icon-theme-variants.py` 输出 `Scientific/Themes/Lumen`、`Scientific/Themes/Isekai` 各221款，主题manifest记录442份资源及材质。元数据共享，几何按绘制线程延迟缓存，避免跨Dispatcher复用椭圆/矩形对象。

新增图形时为功能指定稳定语义 ID，写明对象、动作和设计含义，再在实际调用处绑定；不能全局替换通用名字来改变不相关功能。`build-semantic-icons.py` 默认重建新绘 SVG 与清单；本轮 `--apply` 的首次绑定计划和前后哈希是历史执行记录，已接入代码无需反复重放旧坐标。`export-semantic-icons.py` 导出图库、五主题 SVG、母版、完整总图和逐项说明。

在 18/24/32 的真实尺寸和五主题下检查轮廓、透明背景、方法区别及按钮可读性；原生菜单须保持所有命令、顺序、分组、文字和动作。基础重绘见[语义图形检查](../validation/rechecks/2026-11-03/semantic-icon-redraw/README.md)，两套独立主题见[主题身份接入](../validation/rechecks/2026-11-03/icon-theme-identity/README.md)。文档修订记录与产品验证结果分别保存，不将文档检查追加为原生测试通过数。
