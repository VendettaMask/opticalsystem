## 1. 产品目标与边界

用户打开主程序的“实验室 → AI 初始结构”，在独立窗口输入焦距、口径、视场等指标，点击“生成初始结构”，获得实际镜头处方、光线图、目标完成情况和若干有区别的候选。整个过程不需要用户提供现成镜头、不需要先猜曲率，也不需要编写优化宏。

“从平板开始”是实际计算过程的约束：每条搜索谱系的根节点都是具有真实厚度、空气间隔和目录玻璃的平行平板，全部折射面的曲率精确为零。第一次改变曲率的计算步骤及其结果必须保存。只保存一份平板图片、实际用预制镜头或人为指定的成熟处方起跑，不符合这个要求。

输出目标是经过验证的初始结构，不预先承诺任意输入都有满足全部要求的解。如果预算内未找到达标结构，仍应展示最接近目标的有效候选、逐项差距和可继续操作的选项，明确说明“本次未找到”，不能直接宣布“物理上无解”。

第一版支持：

- 无限远物体、固定焦距、旋转对称、顺序折射成像；
- 球面镜片，真实目录玻璃，空气间隔；
- 先验证 1～3 片的基础能力，再开放经过基准验证的 3～6 片常规定焦范围；7～8 片单列实验能力；
- 单波长和可见光多波长设计；光谱范围必须落在所选材料有效数据内；
- 多个片数、光阑位置和玻璃分配产生的候选结构比较。

非球面、胶合拓扑、有限共轭、无焦扩束器、变焦、反射及折叠系统进入后续独立里程碑。用户此前的 266 nm 无焦扩束器问题不作为本次定焦成像生成器的验收样例。不能用“不含无焦”改变正式工作台已有的导入、追迹或分析行为。

## 3. 用户输入：先少量指标，再按需展开

### 3.1 默认页面

| 输入 | 交互及含义 |
| --- | --- |
| 目标焦距 | 正数，默认显示 mm |
| 系统口径 | F/# 或入瞳直径二选一；另外一个显示为由目标值推导的参考量，避免两个独立输入互相矛盾 |
| 视场 | 明确标注“最大半视场角”；支持切换为像面尺寸输入。角度与像面尺寸不同时作为两个隐含硬约束 |
| 波段 | 单波长／可见光预设／自定义波长表；显示实际波长、权重、主波长 |
| 镜片数量 | 固定片数或“最多 N 片，自动比较”；默认自动范围必须显示 |
| 空间限制 | 最大总长；后焦默认自动，可展开最小值、范围或固定值 |
| 搜索力度 | 快速／标准／充分；转换成明确预算，运行前显示预估规模，运行时间以实测为准 |

示例输入“50 mm、F/4、最大半视场 10°、可见光、最多 4 片、总长不超过 90 mm”只是交互示例，不是尚未验证的成功样例。

点击“生成初始结构”前，在同一页面给出一段可核对的规格摘要，例如“无限远物体；焦距 50 mm；目标入瞳 12.5 mm；半视场 10°；3 个波长；自动比较 1～4 片；后焦自动”。

### 3.2 高级选项

- 焦距及 F/# 允许偏差；每个视场的 RMS 光斑半径上限、最大光斑半径上限；
- 视场采样及权重、波长及权重，采用可增删行的表格；
- 玻璃目录／允许材料集合，能够看到材料来源和波长覆盖；
- 中心厚度、边缘厚度、空气隙、最大外径及后焦约束；
- 光阑自动搜索或指定可行位置；
- 畸变等选配目标；未启用的目标不作为达标条件；
- 精确预算、可重复运行编号以及继续细化的范围。

起始半径、曲率正负编码、迭代算子、种群大小等不进入默认操作流程。调试界面可以保留算法设置，但普通用户不需要理解这些设置才能获得结构。

所有自动选择都在运行摘要中展开成实际值。自动模式不能暗中扩大玻璃集合、增加片数、缩小视场或放宽像质目标。

## 4. 用户输出和使用流程

```mermaid
flowchart LR
    A[输入设计指标] --> B[检查规格与材料]
    B --> C[建立精确平板]
    C --> D[获得聚焦能力]
    D --> E[逐步达到完整指标]
    E --> F[比较多种候选]
    F --> G[独立加密验证]
    G --> H[查看或导出处方]
```

结果区包含：

1. **优选结构**：首先展示达标候选，按像质、片数、尺寸等可理解的指标比较，保留不同结构家族。不是把几十个只有末位小数不同的处方列作几十种方案。
2. **镜头处方**：各面的曲率半径、厚度、玻璃、有效半口径、机械半直径及光阑；平面按既有统一规则显示。
3. **真实二维图**：曲面轮廓来自候选几何，光线来自该候选实际追迹；有效口径和机械尺寸分别处理。不会用机械边缘代替入瞳采样位置。
4. **逐项目标表**：目标、实际值、允许偏差、是否满足。分别显示各视场像质、畸变、通光比例以及结构约束；加权平均不能掩盖坏掉的边缘视场。
5. **演化记录**：可以回看精确平板、首次弯曲、阶段性候选和最终候选；记录各阶段实际使用的视场与口径。
6. **操作**：查看全部候选、A/B 比较、继续细化、保存实验、导出选中的 STAROPT。

用“正在建立聚焦能力”“正在扩展到完整视场”“正在验证候选”等阶段名显示进度，同时给出耗时、预算消耗和达标数。没有可证明的总工作量时显示阶段进度，避免虚假的总百分比。

结果分为“满足本次初始结构目标”“可追迹，仍有指标未满足”“不可用”。只有通过最终独立验证的结果可以标为达标。搜索预算结束与算法失败分别说明。

## 5. 从精确平板出发的计算路线

### 5.1 为什么要单独解决启动阶段

平板系统的总光焦度为零，不能把尚未形成的有限焦距当作正常优化数据。若直接对无穷焦距、无法定义的工作 F/# 或尚未建立的像质指标作运算，会产生异常、常量惩罚或无效搜索方向。

因此新路线第一阶段不依赖有限焦距已经存在。优化变量使用有限曲率 `c`，平面为 `c = 0`；显示半径由该变量转换。第一项技术验证是：**从所有曲率严格为零的实际可追迹结构出发，第一步评价和更新都能形成有限数值**。

### 5.2 阶段 A：输入归一化与平板根结构

- 把单位转换为内部结构化数量；固定视场、孔径及波长的物理定义。
- 用目标焦距和目标 F/# 得到目标入瞳直径。此处只使用用户目标值，不用当前平板的无穷焦距推算孔径。
- 为允许的各个片数生成平板根结构，中心厚度和间隔满足下限，所有曲率为零。
- 根结构可以在厚度分布、间隔分布、真实玻璃分配和光阑位置上有差异。每个根都独立保存；不从参考镜头处方复制非零曲率。
- 依据显式外径限制或光束包络估计建立初始口径，尺寸上限不随搜索偷偷增加。
- 所有材料先核对目录与波长覆盖。候选中的材料始终可实际计算，不用虚构折射率材料。

### 5.3 阶段 B：先获得聚焦能力

采用主波长、较小的实际入瞳和轴上／小视场，在合法的像面搜索区间内先建立能成像的结构。

拟采用两类相互约束的有限残差：

- 系统光焦度相对目标的差，而不是平板阶段的无穷焦距差。近轴矩阵具体符号、折射率约定先以独立薄透镜和厚透镜算例核对。
- 真实光线在指定像面附近的聚拢误差，以及主光线位置与目标成像关系的误差。

像面位置受后焦和总长约束：后焦自动时可作有界变量或条件求解；后焦固定时保持用户指定的物理间距，不强制移到近轴焦点来制造好结果。

在明确的曲率、厚度和间隔缩放下计算更新。完全对称的平板如果产生退化方向，先改变根结构的合法厚度／间隔或使用受控的小曲率探索步；该探索步是有记录的首次更新，不能把更新后的结构冒充原始平板。

如果一种根结构启动失败，保存原因并尝试其他根。禁止把所有失败统一映射为同一个常数后继续长时间空转。

### 5.4 阶段 C：逐步达到完整设计指标

聚焦建立后，逐步增加入瞳、半视场和参与评价的波长，直到实际计算使用全部用户目标。初始进度可采用 30%、60%、100% 等离散难度档位，但比例只是待基准实验确定的内部调度参数。

阶段推进以通光、几何合法性和目标改善为依据。扩大指标后若候选失效，缩小难度增量、回到上一有效状态或切换其他候选；不修改用户最终目标。完整规格尚未达到时，候选不能进入“达标”列表。

切换阶段时重新评价候选。不同口径、视场和采样密度下的评价值不能直接比较并据此宣称改善。

### 5.5 阶段 D：有界连续细化

所有光学数值必须由正式 Core 的追迹与分析接口提供，实验室仅将接口返回量与目标组合为明确的**多项残差向量**，采用带尺度控制的阻尼最小二乘／信赖域步骤；第一版先使用经过差分稳定性检查的数值雅可比。不得在实验室重写分析公式来补足接口。把整个总分开平方当作唯一残差的做法不作为新路线的主要局部优化器。

目标残差包括：

- 焦距、F/#、像高或成像关系；
- 分视场、分波长的光线截距；多色像质使用约定一致的参考中心，不让每个波长单独重新居中而隐藏横向色差；
- 畸变及用户明确启用的其他目标；
- 接近结构边界的连续惩罚；越过不可构造的几何边界时拒绝该步并收缩步长。

同一次梯度／雅可比计算使用相同的光线样本，避免随机采样噪声形成假的梯度。参数采用无量纲缩放，有限差分同时检查步长过大、过小及平面附近的连续性。

这是一条拟优先验证的实现路线，不预先认定它对所有规格优于现有差分进化。现有算法保留为冻结对照；若新路线在公平预算下不能改善成功率、稳定性或效率，先定位原因，必要时采用有界无导数探索作辅助。自动微分是后续性能选项，不是用户拿到第一版结果的前置项目。

### 5.6 阶段 E：多结构探索

- **片数**：在用户允许的范围内分别求解，按预算分配最低探索机会，之后给有希望的家族更多细化预算。
- **光阑**：先比较明确的可行空气区间和镜面位置；再在选定空气区间内把光阑位置作为有界变量。独立光阑面不计为镜片，不得穿入玻璃。
- **玻璃**：按用户允许集合产生若干真实材料分配。对有希望的结构做有限的单片或成对材料替换，每次替换后重新细化曲率和间隔，再用真实色散数据评价。
- **局部停滞**：对曲率、弯曲、厚度分布和间隔做有界扰动，保留之前的好结果。拓扑家族之外的变化不伪装成“全局穷尽”。
- **多样性**：先按硬约束筛选，再结合像质、片数、尺寸及归一化结构距离保留代表。去重指标必须区分实际不同的玻璃、光阑和光焦度分配。

候选数量由搜索结果决定。界面可以默认展示最多 5～10 个优选结果，但不能为了凑数重复结构，也不能因列表限额删除实验记录。

### 5.7 阶段 F：最终独立验证

重新从不可变快照建立计算对象，以完整用户规格、更多光线及补充视场位置计算。至少包含全部明确设计视场、轴上、边缘视场、瞳边界和原搜索采样之间的检查点。

最终评价必须检查：

- 焦距、入瞳／F/# 和视场定义一致；
- 每个视场的通光比例及像质，不仅看总平均；
- 多色 RMS、最大光斑、焦面位置及已启用畸变约束；轴上畸变不能用零像高作分母；
- 中心厚度、边厚、空气边缘间距、表面可构造域、镜片不相交、后焦与总长；
- 光线损失的分母包含尝试发射的光线，遮掉高像差光线不能让一个坏结构被判成好结构；
- 机械口径、净口径和系统入瞳含义独立，绘图与数值采用同一快照；
- 所有材料仍为真实有效目录项，导出后可重新加载计算。

“独立验证”指从不可变快照发起新的正式 Core 计算请求，隔离搜索状态并加密采样，不是另写物理实现。解析算例、独立参考计算和选定处方的外部软件对照只用于测试与校核，不能成为实验室运行时的评价、验收或绘图来源。

## 6. 评价与验收条件

拟建立三层约束：

| 层级 | 内容 | 处理 |
| --- | --- | --- |
| 必须合法 | 材料有效、几何成立、无相交、尺寸界限、固定后焦等 | 不合格候选不能标为达标 |
| 用户目标 | 焦距、口径、分视场像质、可选畸变等 | 显示实际差距，按用户允许偏差逐项判断 |
| 排序偏好 | 更少片数、更短总长、更大结构裕量等 | 在明确目标下用于比较，不覆盖硬约束 |

规格保存时同时保存目标值、容差、是否启用和单位。第一版“初始结构”预设拟从焦距误差 2%、F/# 误差 5%、分视场多色 RMS 半径 50 μm 的量级开始做适用性实验；这些是**待冻结的产品预设候选**，不是文献标准或已经验证的能力。P0 阶段在新算法调参前固定验证规格和门槛，之后不能为了过测试放宽。

用户填写了明确像质要求就采用该要求。只填写基本参数时，应显示所选像质预设的实际门槛，避免暗藏宽松标准。初始结构达标不代表衍射极限，也不代表通过公差或可直接量产。

MTF、波前和点列图可以作为结果分析；作为达标条件的项目必须有经过验证的评价路径。分析无法形成时显示明确原因，不生成看似正常的替代曲线。

## 7. 独立工程方案

沿用现有 `labs/InitialStructure` 的隔离结构：独立解决方案、Contracts、Engine、Persistence、App、Tests。正式程序继续只提供启动入口，实验室不放到“优化”菜单下。

拟新增或重构的职责边界：

| 模块 | 职责 |
| --- | --- |
| 规格编译与校验 | 整理单位、用户目标、自动选项及材料集合，生成不可变运行规格 |
| 平板根生成 | 生成精确零曲率、材料真实、几何合法的根快照 |
| 正式计算调用适配 | 将候选快照与显式设置传给正式 Core，返回既有追迹、分析及几何数据；不包含第二套光学公式 |
| 启动求解 | 以有限光焦度和真实光线残差建立聚焦能力 |
| 难度调度 | 管理入瞳、视场、光谱和采样的渐进阶段及回退 |
| 连续求解器 | 参数缩放、多项残差、约束、数值雅可比和步长控制 |
| 结构探索 | 片数、光阑、真实玻璃、候选扰动及预算公平分配 |
| 候选档案 | 结构去重、多样性、优选结果、父子谱系和状态 |
| 独立验收器 | 从快照调用正式 Core 完整重算，比较返回量与逐项目标，给出报告 |
| 桌面界面 | 指标输入、进度、真实图形、结果比较、继续细化与导出 |

Core 是实验室光学计算的唯一实现来源。实验算法、预算、阶段、候选排序不得流入正式产品的状态、撤销、分析路由或默认参数。如果缺少可复用接口，先在正式共享计算层补充或抽取通用能力并走正式计算验证，再供实验室调用；不得在实验室复制公式、另建分析引擎或用近似结果兜底。

### 7.1 共用计算内核的强制边界

- **统一调用**：真实与近轴追迹、曲面求交／折射、材料色散、光焦度／焦距／F/#、点列图与 RMS／最大光斑、波前、MTF、畸变等光学分析，以及二维图的实际光线和曲面几何，均来自正式共享计算接口。
- **实验室可以实现**：输入整理、平板结构提案、变量与目标设置、参数搜索、有限差分调用调度、正式返回量的残差缩放与加权、目标／几何界限比较、预算、谱系、存储和展示。这不授权重写物理量或像质指标的计算公式。
- **设置一致**：所有请求显式记录快照、材料、波长及权重、视场与归一化、孔径、采样、像面、参考中心及计算版本。搜索可按计划降低采样或分阶段扩展规格；最终验收必须恢复完整目标，并仍调用同一正式内核。
- **错误透明**：接口不支持或分析失败时记录具体原因；不能退回实验室自写追迹、材料近似或替代分析曲线。正式层存在错误就修复正式层，使正式软件和实验室共同受益。
- **一致性验收**：同一候选导入正式软件后，采用相同分析设置，比较正式直接调用与实验室调用的数值、单位、有效／失效光线和错误状态。架构检查禁止第二套追迹／分析实现；解析与外部参考仅留在测试中，不供产品运行时调用。

## 8. 预算、恢复和数据记录

- 一次运行记录目标、容差、材料目录版本及内容指纹、算法版本、随机种子、采样规则、软件版本与机器环境。

## 10. 验证矩阵与成功定义

### 10.1 计算正确性

- 正式共享内核：同一快照、相同设置下，实验室与正式分析接口的返回值、单位、失光计数及失败状态一致；覆盖 P1 指标迁移，禁止用实验室第二套分析实现通过该验证。
- 严格平板、薄透镜／厚透镜、已知球面组合：检查平面连续性、一阶量、真实折射及首次更新方向。
- 边厚与空气边缘间距：使用独立球面矢高公式，覆盖平面、正负半径、口径超域和相交。
- 视场：轴上单视场、多个视场、角度与像面输入、边界归一化坐标；不通过无条件截断坐标掩盖定义错误。
- 材料：存在／缺失／重复名称／波长超出有效范围；不得退回近似材料。
- 多色：共同参考中心、权重为零、主波长变化及色差不能被单色重新居中抹掉。
- 遮拦：故意缩小净口径，确认通光惩罚增加，不能因高像差光线被挡而晋升达标。

### 10.2 搜索有效性

新建约 12 个明确输入规格，至少覆盖短、中、长焦；单色与可见光；低视场与中等视场；固定／自动后焦；固定片数与片数范围。另设高难度压力样例和可证明冲突的输入，不混入常规成功率分母。

每个常规规格固定至少 5 个随机种子和统一机器预算，比较旧原型与新路线：达到全部目标的运行比例、首次达标时间、总光线数、最差视场像质、不同达标家族数量和导出回读误差。不得只展示最好的一次运行。

拟定发布门槛：常规规格中至少 80% 的规格，在 5 次运行中至少 4 次获得一个经独立重算达标的初始结构；每次完成运行都提供可解释的结果状态。最终基准数量、预算和门槛在 P0 冻结。压力样例如未达标照实记录，不能通过改标签或放宽要求混入成功结果。

### 10.3 数值权威与外部对照

现有 `123456.ZMX` 的 Zemax OpticStudio 2026 R1 捕获仍是仓库正式精度基准，既有阈值不修改。它并不自动证明本次新生成镜头的数值正确。

从新生成候选中选择单片、双片和三片代表，明确相同玻璃、波长、视场、孔径、像面和参考中心，与独立解析／追迹计算及可获得的 Zemax 数值导出比较。外部软件暂不可用时明确标注“未做该候选外部对照”，不能只凭图形相似宣布对齐，也不声称与 SYNOPSYS 结果等价。

### 10.4 工程与界面

- 同一固定评价预算下，串行、并行及检查点恢复的候选身份与评价按协议可重复；不同预算不作相同结果承诺。
- 在材料错误、全部光线失败、预算耗尽、取消、损坏检查点及导出失败时保留已完成数据，说明具体阶段。
- 真实操作验证基本输入、生成、选择、二维图、继续细化和导出；不以源代码文本匹配代替界面验证。
- 测试窄窗口、键盘操作、输入错误提示和长候选表；运行时锁定当前规格，修改参数明确产生新运行。
- 独立实验室 Debug/Release 默认输出均可运行；正式项目没有新增实验室引用，入口仍位于独立“实验室”。

## 11. 主要风险和处理顺序

| 风险 | 应对与判断依据 |
| --- | --- |
| 精确平板导致退化或不可用焦距 | P1 先证明有限残差与首次更新，失败则调整启动目标和参数尺度，而不是跳过平板起点 |
| 搜索能聚焦但全视场像质很差 | 分视场门槛、渐进增加规格、保留不同结构家族，记录最差视场 |
| 用遮光或移动像面“改善”结果 | 固定真实目标入瞳、独立通光门槛、后焦约束与完整快照重算 |
| 玻璃或拓扑组合过多 | 分层预算、少量真实材料提案、局部替换与候选去重；报告实际探索范围 |
| 数值差分过慢或不稳定 | P1 测量步长稳定性与调用量；先做缓存隔离和尺度优化，再决定是否需要自动微分 |
| 多种结果只是数值微小变化 | 光学结构距离与家族覆盖，同时保留全部原始候选供审查 |
| 用户只看到“失败”但不知原因 | 逐项目标差距和失败阶段，区分输入冲突、没有达标候选、计算异常及预算结束 |
| 界面或功能越界到主程序 | 保持启动器隔离；正式算法变更独立提出并验证 |
