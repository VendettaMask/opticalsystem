## 设计原则

顺序模式默认只打开“镜头数据”和“二维视图”两个文档页签，镜头数据初始激活；左侧系统选项保持可用。启动、新建、打开工程和重置初始布局均遵守此规则；不会自动恢复额外分析或三维页，完整自定义布局可显式载入。

MDI 平铺/层叠子窗口标题按钮使用 20 × 20 DIP 点击区域，图标在 12 × 12 DIP 内按比例绘制，不继承表单按钮的 32 DIP 最小高度。按钮继续沿用主题状态与关闭权限。子窗口激活不能把业务内容转移到隐藏页签；内容只能在所属子窗口边界内绘制与命中，不遮挡相邻页面。此行为已实现，验证范围见 [平铺交互修复](MDI_INTERACTION_FIX_2026-09-27.md)。

顺序与非序列模式的“窗口”工具栏统一使用“窗口布局”下拉按钮，按原顺序收纳“保留分栏停靠”“合并单窗格”“全部独立浮动”“平铺全部”“层叠全部”五项操作。按钮沿用 Ribbon 的图标、文字和下拉箭头样式，菜单保留各项原图标与动作，并支持中英日界面语言；页面操作和默认布局保存/载入仍保持各自入口。

1. 光学数据优先。界面应服务镜头参数、图形分析、制造数据和误差判断，避免装饰性大卡片、营销式标题和无意义说明文字。
2. 同一语义只允许一种表现。主题色、文本层级、按钮状态、图表背景、分析页底部信息区和品牌区应来自公共资源或公共组件。
3. 响应式优先，固定尺寸例外化。Dock 文档区会被分栏、浮动和恢复旧会话压缩，普通页面不得依赖写死宽高才能可用。
4. 主题完整。明亮、暗夜、异世界、像素风格和光域主题必须同时可读；除物理波长、工程图标准色和导出文档外，不直接写界面颜色。
5. 可访问性是功能契约。可点击、可编辑、可滚动、可选择的控件必须有键盘路径、焦点反馈、自动化名称和可理解的禁用/错误状态。

## 颜色

所有普通 UI 颜色必须通过 `ThemeResourceBindings` 或由它派生的局部资源绑定。品牌图、主题相关位图和其它非画刷资产使用 `ThemeAssetBindings`，不得放入画刷资源表。

核心色彩语义：

| 语义 | 用途 |
| --- | --- |
| `Surface` | 主界面和普通内容背景 |
| `SubtleSurface` | 次级区域、分隔区、状态栏、轻量容器 |
| `SettingsSurface` | 设置卡片、参数卡片和可编辑面板背景 |
| `SettingsOverlaySurface` | 覆盖在图形区上方的设置浮层背景；普通亮模式为不透明白色 |
| `Workspace` | Dock 工作区底色 |
| `Border` | 普通边框和分隔线 |
| `TextPrimary` | 主文本、标题、坐标轴 |
| `TextSecondary` | 次级文本、表格辅助信息 |
| `TextMuted` | 说明、时间戳、低权重元数据 |
| `TextDisabled` | 禁用文本 |
| `Accent` | 当前选择、主操作、活动标签 |
| `PlotBackground` | 分析图页面和图内绘图区背景 |
| `SceneBackground` | 二维/三维查看器背景 |

约束：

- 明亮主题下分析页外层和绘图区必须一致，不允许出现“页面偏灰、图内纯白”的割裂。
- `Brushes.White`、`Brushes.LightGray`、`Color.FromRgb` 等硬编码只能用于物理/工程语义：波长颜色、光线颜色、制造图纸标准线色、导出图像画布、算法数据可视化的固定色标。其它场景必须抽成主题资源。
- 普通窗口、面板、工具栏、状态栏、分隔线、说明文字和表格行前景色不得直接使用白/灰/RGB 字面量；应绑定 `Surface`、`PlotBackground`、`Border`、`TextSecondary`、`TextMuted`、`TextError` 等主题资源。
- 普通 UI 色彩约束由 `OrdinaryAppUiColorsUseThemeResources` 契约测试保护；新增普通交互界面不得绕过 `ThemeResourceBindings` 写裸 `Brushes.*` 或 `Color.FromRgb/Argb`。确需固定色时必须属于工程/物理/标准语义，并集中到受审计的命名调色板或明确豁免文件。
- 分析结果表格的业务行色使用主题资源，例如 `AnalysisRealRayRowBackground/Foreground` 和 `AnalysisParaxialRayRowBackground/Foreground`，必须同时覆盖全部已注册具体主题。
- Zemax 评价函数行色属于业务分类色，不直接散落在面板里；统一由 `MeritOperandRowPalette` 输出背景/前景组合，并通过明暗主题对比度测试。该业务色不得复用为状态色、波长色或普通控件色。
- 基点、焦平面、主平面、节平面等分析注释色属于光学分析语义色，应集中在命名语义调色板中；不得在结果页局部直接写匿名 RGB。
- 波长颜色不是普通分类色。Fraunhofer F/d/C 约定为蓝、绿、红；该绿色是工程曲线辨识色，不描述为真实视觉黄光。
- 按视场、结构、状态、类别着色时不得复用波长调色板，避免物理含义冲突。
- 文本与背景对比度：正文至少 4.5:1，大字号和图形关键线至少 3:1。禁用态可以更低，但必须仍可辨认。

## 主题包、图标和 Chrome

- 主题必须通过 `ThemeRegistry` 注册完整 `ThemeDefinition`，不得在 `MainWindow`、设置窗口或业务面板中增加主题名称 switch。
- 光域（`Lumen`）使用 Dark 派生变体，采用灰青暗场、灰白文字、暖金主操作及灰蓝选择态；方角、细边框和无阴影由自身 Chrome 表达，复用标准线性图标和用户字体。镜头材料行保留蓝色，不用金色替代数据提示；不得加入没有物理意义的仪表刻度、计数圆环或假进度。已有普通/暗夜主题与默认启动布局不变。
- 运行时切换只能经 `ThemeApplicationService` 完成；不得由面板分别修改 `RequestedThemeVariant`、Fluent 强调色或 Dock 资源。
- 业务界面只使用稳定语义图标名；具体几何由 `ThemeIconResolver` 和当前主题包决定。
- 明亮、暗夜主题继续使用当前 `StandardLucide` 图标；普通亮模式按确认的完整工作台预览使用雾蓝底、独立白色圆角分组，卡片圆角为 6、无投影；暗夜保留既有 Chrome。修改异世界或新增主题不得改变这两套显示。
- 异世界使用从 Game-icons.net 官方仓库筛选并随应用内嵌的 `GameIconsFantasy` SVG 图标包以及旧金锐角 Chrome。图标必须保留上游作者、文件名、固定提交和 CC BY 3.0 署名，不得以本地自绘或自动生成符文替代；边框和纹理属于界面装饰，不得替代波长、状态或分析业务颜色。
- 像素风格使用 Light 派生的亮色 8-bit 色板、零圆角 Chrome、无模糊硬阴影、Farm-Fresh 彩色 32×32 PNG 图标和 `Fusion Pixel 10px Mono zh_hans` 中文像素字体；图标缩放必须使用最近邻插值，点阵与阶梯角标只出现在空白 Chrome，正文、表格和绘图区不得使用抖动纹理或模糊位图缩放。
- 顶部工具栏采用确认的“紧凑横排”：全部命令统一左图标、右文字，下拉箭头仍在文字右侧，不混用上下排版。四套主题共用 18 DIP 图标、6 DIP 图文间距、13 DIP 基准正文及至少 56×36 DIP 的命令命中区；组内间距 2 DIP，组间距 12 DIP，分隔线高 22 DIP、垂直居中且不接收输入，工具栏上下各 6 DIP 留白。文字不换行，不缩小字号挤入窄窗口；超宽时保留原生横向滚动，但横向滚动条采用 `Hidden`，常态、悬停和滚动时均不显示轨道或拖块，也不占用底部高度，不能改为 `Disabled` 而截断命令访问；横向输入和键盘焦点带动的滚动保留，顺序与非序列模式及全部主题一致。放大字体时工具栏自然增高。普通 Light 的可用工具栏图标使用主题蓝、文字保留正常深色，禁用文字和图标仍独立灰显；其他主题沿用自身图标包及颜色。像素主题保留连续浅蓝底面，常态命令无独立卡片边框。
- “MTF 曲线”下拉菜单按傅里叶（FFT）、惠更斯、几何三组排列，在两处组界使用原生水平分隔线。每组保留普通 MTF、离焦 MTF、MTF 随视场变化三项的现有顺序、图标和动作；分隔线不计作命令。
- 撤销/重做继续依据实际文档历史启用；禁用时提供“当前没有可撤销/重做的操作”的可见提示和自动化帮助，启用后清除旧禁用原因。导入、导出、示例下拉及所有命令 ID 不因布局调整合并或删除。
- Ribbon 顶部继续与分类菜单连为一体，不增加左右内缩或上方间隔；Light/Dark 仅下侧两角使用 8 DIP 圆角，命令页内容必须随边框裁切，不能用方形底色盖住弧线。四套主题均在 Ribbon 与工作区之间留 8 DIP，间隙及圆角外露区域使用工作区背景；Isekai/Pixel 保留各自锐角/方角装饰。顺序与非序列模式使用同一框架，切换分类、主题或窗口尺寸不丢失间距。
- 普通 Light 的工具/文档停靠区外轮廓及文档内容框统一使用 **12 DIP 圆角**；系统选项标题上侧同为 12 DIP，下侧保持直线，与下方区域连续连接。裁切通过样式绑定原生控件的实时 `Bounds`，窗口/分栏尺寸变化、新建停靠控件及重置布局时自动更新；切换到其他主题时撤销该样式。标题圆角作用于 `ToolChromeControl` 的实际 `PART_Border`，不能只修改内部设置卡片。保留原生页签模板及其原有 6 DIP 圆角、右侧蓝色选中边、1 DIP 分隔线、菜单/固定/关闭命中区与停靠交互；侧栏宽度、标题高度及 Dark/Isekai/Pixel/Lumen 外观不变。
- Windows/macOS 主窗口采用扩展客户区，左侧显示品牌图标及实时文件标题，右侧标题行提供 216 DIP 紧凑功能搜索。Windows 右侧预留 144 DIP、macOS 左侧预留 96 DIP 给平台窗口按钮；Windows 的最小化、最大化/还原和关闭按钮在原框架命中区内分别显示 22 DIP 的黄、绿、红圆形，保留 45 DIP 宽和框架决定的高度，圆外透明区域同样可点击。基准色固定为 `#FFBD2E`、`#28C840`、`#FF5F57`。圆形采用轻微上亮下深渐变、半透明高光边和公共 Chrome 投影，悬停增强亮度与投影，按下改用更深渐变；原生图标在背景之上单独绘制并绑定深色前景，保持最大化/还原图形更新。状态样式只跨一层模板，通过按钮附加属性绑定到圆形，禁止在窗口装饰 ControlTheme 中串联两次模板选择器。macOS 保留系统自身交通灯，其他平台不套用该覆盖。保留 `WindowDecorations.Full`，拖动、双击、缩放、窗口动作继续由平台/框架处理，搜索区域明确使用 `User` 命中角色。标题栏最小 36 DIP，高字号可自然增高；最大化边缘按 `OffScreenMargin` 避让，全屏隐藏自绘标题占位，退出恢复。Linux 保留原装饰，Ctrl+Q 改用原命令面板。原生多显示器、DPI 和平台手工验收范围见 [当前状态](CURRENT_STATUS.md)，不能以 Headless 渲染替代。
- 普通 Light 的标题与菜单共用横向蓝色渐变，搜索框位于标题行而不是菜单行；分类菜单保留快捷字母、选中背景和键盘焦点，不恢复选中下划线。文档页签的关闭 X 使用与主窗口关闭按钮一致的红色 `#FF5F57`，悬停和按下分别使用 `#E5484D`、`#C9353A`，禁用时使用当前主题禁用色，按钮底色和命中区保持原样；该语义色适用于全部主题。普通与紧凑关闭呈现部件均复用 Dock 原关闭模板、命令和几何，通过填充色绑定避免原本地资源盖住红色，不给其他图标追加描边。Dark/Isekai/Pixel 的标题及搜索使用各自主题资源，既有工具栏、文档区和光学功能不因顶栏改版删减。
- Ctrl+Q 聚焦顶部搜索并全选已有查询；名称、类别和命令 ID 检索直接复用 `ActionManager.Search`，上下键选择、Enter 或单击结果执行、Esc/外部点击关闭。失败仍由原命令错误处理显示，执行中阻止重复触发，成功清空查询后不再自动弹出列表。原 Ctrl+K 命令面板继续可用；全屏或平台未显示搜索框时 Ctrl+Q 也使用命令面板。

- 功能搜索的剪贴板读取失败只取消当前粘贴，保留查询、选区和结果；状态栏给出可重试的非模态提示，不弹出抢焦点的错误窗口。成功后保留原生 TextBox 的选区替换、长度约束和撤销/重做。UI 全局兜底只处理原生剪贴板粘贴调用链中的 COM 异常，其他 UI/COM 错误仍正常暴露。
- 默认打开“文件”页，顺序模式依次提供新建、打开、保存、导入、导出、示例、撤销、重做；Cooke/Tessar 仅在“示例”下拉中显示。撤销/重做依照文档历史启用；非序列模式不显示顺序导入、导出或示例。
- Ribbon、工作区、卡片、控件框、状态栏、对话框和视口必须通过 `ThemeChromeRole` 表达边框语义。装饰绘制使用 `ThemeChromeOverlay`，必须不接收输入且不参与布局测量。
- 公共 Chrome 角色保持稳定的布局契约；普通亮模式侧栏采用独立白色圆角分组，组间露出雾蓝底、间距 6 DIP，取消旧内收底部分隔线。分组容器边距为左/上/右/下 6/4/6/12 DIP；标题保留 35 DIP 高度、整行点击区域，箭头后增加稳定语义图标，点击与展开状态不依赖图标或文案。嵌套视场/波长卡片保留完整细边框，表单标签改为常规字重但不缩字号；侧栏空闲输入轮廓使用柔和蓝灰色，聚焦、悬停、禁用和错误提示不能被覆盖。系统选项右侧滚动条使用 `Hidden`：常态、悬停和滚动时都不显示轨道或拖块，也不占用滚动条列；保留滚轮、键盘和焦点带动的垂直滚动，水平滚动仍禁用，不得改为 `Disabled` 而使下方设置不可达。其他主题沿用自己的分组底色、8 DIP 间距、标签字重和边框；双线、纹理只能由覆盖层绘制。
- 普通亮模式工作区左右各留 5 DIP、底部 6 DIP；镜头编辑器内容不再额外内缩，表面属性栏与镜头表格铺满 Dock 内容框内沿，不保留原左右/底部 6 DIP 的浅色边带。外层 12 DIP 圆角裁切与细边保留。文档页签为雾蓝底栏，选中页白底、蓝色文字，原下沿的蓝色效果改在页签右侧显示（2 DIP）；继续使用 Dock 原生页签背景边框及圆角，不叠加模糊阴影、不修改整个工作区边框。所有状态保留相同右侧占位，切换选中、悬停或禁用不移动标题与关闭按钮；未选中和禁用不显示蓝边。悬停和按下仍有独立浅蓝底色；系统工具页签和 Dark/Isekai/Pixel 不套用此位置调整。镜头表格保留全部列、编辑/排序/冻结列与材料行语义，不按示意图删列；表面属性标题上下各留 7 DIP。状态栏使用轻微浅色渐变，指标最小宽度为 96 DIP（其他主题 128 DIP），数据与状态继续来自真实工程快照，不复制预览中的数值或“就绪”灯。
- 普通 Light 文档页签与内容之间采用已确认的“浅色细线”：仅保留原内容框顶部 1 DIP 的 `Divider` 淡蓝灰边（`#DCE5F2`），关闭 Dock 额外的 2 DIP 全宽激活色带及其占位，不再叠加第二条线。激活、悬停、调整窗口和跨主题切换后返回 Light 均不能恢复蓝色粗线；页签右侧 2 DIP 蓝色选中边、内容框其余边缘和原生交互保留，其他主题不受此规则影响。
- `System` 是跟随系统的选择代理，不维护复制的独立调色板；控件必须从 `ActualThemeVariant` 解析实际视觉包。
- 新主题的颜色、图标和边框必须作为同一个主题包注册；不得把新主题资产追加到异世界类或普通主题资源中。
- 公司标识、启动页品牌、物理波长/光线色、工程图标准色、算法固定色标和导出版式不跟随界面主题改色。
- 完整扩展流程见 [主题包开发规范](THEME_PACKAGES.md)。

## 亮模式与数字格式

- 普通亮模式采用“正蓝 × 雾蓝”：标题/菜单栏使用 `#1876E9 → #1455B8` 横向渐变，常态菜单透明以露出连续底色，取消标题行下方分隔线；菜单悬停 `#2864C3`、按下/展开 `#235AB3`，标题文字 `#FFFFFF`、菜单文字 `#F5F8FF`。当前菜单用已有选中背景区分、不显示下划线。顶部检索使用半透明蓝底、亮色文字与占位提示，聚焦保留白色可见边框。主区/普通输入白色，工具栏为 `#FFFFFF → #F8FBFF` 纵向浅渐变；工作区 `#F0F5FC`、侧栏外沿 `#F5F8FE`、分组白底、表头 `#EEF4FC`、分隔线 `#DCE5F2`。普通文本 `#22334C`，次要文本 `#5C6F8A`，普通控件边框 `#8297B6`；侧栏空闲输入轮廓为 `#C6D5EB`。背景、文字、边框 token 集中在 `BlueThemeTokens`，主要按钮背景与焦点边框使用各自变量。浅色区域强调文字三态仍为 `#2446F0`、`#1C3ED8`、`#1734BB`，用于分组标题、活动页签、选中菜单/视场项及对应箭头；释放恢复悬停，移出恢复默认，禁用色沿用原值。
- 普通按钮常态/悬停/按下为白色 / `#EAF1FF` / `#CDDDFA`，松开恢复悬停、移开恢复默认。主要按钮品牌蓝 `#2F65CC`，悬停 `#2554AF`，按下 `#1D448F`。只有 Toggle/Tab/选择模型保留选中状态。
- 镜头数据中材料列非空的所有行在普通 Light 下持续使用材料蓝底 `#EAF1FF`，悬停 `#D5E3FC`；这是材料语义，不是行选择。沿用 `HasOpticalMaterial` / `MaterialDisplay` 判定，Air 显示为空；材料清空/恢复、取消、撤销、刷新、文件切换与行复用必须正确更新。选中、当前单元格、禁用和错误继续使用下述状态规则。此要求已保存为根 `AGENTS.md` 的长期项目偏好。
- 选中/选中悬停/选中按下为 `#DFEAFE` / `#D5E3FC` / `#B9CFF5`，输入选区为 `#BED3FA` 配深色字；2 DIP 蓝色焦点独立于选中。错误边框 `#AD3F3B` 优先，聚焦时额外保留蓝色外圈。禁用 `#F0F3F8` 配 `#9BA9BF`，不得被悬停或选中覆盖。
- 主题资源覆盖 Fluent/Dock 原生模板，局部状态由 `BlueThemeStyles` 处理；仅精确匹配普通 Light，不影响 Light 派生的 Pixel。系统跟随模式在实际主题变化时同步根资源。完整规则与实测边界见 [蓝色主题记录](BLUE_THEME_2026-09-27.md)。
- 默认数字显示最多保留 **3 位小数**，科学计数法尾数同样遵守此设置；不强制补零。新设置、缺失该字段的旧设置和“恢复默认”均使用 3，已有显式自定义位数仍可保存。显示舍入不改变 Core 数值或 STAROPT 保存精度。
- 镜头数据中的“机械半直径”与表面属性“绘图”中的相应摘要必须通过统一 `NumericDisplayFormatter` 显示，位数变更后同步刷新。机械半直径保持只读及按原始数值排序，不能用格式化字符串替代原始数据。实现与验证见 [机械半直径显示精度修复](MECHANICAL_PRECISION_2026-09-27.md)。

二维光学布局中的镜片曲面、外轮廓和上下连接边统一使用固定 2 DIP 黑色实线，缩放不改变屏幕线宽；该工程轮廓不采用主题蓝色。镜片填充、光线颜色、光阑与参考面以及选中表面的橙色提示保留各自语义。此规则仅适用于二维布局，三维与实体模型继续使用原有线条。

## 字体

文档栏中“镜头数据”“二维视图”及同类页签标题统一使用 **Bold（700）** 字重，选中和未选中状态、各主题保持一致。通过原生文档页签的标题呈现部件继承字重，继续使用设置中的字体、字号和斜体；关闭按钮、内容正文、Ribbon 及分析页内部标签不随此规则加粗。

产品默认字体已内嵌：普通主题的拉丁界面使用 DM Sans，中文回退到思源黑体 SC；镜头数值单元格、数值输入、状态读数和数值文本报告使用 JetBrains Mono，中文仍回退到思源黑体。通过 `ProductFonts` 和动态数值字体资源选择角色，不依赖本机是否安装这些字体。字体资源集合按家族隔离，避免符号意外选到另一角色的字体。用户显式设置优先，像素主题默认继续使用 Fusion Pixel；工程图继续使用其既有 Noto 字体。来源、分发许可和设置行为见[字体方案](TYPOGRAPHY.md)。

默认 UI 字号以用户设置的基础字号为准，默认值为 13。普通控件、面板和分析页不得写死不缩放的视觉字号；应使用公共样式或 `DisplayTypography` 的命名字号 token。自绘图表使用 `DisplayTypography.Scale` 或图表专用字号常量。

建议层级：

| 层级 | Token | 默认字号 | 用途 |
| --- | --- | ---: | --- |
| 启动画面标题 | `DisplayTypography.SplashTitle` | 29 | 启动画面产品名 |
| 空状态符号 | `DisplayTypography.EmptyStateIcon` | 27 | 空状态大号符号文字 |
| 页面标题 | `DisplayTypography.PageTitle` | 22 | 向导页、独立窗口主标题 |
| 大标题 | `DisplayTypography.LargeTitle` | 20 | 数据库页面标题 |
| 窗口标题 | `DisplayTypography.WindowTitle` | 18 | 对话框重点数值、材料标题 |
| 空状态标题 | `DisplayTypography.EmptyStateTitle` | 17 | 错误页、空状态标题 |
| 分区标题 | `DisplayTypography.SectionTitle` | 16 | 面板分区、对话框分组 |
| 卡片标题 | `DisplayTypography.CardTitle` | 14 | 结果页底部标题、工具卡片标题 |
| 正文 | `DisplayTypography.Body` | 13 | 普通标签、输入、表格正文 |
| 小正文 | `DisplayTypography.BodySmall` | 12 | 分组标签、Zemax 风格摘要 |

约束：

- 分析结果页底部标签“绘图 / 数据 / 文本”使用紧凑页签样式，不允许出现接近标题字号的巨大页签。
- 图表内坐标轴、图例和标题必须跟随统一图表字号，不得因 `Viewbox` 或局部画布缩放而放大。
- `monospace` 只用于数值报告、Zemax 风格文本输出、代码/日志和固定列数据，不用于普通导航和设置项。
- 中英文混排保留行业通用缩写：FFT、PSF、MTF、RMS、Zernike、Jones、Y-Ybar、vs. 等不得随意汉化。
- 普通 UI 源码不得出现 `FontSize = 12` 这类数字字面量；必须使用命名 token。该规则由 `AppUiFontSizesUseTypographyTokens` 契约测试保护。

## 间距与几何

间距采用 4 点网格：4、8、12、16、24、32。新代码不得随意引入 7、9、13、18、23 等一次性间距，除非是算法图形或标准文档版式。

组件几何：

| 项 | 规范 |
| --- | --- |
| 普通输入/按钮高度 | 32 |
| 表格行 / 表头高度 | 36 / 34 |
| 工具栏图标按钮点击区 | 32 起，优先 36 |
| 控件圆角 | 普通/暗夜为 5；其它主题由 `ControlFrame` Chrome 角色声明 |
| 卡片圆角 | 普通为 6、暗夜为 8，普通侧栏分组同为 6；其它主题由卡片 Chrome 角色声明 |
| 停靠区圆角 | 普通 Light 外轮廓与文档内容框为 12 DIP，标题上角同为 12；原生文档页签圆角仍为 6 |
| 普通边框 | 普通/暗夜为 1；其它主题由对应 Chrome 角色声明 |
| 卡片阴影 | 统一使用主题 Chrome 配置，不新增局部阴影参数 |

上述控件与表格尺寸必须从 `UiDensity` 读取；普通 UI 不得为 `DataGrid.RowHeight` 或 `ColumnHeaderHeight` 新增数字字面量。工具内确有不同密度时，应先增加具名语义令牌并说明使用边界。

约束：

- 普通设置卡片、工具卡片、状态卡片、预览卡片和可编辑表面必须通过 `SettingsPanelChrome.ApplySurfaceCardStyle`、`SettingsPanelChrome.ApplyCardStyle` 或等价公共组件获得卡片圆角、边框、主题背景和阴影。
- 覆盖在分析图或查看器上的设置面板必须使用 `SettingsOverlaySurface` 主题背景（普通亮模式为不透明白色，其他主题保留半透明）；不得通过控件整体 `Opacity` 实现半透明，以免输入框和文字一起变灰。
- 列表框、预览框、输入框外壳等控件框架必须使用 `SettingsPanelChrome.ApplyControlFrameStyle` 或全局控件样式；普通/暗夜圆角保持 5，独立主题从 `ControlFrame` Chrome 角色读取。
- 不允许同类卡片在不同面板使用不同圆角、阴影和内边距；普通 UI 源码不得新增局部 `BoxShadows.Parse`。
- 允许例外必须有明确语义：图例色标/采样点属于数据标记，Splash、Dock 文档 pill 属于外壳装饰，导出文档和标准图纸属于独立版式。
- 底部分析信息区高度、分隔线、品牌区和文件区必须统一；同一组分析页面不得出现不同高度。
- 图标按钮必须有 tooltip 和自动化名称；只有图标无法表达的命令才使用图标加文字。

## 布局

普通页面使用 `Auto`、`*`、`DockPanel`、`Grid`、`WrapPanel`、滚动容器和容器相对尺寸。固定尺寸只允许用于：

- 稳定图标、色块、光标、拖拽柄；
- 明确有标准尺寸的导出文档、工程图和截图对标画布；
- 最小可用窗口尺寸；
- 对话框初始尺寸；
- 分析结果底部信息区这类产品级固定 chrome；
- 方形二维空间图的正方形约束。

查看器和分析设置浮层的字段布局必须响应容器宽度。两列设置应使用 `ResponsiveSettingsGrid` 或等价断点容器，在窄于400px时保持原阅读顺序重排为单列，不得靠固定字段宽度后被父容器裁切。

库存匹配与制图页保留原面板划分，在短视口中用 `ScrollableHeaderGrid` 限制顶部区的测量高度并局部滚动，给结果/预览留出空间。表格不得用大 `MinHeight` 反向溢出到说明区；边界裁剪不能替代正确测量。制图参数滚动条须占用实际宽度，不能悬浮遮住输入框右边框。原制图左右分栏宽度、窄屏断点与分栏比例保持不变。

Fluent 表头排序图标按内容占位，未排序不保留空白的 32 DIP 排序列。长表头和标准文本单元格采用省略号及完整提示；匹配/库存表的 EFL、EPD 和相对偏差单位单独测量，列变窄时优先保留单位。制图长参数使用短名称、完整提示及独立单位行，允许标签自然增高，不缩小字号。实现与验证边界见 [容器测量和文本适配修复](PANEL_CONTENT_LAYOUT_2026-09-27.md)。

禁止：

- 用 `Viewbox` 包住含文字的 UI 来适配窗口。
- 给普通分析子画布写死 840x290、固定列数或固定高度。
- 在 Dock 文档区强制大 `MinWidth` 导致窄分栏不可用。
- 图表外层和内层背景不一致。

设置布局：

- 分析页和查看器设置默认使用左上浮层卡片，不随主窗口宽度横向铺满。
- 分析页设置卡片的左边缘必须与工具栏“设置”按钮对齐，并从工具栏下方开始；不得用 `Stretch + MaxWidth` 形成视觉居中。
- 设置项按两列字段阅读，底部保留自动应用、应用、确定/取消或重置等操作区。
- 参数数量较少时，卡片宽度由内容决定；不得用横向 `WrapPanel` 把字段从左到右排到窗口最右侧。
- 双栏文档使用容器断点：材料、目录和详情页在可用宽度不足时改为上下排列，不能用横向滚动代替重排。
- 含长列表或数据表的主从页面必须在有限视口内测量：宽布局的主列表与详情分别滚动，窄布局按可用高度分配上下视口。不得把整个双栏容器放入纵向滚动区，使列表条目数量决定详情画布高度；否则会破坏列表虚拟化并把详情推到数据末尾。
- 主窗口支持 640px 最小宽度；Ribbon 可横向滚动，Dock 文档不得设置 500px 及以上的内容 `MinWidth`。

分析图布局：

- 点列图、全视场点列图、矩阵点列图、结构矩阵点列图、光瞳/光线 fan、干涉图等二维空间图应保持方形绘图区。
- 标准点列图的每个视场标题随其方形画布定位，紧邻画布上方；不能固定在大网格单元的顶部而让图在剩余高度中居中，造成大块空白。宽度足够时保留视场对称排布，窄窗口按完整视场卡片重排；方形画布和坐标轴保留可读的最小尺寸，长标题换行；窗口缩放、停靠和整页 PNG 渲染均使用同一标题位置。此规则不改变矩阵点列图的共享行列标题或 fan 布局。
- 色焦移是曲线图，不强制方形。
- 塞德尔系数图的柱形和图例共用固定语义配色：球差 `#1F77B4`（蓝）、彗差 `#2CA02C`（绿）、像散 `#D62728`（红）、场曲 `#17BECF`（青）、畸变 `#9467BD`（紫）、轴上色差 `#BCBD22`（黄绿）、垂轴色差 `#FF7F0E`（橙）。各主题保持同一系数颜色，图面背景、坐标、网格及文字继续使用主题资源。
- 玻璃材质配色试用仅限“实体模型”视图：同一场景中相同玻璃名共用颜色，不同玻璃名分别着色；实体、透明、线框和剖切沿用同一映射。图例在视口下方独立区域显示色块与材料原名，窄窗口换行，过多条目在有限高度内纵向滚动，不遮挡相机控制或光路。Air 和空材料不入图例。颜色仅用于识别，不表示玻璃的实际透射光谱；三维布局、二维图和光线配色维持原行为。
- 实体模型默认光线宽 0.7 DIP，每视场/波长组使用 21 条共享 Core 光瞳采样；“细／标准／粗”分别为 0.7／1.0／1.5 DIP，取消额外线宽放大。初始化和重置使用同一组默认值，保留人工调整；二维图和三维布局原有光线数量、宽度与采样规则不变。
- 三维布局与实体模型均只保留左下方向示意，移除右下方形微型三轴及边框。左下标出红 X、绿 Y、蓝 Z，轴端与场景共用同一视角投影，保留投影缩短和前后遮挡顺序。标签随界面字号缩放，沿视线的轴仍保留字母提示，重合文字错开。仅相机角度影响方向，平移、缩放和显示 Y 拉伸不参与。
- 实体模型以半透明中性色和清晰虚线边界显示实际像面参考；通过共享 Core 与场景 DTO 的显式像面标记识别，使用已有真实几何和全局变换，不从名称猜测。未选中、隐藏光线、实体、透明、线框及剖切均可见，参考不随镜片剖切裁掉；绘制在光线和玻璃之前，不作为玻璃材料加入图例，不改变处方、追迹或三维布局绘制。
- 三维布局与实体模型共用图标＋可见本地化文字的视角工具条，立方体所指示的视面使用较深的主题强调色，与其余中性面明确区分；当前匹配预设由实际相机角度决定，以选中背景和 2 DIP 边框突出，自由旋转后清除选中。保留原生焦点与键盘操作，“适配”保持方向。工具条使用与顶部控件一致的圆角面板，悬浮于画布内下方，左右各保留 72 DIP、下方保留 48 DIP，为坐标示意与比例尺留出间距；窄窗自动换行，字号增大时高度自适应。实体模型材质图例仍在视口下方，视口最小高度继续分别为实体模型 160 DIP、三维布局 240 DIP。
- 二维图、三维布局及实体模型共用设置/刷新旁的中性相机导出入口，保存 PNG。绘制沿用实时场景与相机状态，不重新追迹；导出时排除设置、导航和焦点装饰，完整展开材质图例并使元数据换行，保留已显示的比例尺及过期光线警告。先捕获画面再打开保存对话框，使用有大小边界的原子写入；空场景、更新中、过期及导出中仅禁用该按钮，提供提示与自动化帮助，周边控件保持可读。
- 带勾选框的波长、视场和结构系列图例共用绘图页右上侧的独立纵向栏，可读内容页的上、右边距均为 12 DIP；单图、点列/离焦/矩阵与成对 fan 使用相同布局，不再按各分析的底部/居中标志或矩阵专用偏移放置。图例不覆盖坐标及曲线；长标签在有限宽度的条目内换行；内容放不下时原生滚动，不缩小整页字号，勾选过滤及完整 PNG 导出保留。热图/表面图的数值色标及报告中的波长说明保留各自语义。
- 取消图例勾选只隐藏对应曲线/散点，不删除原始绘图依据。全部取消时仍绘制图框、类型化坐标和单位、刻度、网格及零线，并保留当前平移/缩放；单图、多子图和矩阵单元格遵循相同行为，PNG 导出同样保留空图框。重新勾选恢复原系列；真正清空或更换分析结果时清除旧坐标依据和视图状态。
- 所有 MTF 曲线族（傅里叶、惠更斯、几何、采样及离焦/随视场扫描）的命名系列均可独立勾选，子午、弧矢及衍射极限参考线分别控制。普通单图/多子图原来的静态命名图例统一使用右上侧勾选栏，以结果内曲线位置区分重复标签；既有显式波长/结构分组继续使用原身份，未命名参考线保持可见，垂轴色差静态图例仍不显示。过滤仅改变绘制，不重算 MTF 或修改数据/文本、颜色、线型和坐标。
- 光线像差和瞳孔像差按视场分组，X/Y 或 P_x/P_y 成对放在同一视场组内，不按方向拆成两列全局排列。每对的两个方形画布向中线靠拢，保留原有图框尺寸、轴标题/刻度留白和视场组居中；其他方形子图继续沿用默认居中布局。
- 离焦点列图、矩阵点列图和结构矩阵点列图的多个波长应在同一个子图内叠加，图例说明波长，不拆成互相独立的小图。
- 矩阵点列图和结构矩阵点列图不在视场标签旁额外显示脱离图框的竖排共用尺度数字（如 `100.000`）。图框实际范围、坐标轴及单位、视场/结构标题、波长图例与尺度设置保持原语义。
- 垂轴色差图不显示“最短的-最长的”和“艾里斑”等静态系列图例，也不为其保留右侧空栏；曲线、艾里斑参考线、坐标和数据/文本保留。多波长或多结构结果的可勾选图例继续沿用统一图例栏。
- 波前图的“显示为”提供“表面”“等高线”和“二维热力图”，默认仍为“表面”。二维热力图复用既有平面伪彩色绘制，颜色表示原始波前值，保留 X/Y 光瞳坐标、出瞳形状/几何投影、波单位色标及完整 PNG 导出；切换显示方式不改变波前样本、PV 或 RMS。
- 相对照度图的横轴采用扫描点的实际 X 最小值和最大值，不额外增加两端留白。例如 0°～14° 的扫描直接显示为 0°～14°，负方向扫描保持实际负值范围；横轴角度/高度单位、曲线、纵轴范围及图例交互保留。其它分析沿用各自的范围与留白规则。

## 控件与输入

- 每个输入项必须有可见标签；自动化层面应能从标签定位到输入控件。
- 数值输入默认应提供 spinner 或等价微调能力；只有密集表格、只读单元格或明确的紧凑模式可以关闭 spinner。
- 表格数值列右对齐，单位在列标题或旁侧标签中说明，不在每个单元格重复。
- 镜头数据表的“材料”列内容和编辑框同样右对齐，列标题继续居中，各主题一致。材料名保留界面字体及原文本绑定，不能归为数值列；非空材料行蓝底、Air 空显示、提交/取消/撤销与列宽调整沿用原规则。
- 镜头表曲率、厚度和净口径的非法输入保留原文、显示验证边框和完整错误提示；不得提交处方或发布“表面数据已更新”。修正后失焦提交，Escape 放弃本次输入。
- 可复用表面类型单元格必须绑定当前行的角色与面型：物面、光阑、像面角色靠左，标准面等实际面型名称靠右，两侧保留各 8 DIP 内边距，所有主题一致。普通行不显示“普通面”，也不为角色预留宽度；面型随剩余列宽伸展，过窄时省略并以提示保留全名，不与左侧角色重叠。拖动列宽、滚动、展开属性及文件切换后，两类文本和材料蓝底均跟随实际数据。
- 标准球面/圆锥与平面在镜头表、类型选择器及属性摘要中统一显示“标准面”，不提供独立“平面”选项。由曲率半径的有限/无限值表达曲面/平面；应用类型不得为无穷半径生成默认有限半径。特殊面型及旧几何存储保持各自语义。
- 禁用控件必须说明原因，不能保留“可选但无效”的参数。
- 长耗时操作必须使用 `OperationStatusBar` 或等价公共组件表达运行状态，不得在各页面只写局部状态文本。
- 长耗时操作超过约 500 ms 时应显示进行中状态；可能超过 2 秒的操作应提供取消路径或明确说明不可取消。
- 运行状态语义固定为执行中、可取消、失败、已同步、结果过期；失败和过期必须保留可读原因，不允许只显示空白或单独图标。

## 分析结果页

分析结果页统一由以下区域组成：

1. 顶部工具栏：设置、刷新、复制文本、导出文本、同步状态。
2. 中央图形区：使用 `PlotBackground`，图表标题、轴、图例和提示统一字号与颜色。
3. 底部信息区：宽布局左侧摘要、右侧品牌/文件信息，窄布局上下排列；132 DIP 为共同最小高度，内容可自然增高。
4. 底部页签：绘图、数据、文本，使用紧凑字号和统一活动下划线。

约束：

- 公司品牌区统一使用 `CompanyLogo.svg` 的真实矢量轮廓，由共享 `CompanyLogoControl` 按主题配色；工程图 PDF 直接绘制同一资源的路径。不得嵌入 PNG 冒充 SVG，或用普通字体模拟正式字标；出版商、说明和文件元数据中的品牌文字仍使用文本。
- 文件名、来源和版本信息使用同一字号、颜色和行距。
- 同一分析家族共用底部信息区的最小高度、字体颜色、分隔线和内边距；实际高度由摘要、完整文件名、指标和字号决定，不能固定裁切。
- 失败状态必须保留用户能理解的错误原因，并避免显示空白图。
- 解锁时核对显示结果的文档修订；过期结果继续显示“结果已过期，请同步”，显式同步成功后才能显示“已同步”。锁定期间文档变化也须提示过期；切换文件立即清空旧结果。
- 所有分析绘图页先按可用尺寸排布，文字按配置字号显示，不再整页缩小。普通子图和成对 fan 在窄区减少列数；矩阵/离焦图保留行列身份、每格最小画布和轴标题，空间不足时由页内原生横/纵滚动访问，不增大 Dock 文档的最小宽度。
- 图标题、坐标轴留白与专用热图/表面图的几何边距跟随图表字号；刻度按实际字形宽高减少重叠标签，保留网格和数据范围；塞德尔图例按有限宽度换行。底部摘要、文件说明和逐视场指标换行/重排，宽/窄断点随字号调整，基点表格按内容行高显示，瞳孔像差说明同样自然增高。系数报告保留可选文本与双向滚动。
- 分析 PNG 导出当前内容页的完整尺寸，包含滚动区域外的图和图注，排除工具栏、设置浮层、滚动条及页签；保留勾选、交互缩放和相机状态，导出不改变当前滚动位置。分配位图前限制单边 32,768 像素、总计 33,554,432 像素，超限明确提示减少子图；继续使用大小受限的原子写入。该上限不改变采样或计算结果。
- 通用结果页保留“绘图 / 数据 / 文本”的顺序；有绘图点时默认绘图，否则有表格/摘要行时默认数据，仅有报告正文时默认文本。专用报告/场景控件仍由 `AnalysisPresentationKind` 分派，不按本地化名称判断。

## 可访问性

最低要求：

- 所有按钮、菜单、图表、绘图画布、可滚动区域和可编辑控件必须设置自动化名称。
- 自绘画布如果支持鼠标滚轮缩放、拖拽平移、双击复位，也必须提供键盘等价操作。
- 焦点框必须可见，不能被透明背景或自绘层遮挡。
- 图例不能只靠颜色区分，至少结合形状、文本或序号。
- 错误、警告和成功状态不能只靠颜色表达。

当前公共实现：

- 自绘交互控件使用 `InteractiveCanvasAutomationPeer`，并通过 `AutomationProperties.Name` 和 `HelpText` 发布语义。
- 自绘图表统一保留 `Home` 重置、`+/-` 缩放和方向键导航；3D 内容的 `Shift+方向键` 表示平移。
- Ribbon 命令使用动作 ID 作为 Automation ID；分析参数使用参数键作为 Automation ID，显示文本只用于自动化名称。
- `ResponsiveTwoPaneGrid` 是 Dock 双栏文档的公共断点容器；宽度不足时第二栏移动到第 3 行。

## 实验室页面组织（已实现）

镀膜设计、光学装调和相机成像共用窗口内的展示组件：顶部标题、简短操作顺序、来源及换行命令区；左侧按用途分组的参数卡；右侧独立结果卡；底部真实状态。使用共享主题的工作区、卡片、文字和强调色令牌，支持主题和字体设置；仅执行主动作使用 `accent`。参数侧栏隐藏纵向滚动轨道，保留滚轮、键盘及焦点滚动，不横向滚动、不缩小字号。长标题与按钮换行，结果区按实际宽度重排或滚动。AutoLens 不采用本次改版。

光学装调按测量设置、测量头、叉丝与探测面分组；坐标说明可展开。共轭位置表和返回叉丝像在宽窗口并排，窄窗口上下排列，原探测面毫米标尺保持。相机以独立图卡展示阶段，在结果区宽度 880/550 DIP 处切换为三/二/一列；空图卡提供运行提示，真实指标出现后再显示指标卡。布局不得改变输入、默认值、计算、取消、修订失效或保存保护。实际截图及验证边界见[实验室界面改版记录](LABORATORY_PRESENTATION_2026-10-24.md)。

## 相机成像实验室界面适用范围

相机成像实验室是显式打开的自有窗口，计算主动作使用 `accent`，参数区独立纵向滚动；阶段图和 A/B 图在窄窗减少列数。源图/光学图、满阱电子图、ADC RAW 和最终 ISP 图需明确区分标尺，不能逐图归一化掩盖曝光或饱和。默认参数必须标为通用实验模型；无噪声与 A/B 对照保留各自参数、源图和镜头修订。变更输入清除当前结果，切换镜头/模式清除全部旧结果，后台任务按代次与修订提交。范围见[相机成像仿真](CAMERA_IMAGING_LAB.md)。

传感器文件卡提供 JSON 参数导入/保存及绝对 QE CSV 导入/移除。完整验证成功后才更新，导入成功清除 B 并保留 A，失败保留当前参数、曲线及 A/B。名称、来源和文件指纹随每个结果冻结，不把导入数据标成已核实测量。曲线启用时只禁用固定 QE 输入并提供原因，移除后恢复原固定值；其余标签和说明保持可读。光谱响应页使用类型化的 nm 波长轴、无量纲 QE 轴和固定 0–1 纵轴，三条曲线的独立复选图例位于共用右上角区域，隐藏曲线保留原坐标及视图。

光谱模型显式区分默认三波段与连续积分；切换保留 A 和已导入曲线，仅清除当前 B。光源与反射率卡提供独立 CSV 导入及范围/最大区间，连续模式缺文件或覆盖不足时解释禁用运行；固定 QE 和每波段辐照度分别解释其无效条件，不禁用周围标签。光源与场景页分开显示绝对 W/m²/nm 和 0–1 反射率，使用类型化 nm 横轴与各自纵轴、右上独立显示复选框，禁止为比较而峰值归一化。明确标明输入图片为单材质灰度空间图样、光源为理想白目标像面标定量、光学预览为积分能量传递而非 RGB 真彩色；A/B 元数据必须区分模型、光源/反射率、范围和实际节点。

## 镀膜实验室界面适用范围

内置镀膜 UI 在主程序进程和程序集中运行，直接共享主题动态资源、控件样式、标题栏、`UiDensity` 与数值格式；显示设置由同一宿主管理，不再使用独立 App 或仅启动时读取的设置副本。模块实验状态不隐式访问当前镜头优化事务。左栏 256 DIP（240–280），标签与编辑器同排、只纵向滚动；工作区在窄/矮窗口滚动，膜层工具按钮自动换行。窗口最小 820×640 DIP，已有控件尺寸用例覆盖该尺寸及 820×900、1200×900；无头渲染不能替代实机桌面验收。

默认主动作是生成膜系和优化；设计目标、介质与膜料、膜层处方及光谱分卡组织，逐项达标摘要位于默认折叠的“指标与公差”，高级设置折叠。材料管理窗口同样区分元数据、n/k 表和命令区。材料搜索、厚度编辑及固定变量标记必须保留键盘操作；显示舍入不得改变底层厚度。输入变化同步清除旧结果，后台任务须按输入代次提交。五主题、材料编辑和 macOS 原生走查范围见[镀膜验收](../validation/coating/README.md)。主程序菜单无下划线、镜头数据材料行蓝底等既有规范继续适用于正式 App。
