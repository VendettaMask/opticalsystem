# UI 设计规范

状态：当前规范。

适用范围：`src/OptilandWorkbench.App` 中所有 Avalonia 桌面界面、Dock 工作区、Ribbon、编辑器、分析结果、报告页、对话框、预览器和制造图纸 UI。导出的工程图、PDF、外部标准截图对标可以有独立版式，但必须在对应文档中说明。

本文是产品 UI 的稳定约束。历史问题记录见 [UI 设计走查记录](UI_DESIGN_REVIEW.md)，当前不符合项见 [UI 符合性审计](UI_CONFORMANCE_AUDIT_2026-08-04.md)。

## 设计原则

1. 光学数据优先。界面应服务镜头参数、图形分析、制造数据和误差判断，避免装饰性大卡片、营销式标题和无意义说明文字。
2. 同一语义只允许一种表现。主题色、文本层级、按钮状态、图表背景、分析页底部信息区和品牌区应来自公共资源或公共组件。
3. 响应式优先，固定尺寸例外化。Dock 文档区会被分栏、浮动和恢复旧会话压缩，普通页面不得依赖写死宽高才能可用。
4. 主题完整。明亮、暗夜和异世界主题必须同时可读；除物理波长、工程图标准色和导出文档外，不直接写界面颜色。
5. 可访问性是功能契约。可点击、可编辑、可滚动、可选择的控件必须有键盘路径、焦点反馈、自动化名称和可理解的禁用/错误状态。

## 颜色

所有普通 UI 颜色必须通过 `ThemeResourceBindings` 或由它派生的局部资源绑定。品牌图、主题相关位图和其它非画刷资产使用 `ThemeAssetBindings`，不得放入画刷资源表。

核心色彩语义：

| 语义 | 用途 |
| --- | --- |
| `Surface` | 主界面和普通内容背景 |
| `SubtleSurface` | 次级区域、分隔区、状态栏、轻量容器 |
| `SettingsSurface` | 设置卡片、参数卡片和可编辑面板背景 |
| `SettingsOverlaySurface` | 覆盖在图形区上方的半透明设置浮层背景 |
| `Workspace` | Dock 工作区底色 |
| `Border` | 普通边框和分隔线 |
| `TextPrimary` | 主文本、标题、坐标轴 |
| `TextSecondary` | 次级文本、表格辅助信息 |
| `TextMuted` | 说明、时间戳、低权重元数据 |
| `TextDisabled` | 禁用文本 |
| `Accent` | 当前选择、主操作、活动标签 |
| `PlotBackground` | 分析图页面和图内绘图区背景 |
| `SceneBackground` | 二维/三维查看器背景 |

约束：

- 明亮主题下分析页外层和绘图区必须一致，不允许出现“页面偏灰、图内纯白”的割裂。
- `Brushes.White`、`Brushes.LightGray`、`Color.FromRgb` 等硬编码只能用于物理/工程语义：波长颜色、光线颜色、制造图纸标准线色、导出图像画布、算法数据可视化的固定色标。其它场景必须抽成主题资源。
- 普通窗口、面板、工具栏、状态栏、分隔线、说明文字和表格行前景色不得直接使用白/灰/RGB 字面量；应绑定 `Surface`、`PlotBackground`、`Border`、`TextSecondary`、`TextMuted`、`TextError` 等主题资源。
- 分析结果表格的业务行色使用主题资源，例如 `AnalysisRealRayRowBackground/Foreground` 和 `AnalysisParaxialRayRowBackground/Foreground`，必须同时覆盖明亮、暗夜和异世界主题。
- Zemax 评价函数行色属于业务分类色，不直接散落在面板里；统一由 `MeritOperandRowPalette` 输出背景/前景组合，并通过明暗主题对比度测试。该业务色不得复用为状态色、波长色或普通控件色。
- 基点、焦平面、主平面、节平面等分析注释色属于光学分析语义色，应集中在命名语义调色板中；不得在结果页局部直接写匿名 RGB。
- 波长颜色不是普通分类色。Fraunhofer F/d/C 约定为蓝、绿、红；该绿色是工程曲线辨识色，不描述为真实视觉黄光。
- 按视场、结构、状态、类别着色时不得复用波长调色板，避免物理含义冲突。
- 文本与背景对比度：正文至少 4.5:1，大字号和图形关键线至少 3:1。禁用态可以更低，但必须仍可辨认。

## 字体

默认 UI 字号以用户设置的基础字号为准，默认值为 13。普通控件、面板和分析页不得写死不缩放的视觉字号；应使用公共样式或 `DisplayTypography` 的命名字号 token。自绘图表使用 `DisplayTypography.Scale` 或图表专用字号常量。

建议层级：

| 层级 | Token | 默认字号 | 用途 |
| --- | --- | ---: | --- |
| 启动画面标题 | `DisplayTypography.SplashTitle` | 29 | 启动画面产品名 |
| 空状态符号 | `DisplayTypography.EmptyStateIcon` | 27 | 空状态大号符号文字 |
| 页面标题 | `DisplayTypography.PageTitle` | 22 | 向导页、独立窗口主标题 |
| 大标题 | `DisplayTypography.LargeTitle` | 20 | 数据库页面标题 |
| 窗口标题 | `DisplayTypography.WindowTitle` | 18 | 对话框重点数值、材料标题 |
| 空状态标题 | `DisplayTypography.EmptyStateTitle` | 17 | 错误页、空状态标题 |
| 分区标题 | `DisplayTypography.SectionTitle` | 16 | 面板分区、对话框分组 |
| 卡片标题 | `DisplayTypography.CardTitle` | 14 | 结果页底部标题、工具卡片标题 |
| 正文 | `DisplayTypography.Body` | 13 | 普通标签、输入、表格正文 |
| 小正文 | `DisplayTypography.BodySmall` | 12 | 分组标签、Zemax 风格摘要 |
| 紧凑正文 | `DisplayTypography.CompactBody` | 11.5 | 分析结果元数据、图例、状态摘要 |
| Ribbon 文本 | `DisplayTypography.RibbonText` | 11 | Ribbon 命令、紧凑提示 |
| 标注 | `DisplayTypography.Caption` | 10.5 | 时间戳、低权重说明、图内辅助文字 |
| 微文案 | `DisplayTypography.Micro` | 10 | 折叠摘要等极低权重信息 |

约束：

- 分析结果页底部标签“绘图 / 数据 / 文本”使用紧凑页签样式，不允许出现接近标题字号的巨大页签。
- 图表内坐标轴、图例和标题必须跟随统一图表字号，不得因 `Viewbox` 或局部画布缩放而放大。
- `monospace` 只用于数值报告、Zemax 风格文本输出、代码/日志和固定列数据，不用于普通导航和设置项。
- 中英文混排保留行业通用缩写：FFT、PSF、MTF、RMS、Zernike、Jones、Y-Ybar、vs. 等不得随意汉化。
- 普通 UI 源码不得出现 `FontSize = 12` 这类数字字面量；必须使用命名 token。该规则由 `AppUiFontSizesUseTypographyTokens` 契约测试保护。

## 间距与几何

间距采用 4 点网格：4、8、12、16、24、32。新代码不得随意引入 7、9、13、18、23 等一次性间距，除非是算法图形或标准文档版式。

组件几何：

| 项 | 规范 |
| --- | --- |
| 普通输入/按钮高度 | 30 |
| 紧凑表格控件高度 | 28 |
| 工具栏图标按钮点击区 | 32 起，优先 36 |
| 控件圆角 | 5 |
| 卡片圆角 | 8 |
| 普通边框 | 1 |
| 卡片阴影 | 统一使用 `SettingsPanelChrome.CardShadow`，不新增局部阴影参数 |

约束：

- 普通设置卡片、工具卡片、状态卡片、预览卡片和可编辑表面必须通过 `SettingsPanelChrome.ApplySurfaceCardStyle`、`SettingsPanelChrome.ApplyCardStyle` 或等价公共组件获得卡片圆角、边框、主题背景和阴影。
- 覆盖在分析图或查看器上的设置面板必须使用 `SettingsOverlaySurface` 半透明背景；不得通过控件整体 `Opacity` 实现半透明，以免输入框和文字一起变灰。
- 列表框、预览框、输入框外壳等控件框架必须使用 `SettingsPanelChrome.ApplyControlFrameStyle` 或全局控件样式，圆角固定为 5。
- 不允许同类卡片在不同面板使用不同圆角、阴影和内边距；普通 UI 源码不得新增局部 `BoxShadows.Parse`。
- 允许例外必须有明确语义：图例色标/采样点属于数据标记，Splash、Dock 文档 pill 属于外壳装饰，导出文档和标准图纸属于独立版式。
- 底部分析信息区高度、分隔线、品牌区和文件区必须统一；同一组分析页面不得出现不同高度。
- 图标按钮必须有 tooltip 和自动化名称；只有图标无法表达的命令才使用图标加文字。

## 布局

普通页面使用 `Auto`、`*`、`DockPanel`、`Grid`、`WrapPanel`、滚动容器和容器相对尺寸。固定尺寸只允许用于：

- 稳定图标、色块、光标、拖拽柄；
- 明确有标准尺寸的导出文档、工程图和截图对标画布；
- 最小可用窗口尺寸；
- 对话框初始尺寸；
- 分析结果底部信息区这类产品级固定 chrome；
- 方形二维空间图的正方形约束。

禁止：

- 用 `Viewbox` 包住含文字的 UI 来适配窗口。
- 给普通分析子画布写死 840x290、固定列数或固定高度。
- 在 Dock 文档区强制大 `MinWidth` 导致窄分栏不可用。
- 图表外层和内层背景不一致。

设置布局：

- 分析页和查看器设置默认使用左上浮层卡片，不随主窗口宽度横向铺满。
- 设置项按两列字段阅读，底部保留自动应用、应用、确定/取消或重置等操作区。
- 参数数量较少时，卡片宽度由内容决定；不得用横向 `WrapPanel` 把字段从左到右排到窗口最右侧。

分析图布局：

- 点列图、全视场点列图、矩阵点列图、结构矩阵点列图、光瞳/光线 fan、干涉图等二维空间图应保持方形绘图区。
- 色焦移是曲线图，不强制方形。
- 光线像差和瞳孔像差按视场分组，X/Y 或 P_x/P_y 成对放在同一视场组内，不按方向拆成两列全局排列。
- 离焦点列图、矩阵点列图和结构矩阵点列图的多个波长应在同一个子图内叠加，图例说明波长，不拆成互相独立的小图。

## 控件与输入

- 每个输入项必须有可见标签；自动化层面应能从标签定位到输入控件。
- 数值输入默认应提供 spinner 或等价微调能力；只有密集表格、只读单元格或明确的紧凑模式可以关闭 spinner。
- 表格数值列右对齐，单位在列标题或旁侧标签中说明，不在每个单元格重复。
- 禁用控件必须说明原因，不能保留“可选但无效”的参数。
- 长耗时操作必须使用 `OperationStatusBar` 或等价公共组件表达运行状态，不得在各页面只写局部状态文本。
- 长耗时操作超过约 500 ms 时应显示进行中状态；可能超过 2 秒的操作应提供取消路径或明确说明不可取消。
- 运行状态语义固定为执行中、可取消、失败、已同步、结果过期；失败和过期必须保留可读原因，不允许只显示空白或单独图标。

## 分析结果页

分析结果页统一由以下区域组成：

1. 顶部工具栏：设置、刷新、复制文本、导出文本、同步状态。
2. 中央图形区：使用 `PlotBackground`，图表标题、轴、图例和提示统一字号与颜色。
3. 底部信息区：左侧摘要，右侧品牌/文件信息，固定产品级高度。
4. 底部页签：绘图、数据、文本，使用紧凑字号和统一活动下划线。

约束：

- 品牌区使用主题处理后的 S.T.A.R.Labs 标识图，不直接绘制灰块或硬编码文字 logo。
- 文件名、来源和版本信息使用同一字号、颜色和行距。
- 同一分析家族的底部区高度、字体颜色、分隔线和内边距必须一致。
- 失败状态必须保留用户能理解的错误原因，并避免显示空白图。

## 可访问性

最低要求：

- 所有按钮、菜单、图表、绘图画布、可滚动区域和可编辑控件必须设置自动化名称。
- 自绘画布如果支持鼠标滚轮缩放、拖拽平移、双击复位，也必须提供键盘等价操作。
- 焦点框必须可见，不能被透明背景或自绘层遮挡。
- 图例不能只靠颜色区分，至少结合形状、文本或序号。
- 错误、警告和成功状态不能只靠颜色表达。

## 主题和回归验证

涉及 UI 的改动至少验证：

- 明亮、暗夜、异世界三个主题；
- 100%、125%、150%、200% DPI；
- 主窗口最小支持宽度、普通全屏宽度和窄 Dock 分栏；
- 键盘 Tab 顺序、Enter/Escape、图表键盘缩放/复位；
- 关键文字对比度；
- 分析页底部信息区和品牌区高度一致；
- 相关 GUI 契约测试。

## 例外管理

任何违反本规范的实现必须在代码附近或对应文档中说明：

- 为什么需要例外；
- 例外是否只影响导出文档或对标捕获；
- 是否有主题、DPI 和可访问性验证；
- 计划何时收敛为公共组件或公共资源。
