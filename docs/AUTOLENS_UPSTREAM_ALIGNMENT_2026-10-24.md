# AutoLens 原版优化规则对齐（2026-10-24）

基准为已在独立环境完整跑通的 [AutoLens e58db32](https://github.com/AI4Optics/AutoLens/blob/e58db32f3a0b07f25861b5839a45970f77b5c947/1_autolens.py) 的默认 `MOBILE_CONFIG`。本轮修改优化规则，不比较最终像质、成功率、图片或速度，也不把工程测试通过数当作设计达标率。

原版源代码位于 `D:\Projects\autolens-upstream-20261024\source`；上轮默认原版运行退出码为 0，完成课程 2001 次、精修 3001 次更新，输出位于 `results/1024-195541-AutoLens-OhbV`，用时 5742.922 秒。原始日志、配置、源文件及输出哈希留在该目录旁的 `evidence` 中。本轮没有修改原版受 Git 跟踪的源文件。

## 新策略与历史记录

桌面新建实验使用 `AutoLensManagedV1` 优化器入口下的显式 `AutoLensManagedPolicy.UpstreamE58`，算法名称后缀为 `autolens-upstream-e58-v2`，优化状态 schema 为 2。省略 Policy 的旧记录保持 v1 身份与既有序列化指纹；仍可查看和导出，不能被桌面当成新策略恢复。旧实现保留用于历史回归。

产品保持纯 C#/.NET：没有 Python、PyTorch、Python.NET 或外部优化进程依赖。追迹、交点、法线、折射、色散、近轴量、正式光斑分析与布局调用共享 Core。按用户最新边界，相同计算才共享；AutoLens 特有的绿色质心参考、detach 与 epsilon RMS 汇总放在实验室，避免混入普通分析定义。

## 共享 Core 与设备边界

Core 新增独立轴向参数绑定、有限物距固定输入光线求导、解析非球面法线导数、逐面弯折量、有限物距 CUDA 正式传播，以及局部材料注册表导入。原 v1 导数与隐式瞄准约定保持历史行为。

CUDA 的原有“移动起点”瞄准用于无限远物方，不能挪用到有限物距。新流程的物方点保持固定，独立验收的方向瞄准使用正式 Core CPU，单独计为 `CpuAimingRays`；CUDA 正式传播和六输出反传仍执行并记录实际批次。`CpuRecoveryRays` 仍只表示旧 CUDA 瞄准延拓的恢复，不混入有限物距 CPU 瞄准。

嵌入的 [目录数据](../src/OpticalSystemDesign.Core/Materials/Data/autolens-e58-materials.json) 包含上游提交、原始 AGF/JSON 哈希、原版匹配顺序和选取的真实色散数据，使用 `AutoLensE58:` 名称，不覆盖现有目录。来源与 Apache 许可见 [NOTICE](../third_party/autolens/AutoLens-NOTICE.txt)。

仍不宣称逐位或最终输出等效：

- 产品按共享 Core 要求保留 double；原完整运行使用 PyTorch float32。正式交点选择、Newton 容差、临界域处理与物理瞄准仍属于共享 Core，而非复制一套 DeepLens 引擎。
- 训练瞳采样使用可序列化、可恢复的显式稳定随机流，分布与采样位置规则已对齐，但没有模拟 PyTorch CUDA Philox 及其绘图/诊断所消耗的随机流。因此相同种子的完整训练光线序列不逐位相同。
- 本轮对齐的是已经跑通的默认手机配置。原 `CAMERA_CONFIG` 的内部光阑与混合球面/非球面/三面胶合组拓扑没有作为另一套完整原版配置复现；README 相机目标仍是本地适配，不能称作原相机脚本复现。当前可选胶合仍使用绑定的同位置零光焦度参考行，另存真实参数与原有几何验收。
- 原版没有产品的独立硬验收门槛；该门槛保留并与训练分离。没有用本轮测试推出成功率、速度、最终 RMS 或图像效果结论。
