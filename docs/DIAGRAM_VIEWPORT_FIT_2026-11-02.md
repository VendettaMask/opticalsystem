# 分析与二维/三维布局的窗口适配

用户截图反映的是源图被按1:1放入窗口：大窗口图停在左侧并留白，小窗口只能看到图的一部分。此次按用户最新要求，分析及二维/三维布局默认完整适应当前可用区域，提供“原始大小（100%）”原生滚动方式。这取代早期“屏幕始终1:1滚动”的呈现规则；原始绘图、图签和导出规格保持。

## 重复限制审计

| 层级 | 原行为及结论 | 修正 |
| --- | --- | --- |
| `UniformDiagramPage` | 固定1200×900、图签160，属于源图和报告契约 | 保留，不让窗口改变源图排版 |
| `ResponsiveAnalysisPlotHost` | 再次返回同一固定尺寸，并把 `ContentScale` 固定为1；所以滚动而不缩放 | 同一源图通过唯一Viewbox等比显示，默认完整适应；100%模式恢复原生滚动 |
| 旧视口测量 | 当前约束又与上一次ScrollViewer视口取较小值，有新旧尺寸叠加 | 直接使用当前布局约束，视口更新仅同步最终有效可用区 |
| 二维/三维布局宿主 | 另外直接创建ScrollViewer，行为与分析宿主分开 | 统一复用同一显示宿主及同一比例菜单 |
| 三维视角工具条高度 | 以源图逻辑高度限制屏幕工具条，缩放后两个坐标系不一致 | 按实际显示场景矩形计算高度，工具条置于正常字号的独立界面层 |
| 子图最小尺寸、矩阵列宽、方形画布 | 属于源图内部的可读布局及物理比例，不是外层窗口尺寸规则 | 保留其语义，在原始坐标中排版；不重复缩放单个子图 |
| Dock裁切与源图溢出守卫 | 负责视口边界与真实源图超限 | 保留；源图本身超限仍提示并拒绝导出，不能用屏幕缩放掩盖 |

没有发现Dock文档框另设1200×900上限。布局/分析的最小图高和图例宽度在源图内部起作用；删除这些会改变原图和方形子图语义，不能作为修复外层适配的方法。

## 已实现行为

- 默认按当前可用宽、高中的较小倍率等比显示完整源图，居中留出必要的比例空白；缩小、放大和重新停靠后重新计算倍率。这里不把4:3源图拉伸成任意长宽比。
- “适应窗口 / 原始大小（100%）”只控制显示比例。分析菜单在现有工具条，二维/三维布局的比例菜单在源图外，保证小视口及滚动时仍可访问。刷新分析保留本窗口选择。
- 二维/三维的设置、刷新、相机及视角预设保持正常界面字号，按屏幕中的场景矩形定位；不随图纸缩小，也不进入导出图纸。视角预设保留换行和滚动，原有鼠标/键盘操作继续使用实际命中检查。
- 坐标值、数据/文本页、图例选择、曲线手动平移缩放、相机及光学输入不因窗口变化重算或重置。原配置字号和子图几何仍存于1200×900源图；100%模式可按原始大小阅读文字。
- PNG仍捕获同一完整源图，默认2404×1804像素、192 DPI，包含原图签及外边框。报告复用相同源图，显示倍率不进入导出。实体模型保持其已有可伸缩视口与紧凑参数/材质区。
- 非图纸的文本/表格报告保持原来的可读排版和滚动，不套用图纸缩放。
