# 非序列第二阶段：杂散光基础链路

## 实现状态

本阶段已经形成独立的杂散光基础链路：

`STL 机械对象 → 非序列分支追迹 → STARRDB 光线数据库 → 路径筛选/统计 → 3D 布局与探测器重建`

实现参考 Zemax OpticStudio 的工作流，但不复制其专有文件格式。Workbench 的 `.starrdb`、筛选语法和 STAROPT 网格资产均为自有格式，不声明与 ZRD、NSC 或完整 Zemax Filter String 兼容。

## STL 网格对象

对象编辑器提供“导入 STL”，支持 ASCII 和 Binary STL。导入窗口要求明确源文件单位，支持毫米、厘米、米和英寸；数据进入工程前统一转换为毫米。网格对象保存稳定 `MeshAssetId`、吸收/镜面反射/折射行为、材料和双面相交设置。

导入在临时数据中完成以下验证：

- 有限坐标和最多 `2,000,000` 个三角形；
- 按模型尺度容差焊接顶点；
- 删除退化和重复三角形并重新计算几何法线；
- 检查共边流形、闭合、连通、可定向、自相交和有向体积；
- 闭合网格整体朝向反转时统一翻转到正体积；
- 建立三角形级 BVH，用于导入自相交筛选和运行时最近交点。

开放网格可用于双面吸收或反射。折射网格必须闭合、流形、连通、可定向、无自相交且具有正体积，否则对象事务整体失败。精密球面、非球面和标准镜片仍应使用原生参数对象；STL主要用于挡板、镜筒、支架和其他机械杂散光结构。

## STAROPT 内嵌资产

当前 STAROPT 容器版本为2，工程负载版本为3。加载器继续接受容器v1和负载v1/v2：负载v1迁移为空非序列场景，负载v2按第一阶段规则恢复独立文档。

容器v2保持原有52字节工程清单头，随后保存：

1. Brotli压缩的UTF-8工程清单；
2. 每个网格资产的64字节头；
3. Brotli压缩的规范化 `STARMESH` 顶点/三角形数据。

网格资产使用规范小端二进制格式和 SHA-256 内容寻址。同一内容在一个工程内只保存一次；删除或改变最后一个引用对象时会清理未使用资产。加载时交叉检查清单、资产ID、长度、解压上限和固定时间哈希。最多保存 `4,096` 个资产，总解压大小上限 `512 MiB`。保存仍使用目标目录临时文件和原子替换，失败或取消不会破坏已有工程。

## 分支输出和 STARRDB

追迹请求支持四种输出模式：

- `LayoutSample`：确定性保留最多指定数量的分支供3D布局；
- `InMemory`：保留全部匹配分支，适合小规模分析和测试；
- `RayDatabase`：通过 `INonSequentialTraceSink` 流式输出，不保留完整光线树；
- `SummaryOnly`：只返回探测器和能量平衡。

`.starrdb` 是独立的版本1二进制数据库。文件头保存场景SHA-256、工程修订、UTC时间、毫米单位、波长、对象表、追迹设置、随机种子和保存筛选。每512个分支形成一个Brotli分块，分块带SHA-256；文件尾保存随机访问索引和完整完成标记。缺少文件尾、截断、长度不一致或分块哈希失败会被明确拒绝。

应用在目标目录写临时数据库，只有追迹、分块索引和刷新全部完成后才原子替换目标。取消和异常会删除临时文件并保留旧数据库。打开数据库时比较当前场景哈希：不一致的结果仍可只读分析，但界面显示“结果已过期”。

## 路径筛选和联动

统一筛选器支持：

- `Qn` 源对象、`Hn` 命中、`Rn` 反射、`Tn` 透射、`Dn` 探测、`Mn` 未命中；
- `Wn` 系统波长；
- `A` 吸收、`E` 逃逸、`X` 阈值/上限/无效终止；
- `!`、`&`、`|` 和括号，优先级依次为 `!`、`&`、`|`；
- `SEQ(...)` 有序子序列，例如 `SEQ(Q1,H3,R3,D8)`。

语法忽略空白且不区分大小写。非法标记、缺失编号和括号错误会报告从1开始显示的字符位置。依赖完整路径的条件在分支结束后求值，再决定是否保留或写入。

路径分析按对象、面、交互和终止原因分组，报告射线数、功率、占比、最小/平均/最大光程、波长计数和目标探测器，并生成可再次使用的筛选表达式。数据库窗口应用筛选后，会把该数据库和筛选保存为当前非序列分析会话：

- 3D布局从匹配分支中确定性读取最多2,000条路径；
- 探测器查看器流式扫描全部匹配分支并重新累计各波长像素功率；
- 新建或打开另一工程时清除该会话；普通处方修改保留只读数据库并通过场景哈希显示过期状态。

## 桌面入口

非序列对象数据页提供：

- 导入STL及单位、行为、材料、双面选项；
- 追迹控制，包括布局/分析射线、Fresnel分支、保留上限、路径筛选和数据库路径；
- 光线数据库与路径分析；
- 原有非序列3D视图和矩形探测器查看器。

3D网格显示最多确定性抽样50,000个三角形，不影响追迹使用完整网格。数据库的百万级光线不会整体载入3D页面或探测器内存；3D只取上限样本，探测器只保留像素累计数组。

## 验证与边界

自动测试覆盖ASCII/Binary STL、Unicode名称、单位换算、内容去重、开放/闭合约束、网格求交、STAROPT v3往返、路径语法、STARRDB分块往返、场景过期和应用原子发布/筛选联动。正式全量测试基线见README。

百万光线性能测试由独立基准工具执行，不进入普通CI。2026-08-26本机.NET 10 Release记录为：1,000,000条源光线、分支和分段在`11.555 s`内写成`81,675,707 bytes`数据库，吞吐`86,539 rays/s`，托管堆`22,626,656 bytes`，进程峰值工作集`102,162,432 bytes`。源光线和数据库分块均流式推进；该记录只代表简单“点光源—矩形探测器”基线，不代表复杂机械网格或深层Fresnel分支性能。

当前仍未实现：STEP/IGES/SAT导入、CAD面映射、布尔对象、表面/体散射、BSDF、偏振、相干探测、非序列优化/公差、Zemax NSC/ZRD导入以及GPU追迹。后续顺序为散射和面属性、偏振/相干、非序列优化、公差、精确CAD内核和GPU/超大数据库。
