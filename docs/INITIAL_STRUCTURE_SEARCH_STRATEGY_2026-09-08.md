# 初始结构自动搜索：策略整改

日期：2026-09-08。依据用户纠正，停止“人工修改权重或阶段比例，再逐轮跑整套基准”的开发方式，先实现能够自行决策的优化策略。S1 通用局部求解器已实现，验证与接口边界见 [S1 实施记录](INITIAL_STRUCTURE_S1_SOLVER_2026-09-08.md)。S2 光学约束适配、S3 搜索调度与 S4 新版本验收尚未完成，当前镜头搜索仍运行 v4。v4 的固定验收为 52/60 次成功、9/12 个规格达标，仍未达到 10/12；不能将 S1 机制测试作为光学成功率或速度提升的证据。

## SYNOPSYS 公开资料说明了什么

参考对象是 OSD 的 SYNOPSYS 光学软件与 DSEARCH。现在参考其公开的搜索与优化方法，不再仅限于交互形式。

- **搜索与局部求解分层**：官方 DSEARCH 说明从平板系统探索多个方向，产生许多试验结构，由快速局部优化器处理，然后筛选优胜结构。[Automatic Design Tools，第 6～8 页](https://osdoptics.com/wp-content/uploads/2021/12/Automatic-Design-Tools-in-SYNOPSYSTM.pdf)
- **分配不同计算成本**：同一说明中的 Quick 模式用三阶、五阶像差及少量真实光线做初筛，随后对排名靠前的十个结构做真实光线深入优化；也支持多核和可选退火。这是该文描述的流程，不把“十个”或演示耗时当作本项目的固定常量或性能承诺。
- **局部优化利用历史信息**：官方 Lesson 23 描述首轮使用 DLS，PSD 再利用相邻迭代的一阶导数变化获取更高阶信息，并展示单独的光线失败修复。[Lesson 23，第 3～4 页](https://osdoptics.com/wp-content/uploads/2020/05/23_parametric_optimization_study_and_ray_failure_correction.pdf)
- **逃离局部极小值与结构变化是独立操作**：Lesson 37 展示搜索、退火、自动插片和真实玻璃替换的组合，也明确存在设计师后续工作与随机性。[Lesson 37](https://osdoptics.com/wp-content/uploads/2020/05/37_finding_and_changing_lens_structure_automatically.pdf)

这些资料足以支持分层搜索、筛选、深入优化和历史信息复用的架构选择，但没有给出可直接复现当前 PSD III 的完整实现。本项目不能将普通 LM、拟牛顿或割线更新命名为 PSD，也不能声称达到其商业实现速度。SYNOPSYS 的模型玻璃、零厚度插片等示例不覆盖本项目的真实目录玻璃、严格平板根和片数边界。

## 当前实现的具体缺口

| 代码位置 | 实际行为 | 缺少的策略 |
| --- | --- | --- |
| `FlatStartDesignService.Optimize` | 每次外层循环重新做约 2N 次差分，拒绝步后也重新求雅可比；按固定倍率改变阻尼 | 根据模型预测与真实改善决定步长，并在同一点重试时复用雅可比与分解 |
| `FlatStartDesignService.Run` | 按固定视场阶段和剩余阶段数分配预算 | 根据可行性、收敛速度和模型可靠度自动决定阶段推进或回退 |
| `FlatStartDesignProblem.Evaluate` | RMS 坐标、最大半径超限和通光诊断混合成一个加权分数 | 单独表达硬约束；恢复可行性与改善像质具有明确的接受规则 |
| `FlatStartSearchService.Propose` | 五种操作按序号循环，父候选按固定顺序轮换 | 根据停滞、重复结构、改善量和剩余预算选择探索、精修或退出 |
| 完整候选继续优化 | 经常从一开始就使用最终密集采样 | 先做有成本上限的筛选，把密集计算集中于有希望的不同结构 |
| 本轮工作方式 | 观察某个失败种子后人工修改常数 | 冻结通用策略，让程序在一次运行内执行完整决策闭环 |

现有实现已有局部求解、谱系、预算和扰动，并非完全没有搜索逻辑。整改重点是上述控制规则与计算复用；孔径诊断、原始平板证明、共享 Core 和独立验收继续保留。

## 本项目拟实现的自动闭环

以下是根据公开资料和代码审查提出的本项目方案，不是对 SYNOPSYS 内部算法的描述。

1. **通用局部求解器先行**。把局部优化从光学设计服务中拆出，输入只有变量、残差、约束和评价回调。采用有界信赖域最小二乘；比较实际下降与局部模型预测下降，自动接受、拒绝或调整信赖域。同一变量点改变阻尼时复用雅可比。先验证这一基础，再评估受预测误差监控的割线更新；变量点、采样、材料或约束集合改变时，按失效规则重建模型。
2. **约束恢复独立处理**。区分不可追迹、可追迹但违反硬约束、满足约束三个状态。用正式 Core 的可用连续诊断恢复通光；用约束违反量与像质改善共同决定可接受步骤，避免靠人工倍增固定权重维持边缘视场。无法构造或无法传播时停止该方向，保留真实失败状态。最终接受仍使用原始逐视场、逐波长门槛。
3. **从平板产生多方向探索**。每条根谱系保持全零曲率。通过不同真实玻璃、合法厚度/间隔、光阑与求解器产生的首步方向覆盖设计空间，记录首次非零更新。方向生成和结构提案由策略驱动，不在源码中绑定具体镜头名、种子或失败样例。
4. **筛选与精修分工**。固定一种低成本评价协议筛选结构，在同一协议下排序并保留结构多样性；有希望的候选晋升到更密集的真实光线计算。首版使用正式 Core 已有的稀疏真实光线接口。若以后使用三阶或五阶分析，必须先确认正式 Core 能力及一致性，不能为模仿 Quick 模式在实验室补写光学近似。不同采样等级的分数不直接比较。
5. **自动停滞与预算调度**。记录每个家族的约束改善、像质改善、实际光线成本、重复状态和失败原因。先给家族最低探索机会，再按确定性规则分配追加预算；停滞触发受控扰动、玻璃/光阑邻域或新家族，反复无改善则退出。调度依据评价数和光线数，避免墙钟噪声改变固定种子的搜索路径。退火、插片、鞍点构造分开评估；不得在固定片数规格中偷偷增加镜片。
6. **程序完成最终验收**。独立新建 Optic，恢复冻结的全部视场、波长、物理孔径和密集瞳采样。通过后发布可导出的候选，否则报告差距。用户只设置规格和预算；调度、回退、重启与停止由程序执行。

## 实施顺序与验证方式

| 顺序 | 交付 | 必须证明的行为 |
| --- | --- | --- |
| S1（已实现） | 独立的通用局部求解器及成本记录；尚未替换 v4 光学调用 | 简单解析、病态、活动边界和不可行问题；拒绝步复用雅可比和 QR 解；实际/预测下降一致；取消和预算不超支；见 S1 实施记录 |
| S2 | 光学残差/约束适配与自动阶段控制 | 所有光学计算来自正式 Core；同快照同设置数值一致；恢复状态与最终验收分离；阶段切换重建评价模型 |
| S3 | 多方向搜索、候选晋升、停滞与预算控制器 | 自动完成筛选—精修—重启闭环；保留多样性；检查点包含调度和随机状态；串行、并行及恢复按固定预算可复现 |
| S4 | 固定版本验收 | 策略冻结后运行原 12×5 协议，并报告所有种子、失败、实际光线数和耗时；补充独立留出规格，避免只对已见基准调参 |

开发期测试针对机制和已定位的缺陷；完整 60 次运行用于冻结版本的验收，不作为手工寻找常数的内循环。留出规格单独报告，不改写原协议的分母、阈值或历史结果。与旧混合原型的同目标比较、正式项目现有 5 项失败和原生人工界面验收仍需独立完成。
