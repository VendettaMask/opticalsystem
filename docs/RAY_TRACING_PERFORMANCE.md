# 大规模光线追迹性能

## 范围

性能工作主要针对顺序实光线批量追迹、分析复用和 Monte Carlo。非序列追迹使用独立对象源动的分支内核，为有界对象建立单次追迹 BVH，在候选集中选择最近正向命中。它保留交互类型、光程、实体介质和 Fresnel 能量分支，并提供独立的百万光线 STARRDB 流式写入基准；尚未实现非序列批量/SIMD/GPU 或跨分析 BVH 缓存。

## 历史保留 API

`TraceRequest` 支持：

- `FinalOnly`：只保留最终状态；
- `SelectedSurfaces`：只保留指定表面；
- `FullHistory`：保留完整逐面历史。

内存随“光线数 × 保留表面数”增长，而不是始终随全部表面增长。旧 `Trace` API 保持兼容，但新分析应显式声明保留需求。

## 跨分析缓存

缓存键包含光学修订号、数值后端、精确输入光线状态、最终保留表面集合和影响结果的选项。等价保留模式可共享；分析名称和本地化标题绝不能进入键。

任何会影响追迹的分析快照变更必须先与共享缓存分离。缓存有容量边界，文件切换和修订变化会失效。

## 执行模型

- 使用池化 SoA 光线状态和扁平结果视图；
- 常见顺序路径使用 `Vector<double>` SIMD；
- 不支持向量化的曲面回退标量；
- 并行按稳定分块写回原索引；
- 外层 Monte Carlo 或并行 Jacobian 已并行时，内层追迹不再嵌套并行。

## 使用方

PSF、MTF、点列、波前、查看器和公差只请求需要的表面。Monte Carlo 每个试验从不可变名义快照构建独立 `Optic`，按全局种子和试验索引派生种子，串行/并行顺序一致。

## 验证

回归覆盖：

- 三种保留模式的数值一致性；
- 选定末面与仅末面等价；
- 标量/SIMD、串行/并行一致；
- 修订、输入和选项变化的缓存失效；
- 全反射、反射、吸收和提前终止；
- 分析之间的同修订缓存复用；
- Monte Carlo 并行度无关的确定结果。

当前验证确认非序列文档、对象源、基础实体、标准镜片、Fresnel 分支、探测器映射、能量平衡和确定性终止的功能正确性；测试数量与构建结果以 README 当前验证记录为准。STARRDB 性能基准用于观察流式数据库链路，不替代复杂 STL、深分支或多次反射场景的性能剖析。

## 基准

```bash
dotnet run -c Release --project tools/OptilandWorkbench.Benchmarks/OptilandWorkbench.Benchmarks.csproj
dotnet run -c Release --project tools/OptilandWorkbench.Benchmarks/OptilandWorkbench.Benchmarks.csproj -- --non-sequential 1000000
```

第二条命令使用确定性“点光源—矩形探测器”场景，将完整分支流式写入临时 `.starrdb`，输出耗时、吞吐量、总分配、托管堆、峰值工作集、数据库大小和文件路径。源光线采用惰性枚举，每棵分支树完成后才取得下一条源光线，不会预存百万条源射线。

2026-08-26 在本机 .NET 10 Release 配置下的记录为：1,000,000 条源光线、1,000,000 个分支和1,000,000个分段，耗时 `11.555 s`，吞吐 `86,539 rays/s`，托管堆 `22,626,656 bytes`，进程峰值工作集 `102,162,432 bytes`，数据库 `81,675,707 bytes`。这是环境相关观测值，不是 CI 硬阈值；只比较相同机器、运行时、配置和场景的结果。

## 延后工作

GPU/自动微分后端、更高阶批量自由曲面、非序列 SIMD/GPU 加速、跨分析 BVH 复用和跨进程缓存未实现。
