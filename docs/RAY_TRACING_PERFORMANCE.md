# 大规模光线追迹性能

## 通用性能优化规范

本节约束共享 Core、分析运行时与调用方的性能修改（用户要求，2026-11-27）。

- 优化必须基于实际热点、完整输入身份或可证明的光学性质。禁止用镜头名称、示例编号、文件路径、固定材料名称或某个算例的拟合常数选择加速分支。示例只用于复现和验证，不能进入运行时判断。
- 保持原处方、采样节点、物理坐标、孔径/遮挡、传播方向、复振幅/相位、光谱权重、归一化和原精度判据。不能用降低采样、关闭相位保护、跳过收敛或换成几何近似获得提速。只计算强度的接口与需要相位的接口必须分开声明。
- 优先移除重复能力检查中的分配、重复求解与重复不变量准备。对不可变几何或坐标对象可按对象生命周期缓存不变量；不得让缓存参与值相等、序列化或使 `with` 复制继承不适用的旧结果。可变处方缓存必须覆盖完整物理身份和选项，绑定冻结修订，验证材料、孔径、坐标、波长和系统设置变化失效；无法可靠识别的模型不得缓存。
- 按物理条件加速需有通用适用条件和推导。例如，经过均匀平面界面仍为平面波时可复用入射方向；有限共轭、曲面引入像差、非均匀介质或不支持的交互继续走原求解。不得把某个示例上观察到的近似当成通用条件。
- 自动加密应复用同一请求已完成的有效计算，仍保留实际节点相位检查、两档已解析结果的收敛检查、原物理比较域和原工作预算。取消、不可用及未收敛必须如实返回；不能拿无效低档结果显示完成。
- 并行和缓存必须有容量、工作量及取消边界，保持原索引顺序和确定性，避免外层/内层无界嵌套并行。CPU 是共享物理规则的验证基准；GPU 需记录实际执行设备与回退。
- 在同机、同处方、同设置、同版本运行时下分开记录首次和再次请求；保留 CPU/GPU、Debug/Release、预热、计时范围、累计分配和实际追迹提交数。累计分配不能称为驻留内存，局部栈采样不能称为精确耗时占比。
- 验证同时覆盖代表性折射/广角/反射/近轴或其他受影响物理族，比较实际完整数值、物理轴和状态；补充失效、复制、并发和取消的定向控制。不得只用一两个镜头的提速推定全产品完成，也不得通过修改容差消除回归。保留未改善项与适用边界，更新当前状态和可重放证据。

## 桌面性能检验

在顺序模式打开「设置 → 诊断 → 性能检验」，点击「开始检验」。每次使用当前镜头和配置的独立副本，在后台完成预热及三轮测量。窗口显示三轮中位数、各轮计数和用时，结果文字可选中复制。比较机器或软件版本时，建议打开内置「文件 → 示例 → 物镜 → Double Gauss 28 degree field」并固定配置。Ansys 也用该镜头测量顺序追迹吞吐。[Ansys 示例测量](https://optics.ansys.com/hc/en-us/articles/42712671312787-How-to-run-OpticStudio-on-an-Apple-Mac-computer)

| 读数 | 计时与计数 |
| --- | --- |
| 追迹光线/秒 | 主波长、最外视场，每轮使用同一组 32,768 条固定种子随机光瞳光线。计时使用仅保留末面的正式 CPU 批量追迹，停用追迹缓存和 OPD 归一化。光线生成在计时外。 |
| 处理面次/秒 | 预热时用相同光线做一次逐面追迹，统计物面之后实际处理的光线和面组合，再除以各轮追迹时间。中途终止的光线只累计已经处理的面，包括终止所在面。另显示各轮通过末面且强度为正的光线数。 |
| 系统更新/秒 | 每次对新副本应用拾取、求解、表面编号和自动口径，计算各波长的入瞳、出瞳以及主波长各视场的主光线准备。当前配置启用光线瞄准时，准备步骤也执行瞄准。每轮累计约 200 ms 或最多 32 次。副本构建在计时外。 |

OpticStudio 公布的办法是在当前镜头上追迹随机斜光线，报告每秒处理的光线与面组合数，并单独计时求解、光瞳、视场、口径和折射率等系统准备。我们的面次定义和计时边界如上，跨软件比较需对齐这些条件。非序列数据库基准见下文。[OpticStudio 性能检验说明](https://ansyshelp.ansys.com/public/Views/Secured/Zemax/v25202/en/OpticStudio_User_Guide/OpticStudio_Help/topics/Performance.html)

## 范围

2026-09-27 商业审计记录了缓存失效、重复坐标变换准备、标量适配分配以及图像仿真取消/预算问题，并运行了当时的 Release 基准。当前缓存已覆盖嵌套几何变更失效，以及 2026-10-26 修复的整份处方替换失效和相同修订号下不同处方的隔离，见[本轮修复与验证](PRIORITY_RELIABILITY_REPAIR_2026-10-26.md)。原报告的其他建议不能由这些回归推定已全部实施；历史测量范围仍见[商业审计报告](COMMERCIAL_CODE_AUDIT_2026-09-27.md)。

性能工作主要针对顺序实光线批量追迹、分析复用和 Monte Carlo。非序列追迹使用独立对象源动的分支内核，为有界对象建立单次追迹 BVH，在候选集中选择最近正向命中。它保留交互类型、光程、实体介质和 Fresnel 能量分支，并提供独立的百万光线 STARRDB 流式写入基准；尚未实现非序列批量/SIMD/GPU 或跨分析 BVH 缓存。

## 历史保留 API

`TraceRequest` 支持：

- `FinalOnly`：只保留最终状态；
- `SelectedSurfaces`：只保留指定表面；
- `FullHistory`：保留完整逐面历史。

内存随“光线数 × 保留表面数”增长，而不是始终随全部表面增长。旧 `Trace` API 保持兼容，但新分析应显式声明保留需求。

## 跨分析缓存

缓存键包含光学修订号、处方快照 SHA-256、数值后端、精确输入光线状态、最终保留表面集合和影响结果的选项。快照身份排除工程名称、视场/波长/表面标签及评价函数，避免用显示名称决定追迹身份。等价快照和等价保留模式可共享；分析名称和本地化标题绝不能进入键。无法形成可序列化身份的插件组件继续追迹，但不使用缓存。

任何会影响追迹的分析快照变更必须先与共享缓存分离。缓存有容量边界，文件切换和修订变化会失效。

材料注册和首选玻璃目录变化会通知已绑定的顺序追迹缓存并解除共享；相同材料名称不代表相同光学模型。非序列场景身份另外包含实际材料模型，避免同名材料被重新定义后仍认为旧数据库有效。此处验证的是身份和结果一致性，不是新的吞吐量测量。

### 光瞳发射与瞄准结果复用

`GenerateNormalizedPupilSamples` 对显式启用精确光阑瞄准、未传自定义 stopTargets、且已绑定可靠处方身份的请求，复用同一原求解器已完成的发射光束。键覆盖修订和完整处方身份、后端/顺序 GPU 模式、视场、波长、实际像高发射解、渐晕开关，以及每个瞳孔节点的坐标、顺序和权重。自定义目标、无可靠身份、未瞄准或超过单条容量的请求沿用原路径；缓存不替换物理追迹，也不把零强度失效节点改为透射节点。

发射缓存与物理追迹缓存分别受 `RayTraceCache` 的 maximumEntries/maximumSamples 上限约束，默认各为 256 条/500,000 节点；不能把两个额度合称为一个 500,000 节点额度。文件修订或显式 Clear 同时清空两者。发射结果只保留不可变光线，取出时复制容器并保留已有归一化位模式，禁止再次归一化或把内部数组交给调用者。`PupilLaunchStatistics` 单独披露命中、未命中、条目和光线数；原物理追迹统计继续保持原含义。

### 共享准备与相位

能力检查每次读取当前模型，但支持路径不构造逐面迭代器/材料集合。不可变 `CoordinateSystem` 的旋转与逆矩阵按弱引用对象身份复用，不改变值相等、序列化或修改后的副本。均匀传播、折射/反射及无膜层处理通过共享数值规则直接运输值状态，减少 public ray/state 之间的临时对象转换；复杂模型继续使用原适配接口。

近轴面只在 `IsPlaneWavePrefix` 已证明平面波条件时复用恒定入射方向，保留原 Simpson 积分、相位、符号和收敛界限；有限共轭与有像差光束继续反向瞄准。普通 FFT MTF 的按需恢复只求一次原档，已解析则原样返回；欠采样才进入原两档结果收敛流程，并保留请求档诊断和原工作预算。

实现、完整数值复核和环境相关计时见[通用 FFT MTF 性能修复记录](../validation/rechecks/2026-11-27/fft-mtf-general-optimization/README.md)。

## 执行模型

- 使用池化 SoA 光线状态和扁平结果视图；
- 常见顺序路径使用 `Vector<double>` SIMD；
- 不支持向量化的曲面回退标量；
- 并行按稳定分块写回原索引；
- 外层 Monte Carlo 或并行 Jacobian 已并行时，内层追迹不再嵌套并行。

## 使用方

PSF、MTF、点列、波前、查看器和公差只请求需要的表面。Monte Carlo 每个试验从不可变名义快照构建独立 `Optic`，按全局种子和试验索引派生种子，串行/并行顺序一致。

## 验证

回归覆盖：

- 三种保留模式的数值一致性；
- 选定末面与仅末面等价；
- 标量/SIMD、串行/并行一致；
- 修订、输入和选项变化的缓存失效；
- 全反射、反射、吸收和提前终止；
- 分析之间的同修订缓存复用；
- Monte Carlo 并行度无关的确定结果。

当前验证确认非序列文档、对象源、基础实体、标准镜片、Fresnel 分支、探测器映射、能量平衡和确定性终止的功能正确性；测试数量与构建结果以 README 当前验证记录为准。STARRDB 性能基准用于观察流式数据库链路，不替代复杂 STL、深分支或多次反射场景的性能剖析。

## 基准

```bash
dotnet run -c Release --project tools/OpticalSystemDesign.Benchmarks/OpticalSystemDesign.Benchmarks.csproj
dotnet run -c Release --project tools/OpticalSystemDesign.Benchmarks/OpticalSystemDesign.Benchmarks.csproj -- --non-sequential 1000000
```

第二条命令使用确定性“点光源—矩形探测器”场景，将完整分支流式写入临时 `.starrdb`，输出耗时、吞吐量、总分配、托管堆、峰值工作集、数据库大小和文件路径。源光线采用惰性枚举，每棵分支树完成后才取得下一条源光线，不会预存百万条源射线。

2026-08-26 在本机 .NET 10 Release 配置下的记录为：1,000,000 条源光线、1,000,000 个分支和1,000,000个分段，耗时 `11.555 s`，吞吐 `86,539 rays/s`，托管堆 `22,626,656 bytes`，进程峰值工作集 `102,162,432 bytes`，数据库 `81,675,707 bytes`。这是环境相关观测值，不是 CI 硬阈值；只比较相同机器、运行时、配置和场景的结果。

## 延后工作

GPU/自动微分后端、更高阶批量自由曲面、非序列 SIMD/GPU 加速、跨分析 BVH 复用和跨进程缓存未实现。
