## 一、先确定两个真正需要新增的核心模块

你现在最缺的不是再加一个 Adam，而是这两个入口：

```csharp
FixedTopologyOptimizer.Optimize(...)
ParaxialRestorer.Restore(...)
```

### `FixedTopologyOptimizer`：允许从任意当前结构开始优化

输入不是“指定片数的平板起点”，而是一个已经存在的光学处方：

```text
当前光学处方
当前元件与表面映射
本轮允许变化的参数
用户原始设计要求
当前阶段与计算预算
```

输出是：

```text
优化后的处方
实际消耗的工作量
终止原因
完整目标下的性能
是否需要继续恢复或优化
```

你现在的 `FlatStartDesignService.Continue()` 仍然围绕固定家族、片数和根证明接续；`FlatStartDesignProblem` 的参数向量还依赖 `2 × elementCount` 的面布局。**因此不能直接“删掉两行，然后继续调用旧接口”。** 

### `ParaxialRestorer`：结构变化后，先把焦距和焦点拉回来

例如，一个原来正常聚焦的五片系统，删除第三片后可能变成严重离焦。如果直接开始优化全视场光斑，算法可能根本找不到有效方向。

这个模块的任务就是：

> **在尽量少改动其他参数的情况下，让新结构重新获得接近父结构的一阶聚焦行为。**

CMU 论文里真正值得优先移植的就是这个环节。不过它也明确承认对高质量初值的依赖，并没有证明“任意指标都能从随机结构直接成功”。所以你的 AutoLens 起点生成能力仍然有必要保留。[arXiv](https://arxiv.org/html/2509.23572v1)

## 二、具体改哪些文件，哪些不能直接复用

我建议不动已对齐的 `UpstreamE58`，另外增加 `AutonomousTopologyV1`。

| 新增模块 | 实际工作 | 复用什么 |
|---|---|---|
| `TopologyCompiler` | 把镜片级结构转换成 Core 处方，生成 ID—面序号映射 | 现有 `Optic`、快照和材料系统 |
| `TopologyParameterBinder` | 根据当前结构建立优化变量 | `OpticalDesignParameters.Read/Apply` |
| `FixedTopologyOptimizer` | 从任意支持的处方开始局部或全局参数精修 | 自动微分、Adam、通用信赖域求解器 |
| `ParaxialRestorer` | 增删以后恢复一阶特性 | Core 的一阶光学计算 |
| `TopologyOperators` | 插片、删片、拆分、合并与保护规则 | 新增的镜片级模型 |
| `AutonomousSearchService` | 自动选择父结构、操作位置和预算，管理候选 | 现有候选保存、计费和检查点思路 |

有三点必须处理正确。

**第一，参数操作可以复用，固定参数表不能照搬。**  
你的 `OpticalDesignParameters.Apply()` 已经会重建曲面、同步介质并清理追迹缓存，适合继续作为共同入口。新增模块负责生成正确的参数映射，不另写折射公式。

**第二，现有精修器并不是完整的自由面型精修器。**  
`AutoLensTargetPolisher` 明确固定了非球面系数和真实玻璃。因此需要重新建立可选择变量集合的优化入口，而不是把它直接改名为“自动设计”。

**第三，通用数值求解器可以直接复用。**  
`BoundedTrustRegionLeastSquares.Solve()` 已经接受初值、上下界和残差回调。它本身不依赖光学面表布局，可以继续使用。结构、变量集合、材料或残差定义改变后，需要启动一次新的求解，不能沿用旧雅可比。

## 三、镜片增删必须基于稳定 ID 和绝对位置

### 1. 镜片模型这样定义

附件源码采用的核心信息是：

```text
LensElement
    Id
    FrontSurfaceId
    BackSurfaceId
    FrontZ
    Thickness
    ClearSemiDiameter
    Material
    FrontProfile
    BackProfile
    Protected
```

光阑和像面独立保存，不依附于“第几片镜片”。

这样删除第二片以后，第三片的显示序号可以变化，但其 ID、坐标、材料和参数身份不会混乱。

面型使用**显式幂次**保存非球面项，例如：

```text
Power = 4, Coefficient = ...
Power = 6, Coefficient = ...
```

编译到 Core 时再转换成对应系数数组，避免把 \(r^4\) 项误放到 \(r^2\) 的位置。

### 2. 结构变更首先保持其他元件位置不动

我建议第一版采用一个非常明确的约定：

> **增删瞬间保持未修改元件、机械参考平面、独立光阑和像面的全局坐标不变；之后由优化器在允许的范围内调整。**

这样结构操作本身是可验证的，不会同时发生隐含的像面移动、后组平移和光阑跳转。

需要区分两个长度：

- 固定机械参考平面到像面的长度。
- 第一片真实透镜到像面的光学总长。

删除第一片后，前者可以不变，后者需要重新计算。不能用一个固定数值同时冒充两者。

## 四、自动增加镜片，具体怎样执行

第一版不以零厚度透镜作为默认插片方式，而是插入**有实际厚度、满足基本尺寸限制的弱作用镜片**。

### 第一步：列出可插入的空气区间

设相邻两个保留界面的轴向位置为 \(z_L,z_R\)：

\[
G=z_R-z_L
\]

准备插入一片厚度为 \(t\) 的镜片，最小空气间隔为 \(g_{\min}\)，必须满足：

\[
G\geq t+2g_{\min}
\]

如果中间有独立光阑，就把区间按光阑位置分开。不能为了插片成功而擅自移动光阑。

### 第二步：生成具体位置

取位置参数 \(\eta\in[0,1]\)：

\[
a=g_{\min}+\eta(G-t-2g_{\min})
\]

\[
b=G-t-a
\]

于是：

\[
z_{\mathrm{front}}=z_L+a,\qquad
z_{\mathrm{back}}=z_{\mathrm{front}}+t
\]

例如，原空气隙为 6 mm，插片厚度为 1.2 mm，左右等分，就变成：

```text
原结构：        6.0 mm 空气

新增后：2.4 mm 空气 + 1.2 mm 玻璃 + 2.4 mm 空气
```

其他镜片的位置没有变化。

### 第三步：生成初始形状和材料

我的首轮设置建议是：

```text
位置：每个候选间隔选择少量位置
材料：从允许目录中选择少量候选
光焦度：弱正、弱负两个方向都尝试
形状：少量不同弯曲形式
```

初始弱光焦度可以定义为：

\[
\Phi_{\mathrm{new}}=\frac{\alpha}{f_{\mathrm{target}}}
\]

例如从 \(\alpha=\pm0.03,\pm0.10\) 中抽取少量值。这只是我建议的**待校准初始化设置**，不是已验证的最佳参数。

薄透镜关系只用于生成大致曲率。真实厚透镜的光焦度、边缘厚度和曲面间隙必须重新由 Core 检查。

### 第四步：恢复和优化

每个新增结构按固定顺序执行：

```text
结构与材料检查
    ↓
近轴恢复
    ↓
新增镜片与邻近镜片局部补偿
    ↓
释放全系统允许的变量
    ↓
满目标优化
    ↓
统一协议复核
```

**轴向空间足够，不代表曲面边缘不会碰撞；近轴恢复成功，也不代表像质已经合格。**

## 五、自动删除镜片，具体怎样执行

### 主路径：直接删除，再恢复

对每一片非保护镜片创建独立试删分支。

假设被删除镜片的前空气隙、厚度、后空气隙分别是 \(a,t,b\)，删除后：

\[
G_{\mathrm{new}}=a+t+b
\]

使用绝对坐标模型时，只需要删除该镜片对象，其他元件位置不动，这个关系自然成立。

然后执行：

```text
删除目标片
    ↓
重建介质、参数和光阑映射
    ↓
近轴恢复
    ↓
邻近镜片补偿
    ↓
全系统精修
    ↓
按原始目标验收
```

这里有一个关键规则：

> **删片价值由“补偿优化后的结果”决定，不由刚删除瞬间的 RMS 决定。**

也不应只删除最低光焦度镜片。第一版片数不多，可以在预算允许时轮流覆盖各个可删除位置，避免一个启发式指标漏掉有价值的结构。

### 补救路径：渐进删除

直接删除不能恢复时，再尝试逐渐减弱目标片。

建议以原处方为基准设置：

\[
t(s)=s\,t_0,\qquad
c(s)=s\,c_0,\qquad
a_p(s)=s\,a_{p,0}
\]

其中 \(s\) 逐步降低，例如：

```text
0.7 → 0.4 → 0.2 → 0.1 → 0.02 → 实际删除
```

每个阶段让其他镜片重新优化，以接管目标片的作用。

**每一步都从原始目标值计算，不能把上一步再乘一次 \(s\)。**

在这个过程中，目标片可以暂时低于最终最小厚度，但必须标记为 `Transition`。其他镜片的制造约束不能一起放开。最终实体删除后，清除过渡例外，再按全部原始要求验收。

HappyLens 的删除实现确实单独处理了被删元件的厚度约束及相邻间隙、后焦相关计算，值得借鉴的是这种“明确隔离删除过渡”的处理方式。

## 六、近轴恢复模块，具体怎么求解

这是整个方案中最值得优先写好的部分。

### 1. 先记录父结构的一阶行为

对第一版的无限远物方系统，固定输入参考平面和像面。采用一致的光线坐标约定，例如：

\[
\begin{bmatrix}y\\nu\end{bmatrix}
\]

从参考平面到像面的传递矩阵为：

\[
M_{\mathrm{img}}=
\begin{bmatrix}
A&B\\
C&D
\end{bmatrix}
\]

可以选择两项无量纲量：

\[
G(\mathbf q)=
\begin{bmatrix}
A_{\mathrm{img}}(\mathbf q)\\
f_{\mathrm{target}}C(\mathbf q)
\end{bmatrix}
\]

其中 \(\mathbf q\) 是当前子结构的归一化变量。

结构变化后，恢复残差定义为：

\[
\mathbf r(\mathbf q)=G(\mathbf q)-G_{\mathrm{parent}}
\]

这样恢复的是父结构对轴向近轴光线的聚焦行为。

**不要把论文中的矩阵元素顺序直接抄进来。** 必须先统一你 Core 的光线坐标、矩阵乘法顺序和参考平面。CMU 的近轴投影也不是要求四个矩阵元素都作为独立约束强行匹配。[arXiv](https://arxiv.org/html/2509.23572v1)

### 2. 最小改变量围绕“子结构”定义

增删后参数维度变了，不能计算：

```text
父结构参数数组 − 子结构参数数组
```

正确做法是把刚编辑完成的子结构记为 \(\mathbf q_0\)，求解：

\[
\min_{\mathbf q}
\left\|
\frac{\mathbf r(\mathbf q)}{\boldsymbol\tau}
\right\|^2
+
\eta\|\mathbf q-\mathbf q_0\|^2
\]

同时满足变量上下界和受保护坐标约束。

这里：

- \(\boldsymbol\tau\) 控制一阶恢复精度。
- 第二项限制过大的结构改动。
- 新插镜片的初始形状可以先冻结，让邻近镜片补偿。
- 局部自由度不足时，再释放全系统进行一次恢复。

矩阵或近轴焦面接口尚未暴露的部分，应补到共享 Core，不能在实验室里再写一套不同定义的近轴引擎。

### 3. 第一轮就使用有界信赖域

不需要先开发新求解器，可以将这个残差接入现有：

```csharp
BoundedTrustRegionLeastSquares.Solve(...)
```

恢复失败时输出明确原因：

```text
RankDeficient
GeometryBlocked
NoParaxialRecovery
BudgetExhausted
```

不能把“没有恢复成功”和“该规格物理无解”混为一谈。

## 七、连续优化如何具体接入现有 Core

新优化器的调用链应当是：

```text
DesignTopology
    ↓
TopologyCompiler
    ↓
当前 SurfaceId → SurfaceIndex 映射
    ↓
OpticalDesignParameter 列表
    ↓
OpticalDesignParameters.Read / Apply
    ↓
共享 Core 光学计算
    ↓
Adam 或信赖域更新
```

**结构改变后，一律重新建立变量表、自动微分映射和优化器状态。** 第一版不继承旧 Adam 动量，不按旧数组位置猜测对应关系。

### 首轮优化阶段建议

以下是便于实现与做对照实验的起始设置，后续需要基准数据调整。

| 阶段 | 允许改变的参数 | 建议的初始窗口 |
|---|---|---:|
| 近轴恢复 | 邻近镜片曲率、允许的间隙；必要时扩大范围 | 最多 30 个接受步骤 |
| 局部补偿 | 新增/相邻镜片及相关间隔 | 80 步 |
| 满目标粗优化 | 全系统允许的连续变量 | 160 步 |
| 候选深化 | 同一结构进一步优化 | 追加 400 步 |

这里的“步数”只是阶段上限，**实际预算还要记录光线追迹、梯度计算和函数探测工作量**，不能把不同采样规模的一步当成相同成本。

原版 `UpstreamE58` 的训练协议不受这些设置影响。

### 评价函数必须固定布局

对一个优化阶段，残差维度和含义保持不变，至少包括：

```text
焦距 / 倍率
实际 F 数或任务规定的孔径指标
各视场像质
畸变
通光
中心和边缘厚度
空气间隙
总长与后工作空间
曲面有效域
```

多波长光斑不能每个波长分别居中后就宣称消色差；需要保留横向色差的影响。

失效光线也不能直接删除对应残差行，让损失“自动变小”。能通过净空诊断恢复的裁光使用连续惩罚；没有有效交点或导数的情况，采用拒步、回退或几何恢复。

现有 `DifferentiableOpticalMetrics` 已提供部分净空和光线方向诊断，但其接口明确针对支持范围内的无限远同轴折射路径。一般有限共轭需要另行适配，不能默认已经支持。

## 八、外层自动搜索，用这套明确规则执行

第一版我建议使用**有界多候选搜索**，而不是先照搬完整 RESTORE。

### 候选池怎么管理

建议按片数保留少量候选，例如每个片数最多四个：

```text
两个表现较好的候选
一个结构差异较大的候选
一个探索候选
```

这是起始调度设置，不是必须固定的常数。

另外永久保留已经独立验收达标的结果。探索分支无论如何变差，都不能覆盖已达标处方。

### 每一轮具体做什么

下面是拟实现的控制流程，**是伪代码，不是仓库已经存在的 API**：

```csharp
while (budget.CanSearch)
{
    var parent = archive.SelectParent();

    var operation = scheduler.SelectUntriedOperation(parent);
    var child = operators.Apply(parent, operation);

    if (!compiler.TryCompile(child, out var compiled))
        continue;

    var restored = restorer.Restore(parent, compiled, budget);
    if (!restored.CanContinue)
        continue;

    var optimized = optimizer.Optimize(
        restored,
        OptimizationPlan.LocalThenFull,
        budget);

    var screened = validator.Screen(
        optimized,
        fixedScreeningProtocol,
        budget);

    archive.Update(screened);
    checkpoint.Save();
}

var finalists = archive.SelectFinalists();
var results = PolishAndValidate(finalists, reservedFinalBudget);
```

实现时不能把每个 `continue` 当成无记录跳过。操作、失败原因和消耗都需要写入日志与检查点。

### 什么时候加片，什么时候删片

采用可以审计的规则：

| 当前情况 | 下一步优先操作 |
|---|---|
| 几何或追迹都不成立 | 恢复几何和一阶指标 |
| 同一目标下仍持续改善 | 继续优化，不急着改片数 |
| 像质停滞且未达标 | 增片、拆片、改变材料或面型 |
| 已达标且有余量 | 删片、并片、降低面型复杂度 |
| 已到片数上限 | 重新分配光焦度、材料和允许面型 |
| 多个起点都变成同类结构 | 补充不同结构起点 |

每个父结构每轮只派发少量子分支，比如最多六个，逐轮覆盖未尝试的位置。不要一次展开“所有位置 × 所有材料 × 所有曲率 × 所有厚度”。

### 为什么第一版不直接复刻完整 MCMC

CMU 的 `jump_restore()` 不只是一个“随机增删 + 接受概率”函数，它还包含候选储备、局部优化序列、再生过程及相关状态。直接摘取几个公式，不能算作原算法复现。

先把相同的结构变换、近轴恢复、真实精修和验收接口跑通，再把外层调度器替换成 RESTORE，才能做有意义的同预算比较。

## 九、怎么判断它确实实现了，而不是只有一个自动运行按钮

我建议按六个提交推进，每个提交都带明确门槛。

| 提交 | 交付内容 | 必须通过的验收 |
|---|---|---|
| **1** | 镜片级模型、稳定 ID、Core 编译器 | 增删不破坏父处方；介质、光阑、像面、非球面项不串位 |
| **2** | 任意固定拓扑优化器 | 同一处方与普通 Core 分析一致；变量导数和约束正确 |
| **3** | 增片、删片、近轴恢复、补偿优化 | 实际出现 \(N\rightarrow N+1\) 和 \(N\rightarrow N-1\)，并完成真实复核 |
| **4** | 自动搜索、预算、取消与恢复 | 无人工介入完成搜索循环；中断不丢失已达标结果 |
| **5** | 渐进删除、材料和面型分支 | 过渡结构不能被发布为合格设计；最终恢复全部约束 |
| **6** | UI 与同预算基准 | 比较达标率、计算成本、最终片数和最差视场性能 |

**第三个提交就必须真正具备增片和删片。** 不应等界面、知识库或强化学习完成以后，才验证核心功能。

### 必须有的四组对照

对相同任务、相同种子、相同实际预算，分别运行：

```text
A：固定片数优化
B：允许增删，但没有近轴恢复
C：允许增删，并加入近轴恢复
D：在 C 上增加渐进删除补救
```

这样才能回答三个实质问题：

**近轴恢复是否减少失败分支？自动增删是否提高达标机会？渐进删除是否值得它消耗的预算？**

不能只展示一个成功案例或一张更好看的光路图。

## 十、你现在可以直接执行的第一步

附件里的结构操作项目不需要额外 NuGet 包。它不包含真实追迹，也不会生成虚构的焦距、RMS 或 MTF。

在安装相应 .NET SDK 的机器上运行：

```powershell
cd TopologyProbe

# 编译并执行结构自检
dotnet run -c Release -- --self-test

# 输出插片、删片、拆片后的结构坐标演示
dotnet run -c Release -- --demo > structural-demo.json
```

随后按实施规范完成这三个接入动作：

**先写 `TopologyCompiler`，让这些结构能够变成你的真实 Core 对象；再写 `FixedTopologyOptimizer`，让任意支持的处方都能优化；最后写 `ParaxialRestorer`，把增删操作与真实优化接起来。**

这里的先后关系很重要：

> **没有任意结构优化入口，增删只是改面表；没有近轴恢复，许多增删分支会在一开始就失去可用光路；没有独立验收，自动运行得到的只是更小的训练损失。**

完成这三个核心模块后，外层自动搜索才是在管理真实、有意义的光学设计分支，而不是不断随机改参数。
