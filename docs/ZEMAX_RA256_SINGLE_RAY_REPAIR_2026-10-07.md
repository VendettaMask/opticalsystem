## 自动光阑 DIAM 的真实截光问题

Tessar 源文件第 5 面是平面 STOP，`DIAM 8.1109587729318147 0 ...` 为自动估值，没有单独的圆形表面孔径。原导入器对每个 STOP 无条件建立相同半径的 `CircularAperture`。RA256 / 移除渐晕因子 / 25° 边缘视场共 51468 条输入，原生接纳 37596 条，旧导入模型只接纳 37550 条：46 条被第 5 面错误拒绝，另 4 条的首次截断从原生第 8 面提前到第 5 面。此前整条曲线仍按原 NRMSE 门槛判 Pass，不能据此宣称每条孔径接纳一致。

修复仅改变 ZMX 导入规则：自动 DIAM 保持显示/几何估值，STOP 标记继续参与系统孔径和瞄准；用户固定的 STOP DIAM 及有光焦度表面 DIAM 才创建圆形截光孔径，固定平面 STOP 继续截光。`APMN` 遮拦及独立 `MEMA` 机械边界保留各自语义。没有修改圆形孔径计算规则，也没有从任意旧快照中猜测、删除显式孔径。

新导入 Tessar 的 46 条接纳差异、4 条首次截断面差异均归零。原生与 Core 均接纳 37596 条，原生像点独立 RMS 为 51.49562497684093 µm，正式 Core 为 51.49562497683142 µm。旧导入模型为 51.38373372355049 µm，约 0.111891 µm 的差异直接对应错误的接纳掩码。交点最大差约 2.14e-13 mm，错误来源是导入语义。

本机官方手册 PDF 第 215、357、1848–1849 页说明自动半口径是估值，用户固定的有光焦度表面可以产生浮动圆形孔径；**自动 STOP 的这批具体接纳行为来自实际原生逐光线捕获**，没有把手册未明确的范围扩写为普遍认证。源为 `D:/Program Files/ANSYS Inc/v261/Zemax OpticStudio/OpticStudio_UserManual_en.pdf`。

## 两条复算路径与不可改写的证据

1. **原快照复算**保留最初的导入模型、分析请求、原生数组和逐量容差。该路径只呈现 Single Ray Trace 报告修复的效果；旧自动 STOP 的硬孔径仍在旧模型中。
2. **重新导入源文件**使用完全相同 SHA-256 的原始 ZMX，以及相同原生数组、请求和容差。它另存新模型快照和 SHA-256，验证当前用户重新打开 ZMX 的行为。不能称为旧快照逐字节未变的计算模型。

这两条路径均通过正式 `WorkbenchRuntime.BuildAnalysisData`，并保留每项原生版本/许可、请求指纹、源哈希、旧快照哈希和实际执行快照哈希。不能把两条路径、23 项独立控制或逐光线诊断相加后宣称比较了更多官方镜头。原计划仍为 6/27 文件，其余 21 份未运行。冻结的 `123456` 主参考和 `validation/history` 未改动。

已经保存为 STAROPT 的旧导入模型会保留其显式孔径；应用这项导入修复需要从原始 ZMX 重新导入。单光线首段报告修复可直接作用于当前模型的分析输出。

## Single Ray Trace 首段约定

原矩阵有 10 项 Single Ray Trace Difference，分别来自五份无限物距镜头的轴上与短波边缘选择。其交点、出射方向、法线与入射角已符合原预算，差异集中在首段几何路径：Workbench 从辅助发射平面起算，原生从第一面顶点所在、垂直于该面局部 Z 的平面起算。

`SingleRayTraceAnalysis` 现在仅在 Object 厚度为正无穷、第一面存在真实几何交点时，以局部交点 Z / 局部入射方向 Z 输出带符号的首段路径。几何求交失败不构造假段；有限物距、Object 厚度零及后续段保持物理段长。此修改限于分析输出，物理发射、累计几何距离、折射率加权 OPL 和追迹缓存不受此报告约定修改。

新增固定参考保留六镜头、两组选择的全部 12 份原生报告，共 120 个有哈希的文件。测试逐面比较全部十一列：坐标/路径 1e-6 mm，方向/法线分量 1e-8，入射角 1e-6°，均沿用原捕获预算。Relay 的两份有限物距报告保持通过。另检查平面、正/负曲率、有限/零物距、几何未命中、全局输出及物理历史不变。官方语义来源为上述本机手册 PDF 第 745 页；路径列是几何长度，不能当成折射率加权光程。

## 大型 JSON 捕获可靠性

首次 Tessar RA256 诊断在原生启动前失败：旧 `JsonFiles.Write` 先把完整 Core 结果变为 UTF-16 字符串，单对象分配溢出。该失败目录和 `failure.json` 保留，不能记成原生失败或完整捕获。

现在直接向独立临时文件流式序列化，完成后才替换目标；失败时保留原目标并清理自身临时文件。保留原 UTF-8 字节格式、序列化配置、非有限数表示和指纹省略规则。测试检查精确字节兼容、约 32 MB 惰性枚举在完成前已写盘，以及失败保护。新目录重试完成 1367552365 字节 Core JSON 和完整原生逐面数组，源文件保持不变。该修复消除了整段字符串分配，不意味着整个追迹流程不需要内存或预算。
