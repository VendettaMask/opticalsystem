# DSEARCH 路径修正 R1：统一真实光线目标与连续求导域

后续运行时已完成 [v10 R2 缩放与正则化修正](INITIAL_STRUCTURE_DSEARCH_R2_2026-09-26.md)。本文保留 v9 的冻结结果和 183 项测试基线。

本轮将[路径复核](INITIAL_STRUCTURE_DSEARCH_ROUTE_AUDIT_2026-09-26.md)的 R1 落到实验室运行时代码，算法身份升级为 **v9**。这是局部优化契约修正，不是完整 SYNOPSYS DSEARCH / PSD 复现，也没有实现官方 QUICK 的三阶、五阶像差筛选。正式 Core、冻结的 60 次原协议和 15 次留出协议的规格与门槛均未改变。

## 已实现

几何恢复完成后，`FlatStartLocalSolver` 使用唯一的 `RealRay` 阶段。它直接优化正式 Core 适配器提供的联合逐光线残差：归一化光焦度误差、逐视场最大点列半径超限、逐光线孔径净空罚项和加权像面 X/Y 坐标。残差内容及权重沿用路径复核的连续域变体；没有根据原验收集重新调权。原来的透过率、目标约束、像质三个阶段不再切换三套目标。旧的诊断残差仍可用于审计，不能用于运行时选择不同的光学目标。

新的导数有效域要求几何有效且 Core 返回完整、连续的真实光线坐标。实际孔径遮挡造成的透过率暂时不足，可以使用 Core 的不裁剪诊断坐标和净空罚项参加试探；TIR、缺失传播结果和无效几何仍然无效。既不补造光线，也不把诊断透过率用于验收。

每次评估和最终候选发布 `FlatStartObjectiveValue`，包含目标函数种类、阶段、粗/密采样、连续结果有效性和平方和。候选评分、稠密候选保留、分支晋级都使用同一个完整目标下的密采样值。不同阶段、粗采样或缺少连续数据的值不能冒充最终评分。阶段内是否有进展，也改为根据该阶段的联合目标判断。

物理合格级别仍优先于目标分数：已满足全部门槛的候选优先，其次是满足几何和指定透过率的候选。同一级别内才比较统一平方和。局部试探允许暂时跨越物理门槛，稠密候选保留逻辑会保存此前更合格的结果，最终重新构造完整视场、完整孔径、全部波长的光学系统独立验收。目标函数下降本身不代表 `LabAccepted`。

## 历史兼容

新增字段在缺省时不序列化，保留旧文件校验和。v1–v4、v6、v7、v8 可读取、导出，并创建独立 v9 续算；禁止以 v9 静默恢复旧算法。v8 仍使用其原二进制形式规划器校验根计划，不能按 v7 规划器解释。

历史评分只服务于历史结果浏览。旧候选第一次进入 v9 续算时，会按当前完整密采样重新评估，并参与本轮候选保留。产生当前候选后，历史原始分数不再混入排序；来源文件、来源候选和严格平面祖先仍保留在 `Origin` 中。当前检查点拒绝候选分数与最终验证的种类、范围、有效性或数值不一致。

## 证据与限制

独立诊断使用先前定义的 62 mm / F6 / 7°、113 mm / F7 / 4° 两套目标及四个符号起点，共八例，不属于原协议或留出集。保留的 v8 程序集重新生成每例的 256 次暖启动快照，并逐个与原审计哈希一致，再交给 v9 的真实 `FlatStartLocalSolver`。每例局部预算 600 次，入口和末次验证另计。

八例全部精确复现先前连续域变体的末次平方和、焦距、合格状态和求解评估次数：累计 **4772 次**求解评估，**0 次**无效评估，其中 **1143 次**为连续但不满足实际透过率的试探。导数不可用退出为 **0/8**；原审计目标约束变体为 **4/8**。这一对照同时改变了原目标函数和有效域；单独隔离有效域的原审计对照是联合逐光线变体 **2/8 → 0/8**。

所有八例仍然 **0/8 通过全部物理门槛**。这是修正机制的可重复证据，不能据此声称搜索成功率改善。实际 v8 的 03-50mm-monochrome / seed 101 检查点通过校验导入，创建并完成了 120 次预算的 v9 续算，产生带当前目标元数据的候选，来源文件 SHA-256 未改变。

完整证据、八个起点、复现程序和后续验证记录见 [R1 evidence](../labs/InitialStructure/benchmarks/dsearch-r1-20260926/README.md)。Core 程序集 SHA-256 仍为 `e08f48f3f12c7534820b9482b1db61f0f8c72596c38094b292d1ac6ee151a5b0`，与冻结 v8 相同。独立诊断不计入工程测试数。

## 后续顺序

工程验证：完整实验室 Release 回归 **183/183** 通过，零失败、零跳过，用时约 5 分 18 秒；比 v8 增加四项目标/域契约用例和一项 v8 历史版本用例，原真实遮挡和阶段测试也扩展了断言。随后仅整理新增测试的空白格式，最终四项目标函数测试再次通过，属于 183 项的子集，不相加。默认 Debug/Release 解决方案构建零警告、零错误，格式与差异检查通过。正式 Core 未改变，正式主测试 **1304/1304** 和工具 **104/104** 沿用已通过基线，本轮不重复计数。桌面交互回归包含在完整实验室测试中；本轮未新增原生 GUI 手工认证。

下一步是 R2：在相同独立起点和通用病态最小二乘测试上验证变量缩放、秩亏下的正则化步长与局部收敛，再决定是否采用更复杂的雅可比历史更新。只有内层改进有证据后，才进入 R3 的完整形式搜索预算和晋级策略比较；之后冻结新的完整原协议与留出集复测。三/五阶筛选、经过验证的模型玻璃及连续光阑属于共享 Core 的后续能力，仍未实现。

本轮没有重跑 60+15 次完整搜索验收。最新已完成完整协议仍是冻结 v8 的 **30/60、6/12**，门槛未通过；其留出集 **15/15**。这些是历史 v8 结果，不能充作当前 v9 的验收结果。
