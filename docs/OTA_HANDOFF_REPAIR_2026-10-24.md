# Windows OTA 交接占用修复

日期：2026-10-24。基于 `376863d0`，针对用户本机更新失败日志和实际辅助进程排查。未改变光学计算。

## 问题与修复

旧版从安装目录的主 EXE 启动 `--apply-update` 辅助进程。主窗口退出后，辅助进程仍加载旧 EXE 并等待安装器退出；安装器的 `ExclusiveFileAvailable(PreviousExe)` 检查因此失败。本机 `setup.log` 记录 `PrepareToInstall failed`，`handoff-error.log` 记录安装器退出码 7；进程核对显示旧安装载荷中的辅助进程仍在运行。这不是下载哈希失败。

辅助进程现在运行在本次独立更新缓存中的运行文件副本。保留同一份产品代码与 OTA 公钥，复制 EXE、DLL、运行配置、原生依赖和卫星资源，逐文件校验 SHA-256，最多 2048 个文件/目录计数、8 层依赖目录、总计 1 GiB。工程、示例和用户设置不参与复制。拒绝重用既有辅助目录、重解析路径、不完整副本及原安装目录内的辅助进程启动。

票据增加原安装目录和活动载荷，辅助进程从原目录核对当前用户注册、版本和载荷身份，并按原 EXE 验证父进程 PID/启动时间。等待父进程正常退出后，再检查旧 EXE 的实际独占访问；短暂句柄清理最多等 5 秒，持续占用时停止。安装器成功返回后，还需确认最终维护互斥标记和安装文件锁均已释放，再从新载荷目录启动软件，避免安装启动器提前返回造成重启竞争。原应用/安装文件锁、互斥标记、更新签名、构建比较、最终安装包哈希及安装时的只读锁均保留。失败恢复指向原安装目录，不会误操作缓存副本。

同版本不同发布 ID 显示“更新”，相同载荷重复安装仍显示“修复”。未签名 EXE 的下载完成提示明确说明 Windows 安装包未签名、可能出现未知发布者；没有抑制系统警告或把 OTA 签名当成 Windows 发布者签名。获得可信发布者身份仍需要有效代码签名证书及既有 Required 签名发布流程。
