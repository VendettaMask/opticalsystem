# Project collaboration instructions

## Persistent UI preferences

- Manual Windows OTA must let users update without saving the current project or tolerance edits. Offer Save and continue, Don't save, and Cancel for dirty documents; no edits means no save prompt. Honor Don't save through the final close without a second save or prompt, preserve the original project file, and retain the current editor and verified download when the user cancels. Update action labels must not imply that saving is mandatory.

- Desktop releases include an Apple Silicon-only macOS DMG (`osx-arm64`) alongside Windows installers. Do not build or publish an Intel Mac package. The Mac app is self-contained and includes both built-in modules and bundled fonts. Preserve untouched platform assets and Windows OTA signatures when updating one platform; do not claim Developer ID signing, notarization, native GUI acceptance or Mac OTA unless actually implemented and verified.

- AI Initial Structure uses only managed AutoLens (`AutoLensManagedV1`, `TargetPolishEvaluations = 0`) for new searches, resumed runs and candidate refinement. Do not expose the former TrustRegion, AutoLens CPU heuristic, or native target-polish options in the desktop UI. Historical old-algorithm and hybrid records remain viewable/exportable with their original identities, but cannot resume or refine through this entry point. Preserve the shared Core and the existing historical engine/validation records.
- AutoLens compute-device selection is separate from optimizer selection. New desktop runs default to Automatic (prefer CUDA GPU), with explicit GPU and CPU choices; loading a target preset preserves the chosen device, while opening a saved record preserves its recorded device mode. GPU acceleration executes shared Core intersection, refraction, stop aiming, physical trace and derivative functions, not a second optical engine. Eligible AutoLens geometry uses CUDA for batch aiming, nominal propagation and dense independent physical validation as well as gradients; CPU remains the comparison authority in tests, with unchanged sampling and hard acceptance gates. Count and disclose extended aiming recovery and unsupported-backend fallback. Keep actual device/fallback evidence, double precision, bounded allocations, cancellation and original CPU behavior; never label a CPU fallback as GPU execution.

- Sequential-mode automatic startup, new documents, file opening and system layout reset must load only the lens data editor and the 2D viewer as document tabs, with the lens editor initially active. Keep the system-options sidebar. Do not automatically restore analysis, 3D or other document tabs from a saved session; explicitly loading a saved default/slot remains supported. Preserve the separate non-sequential workspace behavior.
- The ordinary Light theme's top menu must not show a selected-item underline. Indicate the current category using its existing selected background, retain keyboard focus feedback, and do not remove selection indicators from document or analysis tabs.
- In the ordinary Light theme, document tabs place their 2-DIP blue selected edge on the right, not below the tab. Reserve that edge in every state so selection does not shift the title or close button; keep the rounded native Dock tab template and other themes unchanged.
- Keep the ordinary Light document-wide divider subtle and one DIP thick in both active and inactive states. Reuse the content frame's existing Divider-colored top edge; do not restore Dock's extra blue active stripe or stack a second line. Retain the selected tab's blue right edge.
- In the ordinary Light theme, tool/document Dock containers and document content frames use 12-DIP rounded corners. The system-options header uses the same 12-DIP top corners with a straight lower edge. Clipping must track live bounds through resizing, docking and layout resets, and clear when another theme takes over. Preserve the native document-tab template and its existing radius, the blue right selection edge, the single-DIP divider and all Dock interaction targets.
- In the ordinary Light lens editor, the surface-properties header and lens table fill the Dock content frame's inner area. Do not restore the former 6-DIP left/right/bottom content inset or the pale side rail it exposed; retain the outer 12-DIP rounded clipping and native fine border.
- In every theme, lens-editor surface-type cells place Object/Stop/Image role labels on the left and actual geometry names (including Standard Surface) on the right. Ordinary surfaces show no role placeholder. Retain both live row bindings when cells are recycled; column resizing must keep the two alignments separate.
- Selectable analysis legends (wavelength, field and configuration series) share one vertical rail at the plot page's top right, inset 12 DIP from the top and right before responsive page scaling. Use the same layout for single plots, spot matrices and fan groups; do not restore per-analysis bottom/center placement or matrix-only offsets. Keep long labels wrapped, checkbox filtering and complete-page export working.
- Paired fan plots pack their square canvases toward the pair's center: the left canvas aligns right and the right canvas aligns left within their allocated cells. Keep the actual plot sizes and axis-label margins, field grouping, final-row centering and other square-plot hosts' default centered layout unchanged.
- Seidel coefficient bars and their legend share the fixed semantic palette: spherical #1F77B4, coma #2CA02C, astigmatism #D62728, Petzval #17BECF, distortion #9467BD, axial color #BCBD22 and lateral color #FF7F0E. Keep backgrounds, axes, grids and text theme-driven; the reference screenshot's dark background is not a product requirement.
- The glass material color trial applies only to the Solid Model viewer, including its solid, transparent, wireframe and cutaway modes. Identify materials by their scene material names and share colors with a non-overlapping material legend; omit Air and empty material names. Keep the separate 3D Layout viewer's colors and layout unchanged. Identification colors must not alter physical glass properties, ray colors or shared Core results.
- Solid Model starts and resets with 21 pupil samples per selected field/wavelength group and thin 0.7-DIP rays. Its thin/standard/thick choices are 0.7/1.0/1.5 DIP, without the former 3.6x width multiplier. Keep its controls adjustable and the 2D/3D Layout viewer defaults unchanged; add displayed rays through the shared Core sampling request, never by copying or inventing paths.
- In Solid Model, the lower-left orientation triad labels positive X/Y/Z in red/green/blue and shares the scene camera projection. Both orientation indicators must follow mouse/keyboard rotation, view presets and reset, including foreshortening; pan, zoom and display Y stretch must not rotate them. Keep labels legible at edge-on views and leave the separate 3D Layout orientation graphics unchanged.
- Solid Model view presets use visible localized text alongside cube icons, with the actual matching camera preset highlighted. Use a stronger theme-accent fill for each cube's indicated face so it is clearly distinct from its neutral faces. Free rotation clears the highlight; fit/pan/zoom preserve it and reset restores Isometric. Keep the labelled controls in their own wrapping footer above the material legend, outside the model viewport and orientation indicators. Preserve keyboard focus/activation and the separate 3D Layout icon toolbar.
- The 2D, 3D Layout and Solid Model viewers expose a neutral PNG export camera action beside settings/refresh. Export the actual current viewport with full material legend and visible metadata, excluding settings, navigation and focus chrome. Freeze image/name before opening the picker; retain stale-ray warnings when shown, use bounded atomic writes and preserve files on cancel. Explain disabled empty/updating/outdated states without disabling surrounding controls.
- In the lens data editor (镜头数据), every row with a non-empty displayed material must retain a blue background across the entire row, even when it is not selected or hovered. In the ordinary Light theme, use the shared semantic material-row blue tokens; do not let a template's default white fill hide this data cue. Preserve distinct selection, hover, current-cell focus, disabled and validation states. Use the existing `SurfaceEditorRow.HasOpticalMaterial` / `MaterialDisplay` semantics: Air is displayed as empty and must not be treated as a filled material. Re-evaluate the cue after edits, refreshes, file changes and recycled-row loading. This is a standing user requirement, not a screenshot-specific example.

- Keep the system-options sidebar compact: preferred width 256 DIP, minimum 240 DIP, maximum 280 DIP, including previously saved wider layouts. Use finite-width label/editor rows with unchanged font sizes and control heights; disable horizontal scrolling in the sidebar and its material lists, retaining vertical scrolling. Hide the system-options vertical scrollbar rail (including hover) without disabling mouse-wheel, keyboard or focus scrolling; do not restore a visible or auto-reappearing rail. The lens table and top toolbar may still scroll horizontally when required. Keep the top toolbar's horizontal scrollbar permanently hidden, including hover and scrolling, while retaining horizontal overflow scrolling and focus access to commands in every theme and both workspace modes.
- Declare primary execution actions with the existing theme `accent` role. Cancellation, reset, export and other secondary actions remain neutral. Explain existing disabled conditions through visible tooltips and accessibility help, clearing obsolete reasons when enabled; never dim ordinary surrounding labels or explanations by disabling an entire container.

Truthful material provenance, frozen historical evidence and test-only negative branding fixtures retain their original identities. Do not delete actual user data.

- Product integration decision (2026-10-13): initial-structure and coating design are mandatory built-in modules of Optical System Design, not independent software, optional components, separately installed executables or external processes. - Documentation must distinguish implemented behavior from planned or compatibility-only behavior.
- Keep current verification summaries in `docs/CURRENT_STATUS.md` with links to scoped evidence. Do not copy historical test-count/status paragraphs into unrelated guides. Dated reports preserve their original scope; obsolete current instructions must be corrected in the body.

## Accuracy reference priority

- User scope decision (2026-10-11): exclude independent Cooke and Tessar residual investigations and native certification from follow-up work. Preserve existing captures and regression tests, but do not add these independent cases back to the work plan or acceptance gates unless the user changes the scope.
- The initial-structure module must use the product's shared Core for all optical ray tracing and analyses, including paraxial quantities, material dispersion, spot metrics, wavefront, MTF, and layout ray data. Its internal boundaries separate features, search orchestration and editing state, never a second application/process or optical engine. Module code may assemble search residuals and compare returned results with targets, but must not implement or copy optical tracing/analysis formulas or use approximation fallbacks. Missing reusable capabilities must be added to the shared computation layer and verified there before module use. Independent analytical/reference checks belong only in tests and must never supply runtime candidate evaluation, acceptance, or display results. P1/P2 now use the shared sampled-spot and optical-power interfaces; preserve same-snapshot, same-settings consistency checks and never restore module-local optical metric summaries.
- The default precision authority is the committed Zemax OpticStudio 2026 R1 baseline for `123456.ZMX` under `artifacts/zemax/123456-zemax-2026-r1-baseline`.
- That baseline validates only the captured file, analysis settings, and OpticStudio version. Never present those captured settings as universal Zemax defaults or specifications.
- Dispatch analysis result controls by `AnalysisPresentationKind`; localized names, visible titles, and imported labels are presentation text and must not select a control implementation.
- Treat `AnalysisAxisQuantity` and `AnalysisAxisUnit` as the authority for plot scaling, value formatting, and data export. Axis-label strings are presentation text and must never be parsed to determine a quantity or unit; every non-empty analysis axis must publish typed metadata.
- Treat scene ray segments as directed propagation data. Preserve the traced `RayInteractionKind`, publish typed segment and surface-interaction metadata through scene DTOs, and orient viewer arrows from the explicit direction vector; never infer reflection, transmission, diffraction, or TIR from point order, Z-axis order, labels, or colors.
- Share ray-trace results only through a bounded cache keyed by optic revision, numeric backend, exact input-ray state, retained surface indices, and result-affecting request options. Equivalent retention modes may share when they resolve to the same surfaces; analysis names and localized labels must never participate in cache identity. Any trace-relevant mutation of an analysis snapshot must detach that snapshot from the shared cache before further tracing.
- Treat analysis viewport, pan/zoom, hover, and surface-camera state as document-revision state. Reset interactive analysis controls when their displayed source revision becomes stale, and clear the old result content immediately on a file switch even when the analysis page is locked.
- Treat only a positive-infinite Object-surface thickness as an infinite object conjugate. A zero Object thickness is a finite object coincident with the first physical surface; never infer conjugate type from coordinates, labels, field type, or a small-distance tolerance.
- In RMS-vs-field Spot mode, sample `Field Density + 1` positions from zero through the maximum defined field magnitude along the selected orientation; do not substitute the discrete Field Editor rows. For wavefront RMS, chief-ray reference removes piston only, while centroid reference removes the weighted best-fit piston and both pupil tilts.
- Core analysis constructors and `AnalysisCatalog` must keep general-purpose defaults. Application presets may choose product defaults, while baseline tests must pass captured settings explicitly and name them as captured-file settings.
- Product computation must stay pure C#/.NET: no Python, Python.NET, Optiland package, external Python process or service, or Python Optiland document interchange. Keep general numeric backends independent of external validation tools.
- Optiland 0.5.8 data under `validation/history` is frozen auxiliary historical regression evidence only. Never add or regenerate Optiland comparisons, and never reference history assets from product projects. Use committed Zemax OpticStudio 2026 R1 captures as the primary external numerical validation reference.
- Reports must distinguish Zemax baseline integrity, current Workbench recalculation, numerical comparison, and screenshot-only review.
