# Complete installed Sequential sample comparison

Offline validation tool derived from the existing [standard matrix runner](../StandardMatrix20261015/README.md). It uses the formal Application/Core and comparison adapters, with no product optical formulas or alternate engine. The 2026-10-19 user request selects the entire installed `Documents/Zemax/Samples/Sequential` directory, including Cooke/Tessar within this common comparison; it does not request a new independent residual investigation.

Preparation inventories and hashes every original file. Each ZMX is one logical lens; its paired ZOS is preserved and receives an additional native model probe. Only workspace copies are loaded, and the original sources are never saved. Source ZDA caches are inventoried but not supplied as numerical reference data. All imported configurations receive the existing 18 primary analysis requests, four edge-field controls per positive-weight wavelength and the existing GQ6 explicit-ray controls. Unsupported units, afocal adapters, surfaces, missing assets, failed imports and failed captures remain visible in the inventory and results; they are never counted as numerical passes.

The later Riflescope investigation replaces the blanket afocal gate with the shared per-analysis `AfocalAnalysisContracts`. Ray Fan, FFT MTF and Field Curvature/Distortion now retain explicit angular/power contracts; unverified afocal analyses remain individually excluded. Angular Ray Fan needs separately declared degree tolerances, and canonical afocal MTF frequency is cycles/mrad. This changes future preparations only; the earlier 95-lens and 14-lens reports remain historical and are not retroactively recounted. See the [current afocal tool contract](../../OpticalSystemDesign.ZemaxComparison/README.md#afocal-comparisons).

```powershell
dotnet build tools/diagnostics/SequentialCorpus20261019 -c Release -m:2 -p:UseSharedCompilation=false
$tool = 'tools/diagnostics/SequentialCorpus20261019/bin/Release/net10.0/SequentialCorpus20261019.dll'
$run = 'artifacts/zemax-sequential-corpus/20261019/full-v1'
dotnet $tool prepare . $run
tools/diagnostics/StandardMatrix20261015/Run-Native.ps1 -RunDirectory $run
dotnet $tool workbench . $run
dotnet $tool compare . $run
dotnet run --project tools/diagnostics/SequentialCorpus20261019/Reporting -c Release -- $run artifacts/zemax-sequential-corpus/20261019/report-v1
```

Use a fresh directory. This task freezes the current original comparison policy; it does not change tolerances or claim full field/wavelength/sampling convergence. Native API execution remains serial. Keep per-job logs and completion records, preserve failed attempts, and use explicit unfinished-job lists when resuming; never overwrite a completed native capture. Workbench jobs use the existing two isolated processes and 900-second deadline. The native batch runner requires active monitoring and task-scoped interruption if a request stalls. No proprietary API binaries are distributed. Python is not used by this new workflow.

The separate reporting project references only the .NET base libraries. It rejects unfinished native/Workbench jobs, verifies every original source and copied input hash, retains all 95 logical lens rows including failed imports, and applies the prior pointwise ray-audit limits (coordinate `1e-6 + 1e-6*abs(reference)` mm; direction `1e-8 + 1e-6*abs(reference)`). Acceptance and first clipping surface are compared separately. Folded coordinate-break indices remain incomparable, unsupported preflight findings cannot become ray-certification passes, and reflective raw-direction conventions remain explicit. ZMX/ZOS equality refers only to the captured first-configuration model readback, not all configurations or numerical outputs. The output includes a readable per-lens table, per-analysis CSV, raw ray comparisons, integrity checks and machine summary. `Pack-Evidence.ps1` packages completed raw captures and report/source evidence into a new ZIP and verifies every payload after reading it back; binary APIs and build directories are excluded.

If the native application disconnects after a resource failure, first let the original host exit, then run `Resume-Native.ps1 -RunDirectory $run -ChunkSize 50`. It archives only completed remoting failures under a checked run-local path, restores identical request bytes, and starts a fresh native application for each small chunk. It does not retry genuine numerical/capability failures or alter valid captures. `Resume-Workbench.ps1` similarly retries only recognized CLR/pagefile/memory infrastructure failures after the original Workbench stage has finished. All discarded attempts and final completion records remain in the archive; report attempt counts include them.

Paired file formats are checked independently. `Export-Formats.ps1` loads each copied ZMX/ZOS and writes new native ZMX exports inside a fresh workspace directory; it checks source hashes and never saves the input. Compare all ordered native-export records except display-only NAME/NOTE/COMM, and retain captured model differences separately. The 2026-10-19 run conservatively selected the union of 12 ordered-record differences and 8 model-readback differences: 13 format controls. Preparation accepts an optional source directory and `zos-reference` argument; the native analysis then reads the original ZOS copy while Core reads its independently exported ZMX. This does not implement direct product ZOS import. `Run-NativeChunks.ps1` executes fresh requests using the recorded host binary, restarting the native application every 50 requests.

The `classify-preparation-errors` mode repairs only an old orchestration bookkeeping case: a request row created immediately before preparation throws must be Error with its recorded exception, rather than default Skipped with no reason. Original item/result/summary JSON is retained before this classification; captured arrays, requests and tolerance policy are untouched.

The completed results are maintained [by lens](../../../validation/zemax/2026-r1/sequential-corpus-2026-10-19/BY_LENS.md). `Write-LensResults.ps1 -ReportDirectory validation/zemax/2026-r1/sequential-corpus-2026-10-19` renders the 95-row Chinese overview, per-lens configuration/analysis differences and the 13 overlapping ZOS controls from completed reports. It verifies input/output row counts, preserves Close and coverage gaps, and does not recompute optics or change conclusions. Parse multiline CSV records with `Import-Csv`; piping individual physical lines through `ConvertFrom-Csv` does not preserve multiline notes.

The subsequent 14-lens import repair uses a separate selected-source directory and fresh `matrix-v2`; the first candidate and original 95-lens report remain historical evidence. `NativeTools/CoordinateBreakControl.cs` reads original Yolo REAX/REAY operands at native surfaces 9/13 for five pupil points in a new licensed application, without saving inputs. The standalone `ReferenceControls` project evaluates the same rows through the imported Core operands and applies the original coordinate limits. It reports the remaining optical differences explicitly; import/snapshot success does not certify Yolo tracing or unsupported surface geometries.

Native operand controls additionally require a successful, unvignetted independent batch ray and agreement between the native operand and local batch coordinate. A failed native zero return cannot become a numerical reference. `Recompute-Workbench.ps1` explicitly archives completed software attempts inside the checked run root, restores identical request bytes and records the final computation assembly identity before replay; it does not overwrite native captures, snapshots or the preparation identity.
